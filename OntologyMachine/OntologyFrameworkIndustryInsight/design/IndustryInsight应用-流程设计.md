> 「五看三定」环节索引：**五看**（看行业/趋势 → 看市场/客户 → 看竞争 → 看自己 → 看机会）；**三定**（**定战略控制点** → 定目标 → 定策略 —— 注：本项目三定**已含"定战略控制点"**）；配套工具：**SPAN 图**（战略定位分析）、**SMART** 原则。

## 1. 概述与范围

本应用含**一条主流程**：行业洞察（五看三定）流程（**全自动**，无人工任务节点；用户仅在前端输入「洞察场景」并等待结果）。

| 流程 | process id | 名称 | 定位 | 角色任务 |
|---|---|---|---|---|
| 主流程 | `IndustryInsightProcess` | 行业洞察（五看三定）流程 | 全自动：给定任意行业的洞察场景文本，按五看三定逐环节执行，产出洞察 SKILL | 无 userTask（全 serviceTask；前端只负责输入与轮询展示） |

> 流程覆盖前置「洞察场景解析与校验」+「五看」五个洞察环节 + 中间「五看结论交叉验证与机会共识」「洞察结论与关键判断」+「三定」三个决策环节，其间对机会点做 **SPAN 定位与优先级判定**并按优先级条件外发关键洞察，末尾「生成洞察 SKILL」。

> **流程结构修订史**：
> - **v1.1（2026-10-22 业务反馈①）**：新增节点「五看结论交叉验证与机会共识」（五看后、三定前）；「定节奏/定路径」并入「定策略」。
> - **v1.2（2026-10-22 业务反馈②）**：新增前置节点「**洞察结论与关键判断**」（节点 1′ 后、五看前）；将原「五看结论交叉验证与机会共识」扩展为「**五看结论交叉验证与机会共识**」；节点 3/4 增补（**决策链分析**、**客户分层/痛点验证**、**生态位/博弈**、**颠覆性变量**）；全局增补（**数据源分级/置信度**、**质量检查清单〔含资源匹配度〕**、**量化优先**）；报告增补（**分层交付/So What/有效期与刷新信号/可视化**）。**最终节点数 15**，逐节点闸门为 **①-1…①-15**。
> - **v1.3（2026-10-31 业务反馈③，本版）**：按「**先五看、后依五看三定**」重构主链——**移除五看前的「洞察结论与关键判断」前置节点**（纠正原「先假设→五看验证→三定」的顺序）；「交叉验证」环节重构为「**五看结论交叉验证与机会共识**」（去掉「关键假设/验证计划」框架）；其后新增「**洞察结论与关键判断**」作为**三定的直接依据**。节点重排为：**2–6 五看（看行业/趋势→看市场/客户→看竞争→看自己→看机会）→ 7 机会点 SPAN → 8 条件外发 → 9 五看结论交叉验证与机会共识 → 10 洞察结论与关键判断 → 11–13 三定 → 14 生成 SKILL**。

## 3. 环节明细（业务语言，不写技术实现）

> **横切增强（2026-10-22 业务反馈，适用全部「五看」分析节点与决策节点）**：
> ① **数据源分级与置信度**：每条结论须标注**数据来源等级**——**一手访谈 > 权威第三方报告 > 公开新闻 > 内部经验**——并标注**置信度**（高/中/低）；无法溯源者标 **【待考】**（★8/9/10）。
> ② **质量检查清单**：每个「五看」节点经 MaaS 分析后，须对照**标准分析模板 + 质量检查清单**自检（如「看竞争」需含竞品对标打分表、竞争态势演化图），未达清单项须显式列出；清单含**可落地性**维度（**资源匹配度**：资源约束 + 初步资源需求估算）。
> ③ **量化优先**：在定性分析基础上**尽可能叠加定量**（市场规模测算 / 客户细分聚类 / 竞品财务建模等）；**数值必须有出处**，否则标 **【待考】**、不臆造（★10/12）。

| # | 环节 | 输入 | 处理（业务规则） | 输出 | 待业务裁定 |
|---|---|---|---|---|---|
| 1 | **洞察场景解析与校验**（**MaaS 大模型解析 + 应用兜底**） | 用户输入：一段**行业洞察场景**文本（必填）+ 可选补充（行业 / 地域 / 时间窗） | ① **解析（首选：MaaS 调用大模型）**：通过 MaaS 服务调用大模型（LLM）解析用户输入——复用平台 `Utilities` 的 `ChatAgent`（Spring AI `ChatClient` 薄封装，配置走 `spring.ai.openai.*`，铁律21「API 复用优先」，**不另写客户端**），抽取结构化维度：**主体行业/领域、地域范围、时间窗、洞察目标/关注点**；② **兜底（LLM 未配置 / 不可用 / 调用失败 / 超时）**：应用兜底——改用确定性启发式（关键词/规则）抽取可得维度，无法判定处置空、交由后续追问补全，流程不阻断；**兜底路径与系统提示词均不得内置任何具体行业/领域词表或行业示例**；③ **校验可执行性**：场景须包含「针对什么行业/领域、想洞察什么」两个要素——两要素齐备→通过；任一缺失→不通过并给出缺失项（依据：五看三定要求先明确战略意图与业务边界，来源＝方法论原文） | `行业/领域`、`地域范围`、`时间窗`、`洞察目标`、`解析来源(LLM/兜底)`、`场景校验结果(通过/不通过)`、`缺失要素(若不通过)` | Q3：行业/地域/时间窗缺省口径；Q4：场景字段口径；Q13：MaaS LLM 解析 + 兜底口径 |

| 2 | **看行业/趋势**（**五工具 + MaaS 大模型分析 + 求同存异 + MaaS 总结**） | 洞察场景（行业/地域/时间窗）、洞察结论与关键判断（节点 10）、业务方随场景提供的行业资料 | 依方法论「**看行业/趋势**」，**通过 MaaS 服务调用大模型（复用 `Utilities` 的 `ChatAgent`）**借助**五个分析工具**分析该行业，再对结果**求同存异**、**再次经 MaaS 总结分析**：<br>① **PESTEL 分析**：扫描**政策 / 经济 / 社会 / 技术 / 环境 / 法律**六类宏观力量，**筛选出 3–5 条对公司有实质影响的变量**；<br>② **波特五力模型**：分析**现有竞争者、潜在进入者、替代品、供应商与购买者的议价能力**；<br>③ **价值链利润池分析**：识别行业中**高利润环节及其转移方向**，输出「**行业利润池分布图**」；<br>④ **技术成熟度曲线（炒作曲线）**：判断关键技术在**萌芽 / 泡沫 / 爬升 / 成熟**中所处阶段；<br>⑤ **颠覆性变量 / 变化率分析（动态性）**：识别**颠覆性变量**（如 AI、新法规、供应链重构等**非线性**冲击）及其**变化率**，关注**非线性影响**，避免仅做**线性外推**。<br>**求同存异**：汇总五工具结论，标注**共识点**与**分歧点**并各自保留；<br>**总结分析**：**再次经 MaaS 调用大模型**，对五工具结果与共识/分歧做总结，产出行业趋势要点，并**归集结论证据**（各洞察结论的支持/反对证据）。<br>**兜底**：LLM 未配置 / 不可用 / 超时→应用兜底（确定性启发式、或仅保留工具框架而结论置 **【待考】**），不阻断；**不内置任何行业词表/示例**。**凡引用具体行业事实/数值须来自业务方带出处资料**；无出处标 **【待考】**、只作定性描述，不臆造数字（★3/8/10） | `行业趋势要点`（五工具结论 + 共识点/分歧点 + 总结分析 + 趋势条目：表述 + 驱动因素 + **变化率/颠覆性变量** + 不确定性 + 出处/【待考】）+ **质量检查清单自检结果** | Q4：行业资料提供方式；Q14：节点 2 五工具经 MaaS 分析口径 |

## 4. 分支条件

| 网关 | 分支 | 条件（互斥且完备） | 依据 |
|---|---|---|---|
| **G1** 场景校验结果 | 通过 | 洞察场景**同时**含「行业/领域」与「洞察目标」两要素 | 五看三定须先明确战略意图与业务边界（方法论） |
| | 不通过 | 洞察场景**缺**「行业/领域」**或**「洞察目标」任一要素 | 同上；缺失要素无法支撑后续五看三定 |
| **G2** 机会点优先级 | 高优先级 | 机会点清单中存在**≥1 个高优先级机会点**，**或**识别到**关键风险** | 高优先级机会/关键风险需即时提示业务方（§7 Q8） |
| | 中/低 | 机会点清单中**不含高优先级机会点**，且**无关键风险** | 非紧急，随报告汇总呈现即可 |

> 两个网关的分支均**互斥且完备**：G1「通过/不通过」二值完备；G2「高 / 中低」覆盖优先级全集（优先级三档归并为「高」与「中低」两路）。

## 5. 前端交互设计（若含 UI）

### 5.1 交互流程

```
用户在页面输入「行业洞察场景」文本（可选：行业 / 地域 / 时间窗）
  │
  ▼
POST /api/industryinsight/insight {scenario, industry?, region?, timeWindow?}
  │ 返回 {instanceKey, processId, scenario}
  ▼
每秒轮询 GET /api/industryinsight/insight/{instanceKey}
  │ 返回 {status, variables, insightSummary, deliverables, insightSkillPath, ...}
  ├── status = RUNNING    → 显示"洞察流程运行中"（显示已完成环节进度）
  ├── status = COMPLETED  → 显示「洞察 SKILL」内容 + 分层交付物 + SKILL 路径（可下载）
  ├── status = INCIDENT / TERMINATED → 显示错误 / 场景澄清提示
  └── （校验不通过时）显示「场景澄清提示」，提示用户补全后重试
```

### 5.2 输入选项

| 选项 | 标识 | 特点 |
|---|---|---|
| 行业洞察场景（必填） | `scenario` | 一段自由文本，描述「针对什么行业/领域、想洞察什么」（任意行业） |
| 行业/领域（可选） | `industry` | 显式指定行业，缺省时从场景文本推断（见 §7 Q3） |
| 地域范围（可选） | `region` | 限定洞察的地域范围 |
| 时间窗（可选） | `timeWindow` | 限定洞察的时间范围 |

### 5.3 结果展示

流程完成后，前端显示：
- **洞察 SKILL 内容**（insightSummary）：角色设定 + 任务指令 + 内嵌五看三定各环节结论与来源，可直接输入大模型产出洞察报告
- **分层交付物**（deliverables）：行业洞察 SKILL 文件路径 + 「输入大模型即得洞察报告」说明
- **SKILL 路径**（insightSkillPath）：洞察 SKILL 落盘位置（`skill/industryinsight-<key>.md`；可经 `/api/industryinsight/insight/{key}/skill` 下载）（呈现形态见 §7 Q2/Q10）
- **本体验证**（ontologyValidationStatus）：TBox 一致性与类数
