## 1. 概述与定位

`OntologyFrameworkPlumBlossom`（应用简称 **PlumBlossom**）是本工程中的一个**本体应用模块**，用于将邵雍（邵康节）所创**梅花易数**的占断过程建模为可执行的本体应用。

**业务定位**：用户输入一个具体事项及当下可用信息（时间、数字、声音、文字、方位、外应等），应用通过梅花易数「**取象 → 成卦 → 析卦**」三阶段推断该事项的**吉凶趋势、过程波折、应验时间**——即回答三个问题：

1. **这件事成不成？**（体用生克 → 吉凶判据）
2. **中间有无波折？**（互卦 → 内在过程）
3. **大约何时应验？**（卦气旺衰 + 动爻 → 应期推断）

> 出处：《梅花易数全面指南》§一「核心目标」——"通过对当下时空信息的「取象—成卦—析卦」，推断具体事项的吉凶、过程与应期"。

它与 `OntologyFrameworkExample`（Example）是同工程内**并列、独立**的应用模块，共享底层的 `OpenlletResolver`、`OntopOBDAHandler` 与 `Utilities` 三个能力模块。

**核心特征：**

- **本体即约束**：八卦类象、五行生克、体用关系、六十四卦等业务约束由 OWL TBox 表达，Openllet 推理器在运行时判定，非硬编码。
- **BPMN 管编排**：「取象 → 成卦 → 析卦」流程拓扑定义在 BPMN 中，部署到 Camunda 8 / Zeebe 由引擎驱动。
- **Ontop 虚拟取数**：历法数据（农历年月日时干支等）留在 MySQL，经 Ontop OBDA 映射以 SPARQL 视角读写。
- **前端可交互**：Web 页面提供事项输入与起卦信息填写，启动流程并轮询显示占断结果。
- **消息外发**：重大吉凶判定结果（大吉/大凶）经 SWRL 推理自动触发 RabbitMQ 消息外发。

## 2. 范围与边界

### 2.1 在范围

| # | 范围项 | 说明 | 出处 |
|---|---|---|---|
| 1 | **多种输入类型** | 时间（年月日时）、数字（物数/声音数）、文字（笔画/字画/拆字）、物形、物色、方位、外应等——归入原著卷之一「起卦诸法」 | 原著卷之一·起卦诸法 |
| 2 | **起卦法体系（16类）** | **先天（以数起卦）**：年月日时起例／物占数／声音占／字占／丈尺占／尺寸物占；**后天·端法（以象起卦）**：为人占／自己占／占动物／占静物／物卦起例（端法后天）／风觉占／鸟占／听声音占／形物占／验色占 | 原著卷之一·起卦法诸篇 |
| 3 | **心法戒律检查** | 四不占：不诚不占、无事不占、不义不占、重卦不占——起卦前置校验 | 指南§二·2 起卦戒律 |
| 4 | **成卦** | 上卦/下卦/动爻计算；一卦一爻动（梅花易数根本特征）；产出本卦 | 指南§五·第1步 |
| 5 | **体用判定** | 动爻所在卦为用卦，无动爻之卦为体卦 | 指南§五·第2步 |
| 6 | **互卦推演** | 取本卦 2/3/4 爻为互卦下卦、3/4/5 爻为互卦上卦；反映中间过程 | 指南§五·第3步 |
| 7 | **变卦推演** | 动爻阴阳反转得变卦；反映最终结果 | 指南§五·第4步 |
| 8 | **五行生克分析** | 体用五行生克（用生体/体用比和/体克用/体生用/用克体）→ 吉凶判据 | 指南§五·第5步·1 |
| 9 | **卦气旺衰分析** | 春木旺土衰/夏火旺金衰/秋金旺木衰/冬水旺火衰/四季末月土旺水衰 | 指南§五·第5步·2 |
| 10 | **万物类象取象** | 按所问事项取八卦类象（紧扣所问、呼应生克、优先动象）；活变心法 | 指南§五·第5步·4 |
| 11 | **外应参考** | 三要灵验（耳/目/心）与十应互参——可选辅助判据 | 指南§五·第6步·3 |
| 12 | **分类占断** | 婚姻/求财/求谋功名/出行/行人/疾病/失物/官讼/家宅/胎产等分项断法 | 指南§六 分类占断要点 |
| 13 | **断吉凶（以理统数）** | 观象→言数→裁理；理卦互校；不合理义者纵卦吉亦不可许 | 指南§五·第6步·1、§七 |
| 14 | **应期推断** | 以卦气数/五行生数（水1火2木3金4土5）/动爻数推算应验时间 | 指南§五·第6步·2 |
| 15 | **修身建议** | 断语附修身处世之劝——吉则戒骄守正，凶则积德改行 | 指南§五·第6步·1 |
| 16 | **前端展示** | 输入页面 + 占断结果展示（本卦/互卦/变卦、体用关系、吉凶、应期、修身建议） | — |

### 2.2 不在范围

| # | 不做项 | 理由 | 出处 |
|---|---|---|---|
| 1 | **六爻纳甲法** | 梅花易数以先天八卦起卦，不走六爻纳甲（重爻排卦、世应安配）路线 | 指南§二 对比 |
| 2 | **奇门遁甲** | 另一术数体系，起局方法与梅花易数完全不同 | — |
| 3 | **六壬课** | 另一术数体系，四课三传体系与梅花易数无关 | — |
| 4 | **风水堪舆** | 空间环境术数，与事件占断无关 | — |
| 5 | **命理八字** | 四柱推命体系，非事件占断 | — |
| 6 | **多动爻扩展** | 梅花易数每次只有一个动爻，此为与六爻法的根本区别 | 指南§五·第1步 |
| 7 | **分秒级应期** | 应期推断到年/月/日/时辰级别，不精确到分秒 | — |
| 8 | **占断历史记录管理** | 本期只做单次占断，不建占断历史库（后续可扩展） | — |
| 9 | **错卦/综卦独立推演** | 错卦（全爻反转）、综卦（上下颠倒）仅作辅参，不做独立推演环节 | 指南§四·5「以本互变为主干，错综为辅参」 |
| 10 | **「心易」境界建模** | 心法/静心/去执等属修行境界，非可算法化的业务规则，仅在 UI 提示 | 指南§二·1 心法备注 |

## 4. 高层架构

```
┌──────────────────────────────────────────────────────────────┐
│ 前端层（Web 页面）                                              │
│   static/index.html（事项输入 + 起卦信息填写 → 启动 → 轮询结果） │
└───────────────▼──────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│ API 层（REST Controller）                                       │
│   PlumBlossomController（POST /divination 启动、GET 查询）      │
└───────────────▼──────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│ 编排层（BPMN，部署到 Zeebe）                                    │
│   plumBlossomProcess.bpmn (PlumBlossomDivinationProcess)       │
│   「取象 → 成卦 → 析卦」三阶段由 Camunda 8 / Zeebe 引擎驱动     │
└───────────────▲──────────────────────────────────────────────┘
                │ jobType 字面量绑定（BPMN type ⇄ @JobWorker(type))
┌───────────────┴──────────────────────────────────────────────┐
│ 应用层（Spring Boot 应用 = JobWorker）                          │
│   PlumBlossomOntologyJobWorker（多个 @JobWorker）               │
│   逻辑走 BackendService / ReasonerService / RabbitMqHandler     │
└───────────────▼──────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│ 推理层（Openllet）                                              │
│   加载 plumblossom-all.owl → TBox 约束判定 + SWRL 规则推理       │
└───────────────▼──────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│ 数据层（MySQL + Ontop OBDA）                                    │
│   历法数据（农历干支等）经 OBDA 映射以 SPARQL 视角读写           │
└──────────────────────────────────────────────────────────────┘
```

> 详细组件清单、JobWorker 清单、端到端数据流、配置项见《PlumBlossom应用-应用架构设计》（第 7 步产出）。
