## 2. 改动纪律

1. **有依据、不瞎编**——任何修改都必须有依据（代码、本体、输入表、用户指示），不得凭空发明。
2. **先确认后动手**——非笔误类改动**先与用户确认**，改动后**必跑回归**；书写错误（笔误）可直接替换。
3. **回归必过**——任何修改后都必须重跑相关回归测试，保证全部通过后再交付。
4. **跑全反应堆前须同意**——执行全反应堆 `./mvnw test` 前**必须先征得用户同意**（用户环境通常处于**停止**态）。
5. **环境可按需重启**——需要重启环境时可直接执行、**无需用户确认**；重启入口为 `EnvPrepare` 模块（Java）。

**Why:** 用户要保护本体与既有参照资产不被 AI 改动，同时要求每步改动有据可查、可验证，避免「编造」式修改。

**How to apply:** 涉及任何代码/文档/本体改动前，先确认落点在允许范围内并说明依据；改动后立即跑对应模块回归；全反应堆命令先问、单模块回归可直接跑；需重启环境时直接执行。

## 3. 业务真值外置（零硬编码）

> 这是本仓**最核心的长期铁律**，TMSD 与 Pizza 两应用均适用。

**铁律：程序（引擎）中不得硬编码任何业务相关数据。**

- 不得硬编码的内容：具体数值（如 `280mm`、`4×280mm` 等尺寸 / 间距 / 倍数）、**限制、约束、关系、映射**等。
- 业务真值来源：**必须来自「输入」（主体信息表 / 布局表 / 表单变量）或「本体」（`.owl`）**。
- 设计目标：**后续调整业务时无需改动程序代码，只需修改本体（或输入）即可**——即「本体驱动、可配置可维护」。
- 输入缺失时**不得用业务值兜底**；约束值应取自单一镜像（本体内），禁止在引擎中再次复制一份。

**Why:** 把业务真值集中在输入表与本体中，避免散落硬编码，降低后续维护成本。

**How to apply:** 审查或实现引擎时，逐处排查业务数值、约束（如间距上下限、整数倍、避焊缝阈值）、关系是否写死在代码里；发现硬编码须报告并改为从输入表或本体读取。

## 4. 输入与路径纪律

1. **输入文件参数化传入**——主体信息表等输入 `xlsx` 必须作为参数传入，**严禁硬编码**文件路径 / 文件名。
2. **资源路径优先相对路径**——本体 / OBDA / BPMN 等资源路径优先使用**相对路径**，基准＝**模块目录**（如 `OntologyFrameworkPizza`），避免绝对路径换环境出错。
3. **语义化命名**——文件与包名按用途语义命名（示例：`数据库命令.sql`→`createdb_tables.ddl`；包名 `...ontologyframeworkexample`→`...ontologyframework.pizza`）。

**How to apply:** 新增/修改资源引用时用模块根相对路径；输入型数据一律走参数而非常量；重命名须同步核对全仓残留引用。

## 5. TMSD 专项铁律（塔架中段设计）

> 下列条目为 TMSD 业务专属，仅适用于 `OntologyFramework` 的塔架中段设计链路。

1. **中段筒节尺寸必须按主体信息表真实逐节数据计算**——**不是每节都是 28000**，一定要按塔架主体信息表中的数据计算；中段范围按 `TowerGeo` / `Flange` 排序约定界定（外形在 `TowerGeo`、法兰在 `Flange`；第 1＝下段底、第 2＝下段顶、末＝顶段顶、倒数第 2＝顶段底、其余＝中段），中段尺寸取「下段顶法兰」与「顶段底法兰」之间的**全部筒节真实尺寸**，**严禁用默认值 / 均一值替代**。
2. **焊缝位置须直读输入表**——从主体信息表 `TowerGeo` 的 **B 列（标高(下)(m)）** 逐节**直接读取**，**不得由程序推导 / 步进生成**。
3. **生成的 txt 注释格式「以 `/*` 开头、单行、不闭合」**（2026-09-30 增补）——TMSD 生成的 Creo 关系式 txt 中，**注释只能单行、不跨行**；**每行必须以 `/*` 开头**；**不允许出现 `*/` 闭合**；**注释前没有 `/*` 即判错**。并须**从生成端根治**——由输出写出类 `TmsdOutputWriter` 在写出时逐行校验，发现不合规注释即拒绝生成（抛异常），而非事后手工修改已生成的 txt 产物。
   > ⚠ 该铁律**只针对生成的产物 txt 内容**，**不适用于 Java 源码**：Java 源码注释必须正常闭合（`//` 或成对的 `/* … */`），`/*` 未闭合会把后续代码注释掉、导致编译失败，切勿把产物注释风格照搬到 Java 源码。

**Why:** 中段尺寸与焊缝位置是设计的物理真值，只能来自真实输入数据，任何近似或生成都会导致设计结果失真；注释格式则须在生成源头统一，避免坏格式产物反复出现。

**How to apply:** 改动塔架几何 / 排布逻辑时，先核对该逻辑是否直读输入表；发现用默认值、均一值或步进生成即视为违反铁律，须报告并整改。新增 / 修改 TMSD 输出逻辑时，保持产物注释「行首 `/*`、单行、无 `*/`」，并确保 `assertCommentPolicy` 类生成端校验生效；核到不合规注释回到生成端修，勿直接编辑产物 txt。
