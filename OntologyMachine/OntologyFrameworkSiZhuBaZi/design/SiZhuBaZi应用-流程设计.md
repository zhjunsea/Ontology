## 1. 概述与范围

本应用含**一条主流程**：四柱命理推演流程（**全自动**，无人工任务节点；用户仅在前端录入生辰并等待结果）。流程支持**单命推演**与**八字合婚**两种输入模式，覆盖顶层设计 §2.1 全部 47 项在范围业务。

| 流程 | process id | 名称 | 定位 | 角色任务 |
|---|---|---|---|---|
| 主流程 | `SiZhuBaZiProcess` | 四柱命理推演 | 全自动 | 无人工任务（全 serviceTask） |

> 流程主干「**排盘 → 十神 → 格局取用 → 岁运 → 综合断**」，与四书主线一致（渊海子平「论日为主」「论月令」、子平真诠「论用神」、滴天髓「体用」「衰旺」）；并按顶层设计纳入神煞、纳音、六亲、女命、气势中和、应期、运限、合婚诸项。

>
> **SWRL 推理触发时机**：SWRL 规则由本体推理层在**插入个体的节点**（节点 8 格局判定 / 11 岁运推演 / 14 分类断等）后持续触发推导；网关 **G3 读取 SWRL 推导标志**（大凶 / 寿元关 / 重大疾病）判定是否经 [A] 外发。
>
> **异常处理策略**：①输入校验失败（非法日期 / 缺经度 / 缺时辰）→ 流程终止并回 `INCIDENT`（附校验信息）；②排盘计算异常（历法边界致时辰不可定）→ 标记「需人工确认」并终止；③本体推理失败（不一致）→ 回 `INCIDENT` 并记录本体一致性信息；④RabbitMQ 外发失败 → 记录告警日志、不阻断主流程；⑤前端轮询超时 → 返回最近状态并提示重试。（BPMN 实现层：校验失败即对应 ServiceTask 的 Worker 抛异常，由 Zeebe 生成 **job incident** 并停止推进，该任务元素处于「已激活、未完成」状态；若后续需将异常改写为业务错误并走独立错误分支，可另配 **Error Boundary Event**。）
>
> **网关汇合语义（BPMN 落地）**：G1 分出「合婚 M1」与「单命主链」两支，于**汇合点 J** 汇聚（M1 完成后直接进 J）；G2 分出「W 女命 / C 小儿 / 男命」三支，排他网关同一时刻仅激活一支，回归节点 15 时以**汇聚网关（merge）**接续；G3 分出「[A] 外发 / 不触发」两支，于节点 17 前汇聚。

## 5. 前端交互设计

### 5.1 交互流程

```
用户录入生辰（年月日时 · 公历/农历 · 性别 · 出生地 · 对象类型 · 模式[单命/合婚] · 输出粒度）
  │
  ▼
POST /api/sizhubazi/divine  {birth: {...}, mode, granularity}
  │ 返回 {instanceKey, processId, mode}
  ▼
每秒轮询 GET /api/sizhubazi/divine/{instanceKey}
  │ 返回 {status, variables, chart(排盘), reading(批断), ...}
  ├── status = RUNNING   → 显示"推演中"
  ├── status = COMPLETED → 显示排盘 + 批断结论
  └── status = INCIDENT/TERMINATED → 显示错误
```

| 输出粒度 | `granularity` | 年 / 月 / 日（客户裁定：可选） |

排盘（四柱 / 十神 / 藏干 / 纳音 / 神煞 / 大运流年）+ 批断结论（格局 / 用神 / 层次 / 岁运 / 应期 / 分类断 / 修身劝诫）。
