## 1. 概述与设计理念

SiZhuBaZi 的本体是应用的**业务真相来源**：用 OWL 表达「干支基础 → 干支作用 → 十神六亲 → 神煞 → 旺衰 → 格局取用 → 岁运 → 分类断」的约束与关系，由 Openllet 在运行时推理判定，程序**只查询不判断**、不硬编码业务规则。

**核心设计理念（五条）**：

- **本体即约束**：干支五行、十神生克、干支合冲刑穿害、神煞起例、格局成败、用神喜忌、岁运吉凶等业务约束由 TBox 定义；断命逻辑尽量下沉为类约束（`owl:Restriction`）与 SWRL 规则，而非 Java 分支。
- **节点概念与运转支撑并重**：本体不仅表达「流程每个节点自身所需」的概念（排盘 / 作用 / 十神 / 神煞 / 格局 / 岁运 / 断语），还须表达**流程运转所依赖的支撑体系**（干支基础 / 历法节气 / 六书出处与流派标注 / 术语同义 / 告警标志与命例）——缺之则排盘、取用、断验无法完成（详见 §2.1(B)）。
- **TBox/ABox 分层**：术语定义（类、属性、约束、规则）与实例断言（个体）分层组织——TBox 稳定，ABox 可变（干支 / 神煞 / 格局 / 命例实例）。
- **数据虚拟化**：历法 / 节气 / 真太阳时 / 藏干 / 纳音 / 神煞查表等**运行态数据**留在 MySQL，经 Ontop OBDA 映射以 SPARQL 统一访问，不迁入本体文件（★铁律 13/14）。
- **规则驱动事件**：SWRL 规则在推理时自动推导「大凶 / 寿元关 / 重大疾病」标志个体，触发 RabbitMQ 告警外发（对应流程节点 A）。

> 出处：《SiZhuBaZi应用-顶层设计》§1「核心特征」（本体即约束 / BPMN 管编排 / Ontop 虚拟取数 / 前端可交互 / 消息外发）；`Example应用-本体设计.md`§1 设计理念；《渊海子平》卷之一「论日为主」「论月令」、《子平真诠》「论用神」、《滴天髓》「体用」「衰旺」。

```
        ├── imports deity           (sizhubazi-deity.owl)      → imports core, calendar, chart
        ├── imports tpattern        (sizhubazi-pattern.owl)    → imports core, tengod, relations
        ├── imports yongshen        (sizhubazi-yongshen.owl)   → imports core, pattern, relations
        ├── imports fortune         (sizhubazi-fortune.owl)    → imports core, chart, yongshen, pattern
        ├── imports reading         (sizhubazi-reading.owl)    → imports core, tengod, deity, yongshen, fortune

(术语, 第 13 步)     sizhubazi-terminology.ttl 经 tbox 的 owl:imports 并入
```

> 依赖方向自上而下**单向、无环**：core 为最底层被依赖者，rules 为最上层整合者。
> **约束归属规则（第 10 步执行补充）**：`owl:Restriction` 公理按其 `owl:onProperty` 的**所属域**归入对应子本体（**非**按被约束类的域），以保证该文件内 `owl:onProperty` 与本地声明的属性一致、OWLAPI 可识别匿名类表达式。据此，7 条跨域基数约束由 chart 改归其属性域：`chart/Pillar ⊑ tengod/hasTenGod·hasPalace` → **tengod**；`chart/FourPillars ⊑ yongshen/hasYongShen·hasLevel·hasVitality` → **yongshen**；`⊑ fortune/hasFortuneSynthesis` → **fortune**；`⊑ reading/hasConclusion` → **reading**。故上表 chart 的「隐式 imports」无需扩展，仍为 core+calendar（若按主体类归属则会要求 chart→yongshen/fortune… 形成**环**，不可行）。
> **命名空间归属原则**：子本体的 IRI 分别挂在 `.../core`、`.../calendar` … 之下，各子本体只声明本域类/属性，跨域引用走 `owl:imports`（与 PlumBlossom 九子本体同构）。
