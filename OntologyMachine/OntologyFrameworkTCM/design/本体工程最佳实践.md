## 一、本体构造范式（领域建模）

### 1.1 定式：`equivalenceClass ≡ 病位 ⊓ 病性`（中医经方域）

经方本体放弃「症状 → 证型」的扁平映射，改用**三层推导**：

```
八纲判据(Panju)  →  八纲(病位×病性)  →  六经  →  方证
```

- **六经 `≡` 病位 ⊓ 病性**：如 `Taiyangbing ≡ Biao ⊓ Yang`。`belongsToLiujing` 只用于记录**篇章归属**（哪一篇讲此方），**不**用于推理归属（铁律 22/32/41 路线乙）。
- **方证 `≡` 六经 ⊓ 四诊特征**：如 `≡ Shaoyangbing ⊓ (you_zhengzhuang Kouku) …`。
- **合病一律写 `equivalentClass`**：`TaiyangShaoyinHebing ≡ Taiyangbing ⊓ Shaoyinbing`（铁律 41，全 8 个合病类均写 eq）。

> **可迁移点**：当领域存在「多级抽象 + 组合维度」时，用**等价类表达维度组合**，比用自定义属性挂载更利于 DL 推理器做自动归类；「篇章/出处归属」这类**非语义标签**不要混入推理边。

### 1.2 名义量（nominal）不进 TBox

- 数值 / 具体实例（如某患者的具体脉率）**禁止**写入 TBox，否则触发 SROIQ 分类非确定性爆炸（铁律 54，见 §四.1）。
- 需要保留「名义量型知识」（如某方后注里的定量加减）时，退化为 **ABox 注解属性**（本工程用 `chufang` 注解承载加减方数据，共 264 条）。
- **可迁移点**：TBox 保持「干净、无量纲、纯概念」；个体/实例/数值一律下沉 ABox 或用注解属性承载。

### 1.3 加减/规则层用 SWRL，不用应用层字符串解析

- `fangzheng/rules.owl` 现行 **`owl:versionInfo=2.9`**：方后注加减规则由「注解属性 + 应用层正则解析」改为 **SWRL 规则，由 Openllet 自动激发**（铁律对应见 `本体固化记录.md` §一）。
- 原始注解式 **46 方证 / 84 条**，SWRL 展开后 **259 条**（按 OR / 多动作拆分）。
- 应用层 `deriveFormula` / `deriveFormulaFromSwrl` 只在**结果层**消费推理产物，不承担规则语义。
- **可迁移点**：规则语义应落在**推理器可执行的标准格式**（SWRL/Datalog/SPARQL-Update）里，而非散落在宿主代码的字符串解析中——否则「医理→代码」多一层易漂移的翻译。

### 1.4 TBox / ABox 分离

- 概念层（TBox）与个体层（ABox）分文件、分目录（`tcm-*.owl` 概念、`*-abox.owl` 个体）。
- 详见 `design/03 TBoxABox分离设计.md`。
- **可迁移点**：概念演进频率与数据演进频率不同，分离后 TBox 可独立冻结、ABox 可独立刷新。

### 1.5 分册（minibox）+ 组装

- 本体按六经 / 主题拆成若干分册（`fangzheng/taiyang.owl`、`shaoyin_taiyin.owl` …），由 `tcm-all.owl` 组装。
- 加载与推理用**专用 minibox**（只装当前场景所需的子集），避免全量加载拖慢每次推理。
- **可迁移点**：大本体拆分为可独立加载的**单元**，既利协作维护，也利按需加载的性能优化。

## 二、工程治理范式

### 2.1 铁律显式化、编号化、可审计

- 全部工程约束沉淀为 **69 条铁律**（`design/铁律全集.md`），带 ★ 者=用户硬约束（最高优先级）。
- 每条铁律**可被脚本核验**（`_tielv_code_audit*.py` 逐条给出「断言 → 实测证据 → 判定」），经过 **十二轮**逐条对照代码迭代至零修改。
- **可迁移点**：把「团队共识 / 专家口径 / 平台约束」显式编号并写成**可被自动化核验的断言**，是防止规范腐化的关键。

### 2.2 引用符号名，而非行号

- 铁律 / 设计文档引用代码位置时**引用方法名、类名**（如 `resolveLiujingCrossProduct`），**不引用行号**。
- 原因：本次复校对即发现 **4 处行号漂移**（文件由旧版增长到 `TCMOntologyJobWorker.java` **4289 行**）。
- **可迁移点**：代码引用锚点用**符号**（符号比行号稳定），行号只作辅助。

### 2.3 审计脚本只作候选来源，裁定权留给领域专家

- 脚本（`audit_eq_vs_bagang.py`、`audit_comment_vs_eq.py`、`export_fz_table.py`）负责**批量发现候选问题**；
- **最终裁定必须回到医书医理**（如「甘遂半夏汤证」机械判定会漏掉「里实水饮」，需人工依《金匮》补 `Panju_B10`）。
- **可迁移点**：自动化是「发现器」不是「裁决者」；领域一致性的最终裁定权须保留给人 / 权威知识源。

### 2.4 批量修改本体：幂等脚本 + 全量 diff，禁全局 sed 往返

- 批量改动一律用**幂等脚本**（重复运行结果一致），改动前后做**全量 `diff`** 复核。
- **禁止全局 `sed` 往返替换**——本工程曾因全局替换**误伤 `Wutoutangzheng`**。
- **可迁移点**：结构化文本（OWL/RDF）批量改动要有「生成→校验→diff」闭环，杜绝脆弱的字符串替换。

### 2.5 固化是一个过程，不是一次提交

- 固化 = **逐条复审至零违反**（铁律 68）→ 冻结本体（铁律 69.2）→ **固化后才跑回归**（铁律 69.1）；
- 固化后若回归暴露本体错误，**不得当场改本体**，须记录「本体缺陷」、暂停回归、走复审重新固化（铁律 69.4）。
- **可迁移点**：把「冻结点」制度化——冻结前充分复审、冻结后只允许改非冻结层（本工程只允许改 `OntologyFramework/**`，见铁律 69.3）。

### 2.6 临时产物隔离到工作区

- 一切脚本 / dump / 日志 / 快照 / 备份写入 `HWCodeArtsDir/`（工作区，铁律 66 CodeArts 版），**永不改正式产物**。
- **可迁移点**：中间产物与正式产物物理隔离，正式产物（本体 / 代码 / 设计）的变更才是可审计事件。

## 三、验证范式

### 3.1 唯一真值来源：`rules.owl`

- 所有端到端测试的**期望值**必须由**唯一真值来源**（`fangzheng/rules.owl`）经推理得到；
- **禁止**用 Python 另写一套「期望值生成器」（会产生第二套真值，两套漂移即失控）。
- 期望值由 **Java + OWL API** 闭环生成（与生产加载路径同源）。
- **可迁移点**：测试期望必须有**单一权威来源**，且该来源与生产运行时一致。

### 3.2 双轨测试：离线模拟器（快）+ 真实 BPMN（慢）

- **离线模拟器**：用与生产相同的加载 / 推理路径，快速跑全量方证用例（覆盖广）；
- **真实 BPMN / worker**：端到端验证流程编排、网关、任务注册（覆盖真）。
- 端到端测试须**纯 Java 由 Openllet 闭环推理**，无 Python 生成期望值。
- **可迁移点**：用「快轨」做广度回归、用「慢轨」做可信度验证，二者共享同一套加载路径。

### 3.3 用例构造规范

- **输入 base = DNF 最小充分分支**：每条析取规则取一个最小充分症状集作为用例基，保证**唯一触发集**；
- **按唯一触发集拆例**：一个方证若有多条独立触发路径，拆成多例；
- **注入六经锚点**：为每个用例注入明确的六经锚点，隔离跨经误触；
- **期望 = 所满足规则之并集**。
- **可迁移点**：规则型系统的测试用例应按**规则的触发条件**设计（覆盖每个析取分支），而非随机抽样。

### 3.4 重复取样纪律

- **单次结论不可信**：性能取**中位数**（非单次值）；
- 涉及非确定性的行为（如 Openllet 启动）**至少 3 次取样**；
- 当前稳定口径：TBox 分类中位 **16929 ms**、worker 启动中位 **30.632 s**（铁律 54/57）。
- **可迁移点**：任何「耗时 / 概率 / 资源」类断言都须重复取样后取统计量，禁止单次观测下结论。

### 3.5 判定「卡死」而非「慢」

- 判卡死须看**内存是否持续增长**（内存增长=真卡死；内存平稳=只是慢/阻塞顺序劣化）。
- 偶发卡死按 **kill + retry** 处理，**禁止**为消除爆炸而改 `eq` 或 `rules.owl`。
- **可迁移点**：区分「劣化」与「死锁」，处置手段完全不同。

## 四、关键困难与解决方案（12 项）

| # | 困难 | 根因 | 解决方案 |
|---|---|---|---|
| 1 | **Openllet 非确定性爆炸** | SROIQ 含名义量分类时 tableau 阻塞/展开顺序敏感（固有不稳定性） | 关闭 CD 分类 + 高级缓存；用**独立探针**实证其 pre-existing（`probe/TBoxProbe.java`）；接受偶发并 kill+retry |
| 2 | **机械笛卡尔积改坏 eq** | 脚本按「病位×病性」全组合生成 eq，产生医理上不成立的组合 | 逐条复审，收敛为**按医理裁定**的 eq（`fz_audit_readable.txt` 留 `[REASON:]`） |
| 3 | **锚点污染鉴别点** | 为隔离注入的六经锚点被下游误当症状参与判定 | 锚点取**诊断六经**（而非篇章六经）+ **锚点冗余保护** |
| 4 | **兄弟方证抢占** | 同六经下相近方证的 eq 互相包含，排序时高分者抢占 | 排序键改为 **eq 诊断六经** + **eq 精当化**（提高定义精确度） |
| 5 | **union 多通道误判** | 一条规则含 OR 多通道，测试只认一条通道导致漏报/误报 | 测试**接受任一通道命中**（期望=所满足规则之并集） |
| 6 | **正则解析 OWL 失败** | 用正则解析 RDF/XML，遇嵌套 / 命名空间即错 | 改用**标准 RDF/OWL 解析器**（OWL API / rdflib） |
| 7 | **脉象规则属性口径错** | 脉象误挂到症状属性 | 由 `you_zhengzhuang` 改为 **`you_maixiang`**（脉象用专属性） |
| 8 | **`Thing(sym2)` 通配符恒真** | SWRL/OWL 中误用 `Thing(...)` 使匹配条件恒真 | 移除通配符，改为具体类约束 |
| 9 | **兄弟方证规则污染** | 加减规则跨方证误激发 | 规则**限定 `main-fangzheng-only`**（只对主方证生效） |
| 10 | **先删后加交叉污染** | 加减操作先删后加时，中间态被后续规则误读 | 明确定义操作顺序与中间态可见性，避免顺序耦合 |
| 11 | **医理分叉需单独请示** | 同一方证归属存在多种医理流派解释 | **不擅自裁定**，记录分歧并**单独请示**领域专家 |
| 12 | **stale worker 掩蔽缺陷** | 旧 worker 进程未重启，跑的是旧逻辑，掩盖真缺陷 | 回归前**强制重启 worker**，确认加载的是当前本体/代码 |

## 五、可迁移经验清单（15 条）

1. **先立真值来源**：动手前先确定「唯一权威真值」（本工程=`rules.owl`），测试与实现都向它对齐。
2. **禁名义量进 TBox**：概念层保持无量纲纯净，实例/数值下沉 ABox 或注解。
3. **TBox/ABox 分离**：不同演进频率的资产分文件，独立冻结与刷新。
4. **用真解析器**：结构化知识（RDF/OWL）一律用标准解析器，禁止正则硬解。
5. **专用 minibox**：大本体拆分为按需加载的单元，兼顾维护与性能。
6. **幂等脚本 + 全量 diff**：批量改动必须有「生成→校验→diff」闭环，禁全局 sed 往返。
7. **审计自动化但留裁定权**：脚本只做发现器，领域一致性由权威知识源裁定。
8. **设固化点**：冻结前充分复审、冻结后只改非冻结层；发现问题走重新固化流程。
9. **重复取样纪律**：耗时/概率类断言取中位数 / 至少 3 次，禁单次下结论。
10. **引用符号名而非行号**：代码引用锚点用方法/类名，行号易漂移。
11. **隔离变量实验**：用**独立探针**（而非改生产代码）定位性能/正确性问题。
12. **复用生产加载路径写探针**：探针与生产用同一加载 / 推理路径，结论才可外推。
13. **区分呈现语义与排序语义**：输出「排序键」与「展示字段」分离，别让展示逻辑污染排序。
14. **诊断证据落到具体规则**：每个结论都要能回溯到**触发它的具体规则**（可解释性）。
15. **怀疑脚本产物**：脚本生成的中间结论先质疑再采信，尤其涉及医理/领域语义时。

## 六、元经验

- **医理 > 本体 > 代码**：领域知识是第一性，本体是知识的形式化，代码是因本体的实现。三者冲突时按此优先级裁定。
- **固化是过程而非事件**：真正的质量来自「逐条复审至零违反」的**过程纪律**，而非某一次提交。
- **自动化做广度，人做深度**：脚本负责在海量条目中发现候选，专家负责在少数关键点上做出正确裁定——两者缺一不可。
- **可解释性是一等公民**：任何推理结论都要能回答「为什么」，最终追溯到一条具体规则 / 一条医书条文。
- **不确定性要正视而非掩盖**：推理器的固有非确定性是事实，工程手段是**测量、隔离、容错**（取样、探针、retry），而不是改数据去「消除」它。
