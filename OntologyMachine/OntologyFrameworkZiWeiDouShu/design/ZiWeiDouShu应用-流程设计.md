## 1. 概述与范围

本应用含**一条主流程**：紫微斗数推命流程（**全自动**，无人工任务节点；用户仅在前端录入生辰并等待结果）。流程覆盖顶层设计 §2.1「在范围」**组 A~K 全部 66 项**，支持「直接排盘 / 验盘校正」两种输入模式，并按「**仅本命 / 本命+大限 / 本命+大限+流年**」三档推演深度输出。

| 流程 | process id | 名称 | 定位 | 角色任务 |
|---|---|---|---|---|
| 主流程 | `ZiWeiDouShuChartProcess` | 紫微斗数推命 | 全自动 | 无人工任务（全 serviceTask） |

> 流程主干「**安星排盘 → 观星曜宫位 → 推本命/大限/流年 → 综合断**」，与《全書》主线一致（卷二「安南北斗諸星訣」定安星、卷一「太微賦/形性賦」立本命格局、卷三「談星要論」「論大限十年禍福」「論流年太歲吉凶星殺」定运限断法）；并按顶层设计纳入**流派基线（三合派 + 飞星派并重）**、**四化飞星**、**星曜化气**、**十二长生**、**真太阳时校正**、**验盘**、**叠宫断法**等项。
>
> **业务流程与技术实现分离**：§1~§7 为**纯业务流程设计**（业务语言）；引擎绑定、JobWorker、消息通道、SWRL 推理时机等**实现层细节统一移入附录 A**，不混入业务流程描述（应评审意见 #10）。

### 2.1 验盘闭环（应评审意见 #1 / #2）

- **V 前置条件已满足**：验盘支先经**预排盘主干（节点 2~6）**产出 `命盘骨架 + 十四主星盘 + 辅煞盘 + 杂曜/流曜盘 + 四化盘`，[V] 以此**预排盘命盘**与命主自述的相貌/性情/已知事件特征**逐宫比对反推**，方有盘可验（修复「验盘无盘可验」的逻辑倒置）。
- **回流路径显式**：G1b 判定「需校正」时，**校正后时辰回填 `生辰基准` 并回流至节点 2**，以校正后时辰**重排全盘**（2→3→4→5→6），重排完成后入 J1（修复「校正数据无回流路径」）。
- **轮次保护**：验盘闭环设**轮次上限**（**默认 5 轮**，超出则标记「需人工复核」并终止），防止死循环（见 §7 ㉛）。

## 5. 前端交互设计

### 5.1 交互流程

```
用户录入生辰（年月日时 · 公历/农历 · 性别 · 出生地经度 · 命主类别 · 模式[直接/验盘] · 推演深度）
  │
  ▼
POST /api/ziweidoushu/chart  {birth: {...}, mode, subjectType, depth}
  │ 返回 {instanceKey, processId, mode, depth}
  ▼
每秒轮询 GET /api/ziweidoushu/chart/{instanceKey}
  │ 返回 {status, variables, chart(命盘), reading(批断), ...}
  ├── status = RUNNING   → 显示"排盘/推演中"
  ├── status = COMPLETED → 显示十二宫命盘 + 本命/大限/流年批断
  └── status = INCIDENT/TERMINATED → 显示错误
```

### 5.2 输入选项

| 历法 | `calendar` | 公历 / 农历（含闰月） |

| 性别 | `gender` | 男 / 女 |
| 出生地 | `birthPlace` | 经度（真太阳时校正用；缺省用北京时间平太阳时） |
| 命主类别 | `subjectType` | 成人男 / 成人女 / 小儿 |
| 输入模式 | `mode` | 直接排盘 / 验盘（验盘需录入相貌/事件特征） |
| 推演深度 | `depth` | 本命 / 本命+大限 / 本命+大限+流年 |
| 运限粒度 | `granularity` | 年 / 月 / 日（**默认年**；本期年，月/日 预留衔接 R1） |

### 5.3 结果展示

- **十二宫命盘图形化展示**：方形命盘布局（宫位格位；主星/辅煞/杂曜/四化/庙陷/大限的图示约定——字色、标记、方框；昼夜盘/大限盘/流年盘的叠显规则）（K·65）。

- **劝诫与结论**：阴骘延寿劝诫 / 命书式结论。
- **结构化输出**（JSON Schema）：命盘数据、格局判定、四化飞星、运限结论字段化（K·66）。

## 附录 A：实现附注（非业务流程）

- **推理触发时机**：SWRL 规则由本体推理层（Openllet）在**插入个体的节点**（节点 7 庙陷 / 10 组合交互 / 11 格局 / 12 本命断 / 13~15 运限断等）后持续触发推导；网关 **G4 读取 SWRL 推导标志**（大凶 / 寿元关 / 重大疾病）判定是否经 [A] 外发。
- **异常处理**：①输入校验失败（非法日期 / 缺经度 / 缺时辰 / 农历转换越界）→ 终止回 `INCIDENT`；②排盘计算异常（历法边界致时辰或五行局不可定）→ 标记「需人工确认」并终止；③本体推理失败（TBox 不一致）→ 回 `INCIDENT` 并记录一致性信息；④外发失败 → 记日志、不阻断主流程；⑤前端轮询超时 → 返回最近状态并提示重试。（BPMN 实现层以 Error Boundary Event 承载。）
- **消息通道**：`SwrlRuleTriggerListener` 回调 → `RabbitMqHandler.send(...)` → Exchange `ziweidoushu.alert.exchange`(direct) / routing-key `ziweidoushu.alert` → Queue `ziweidoushuQueue`；`content_type=application/json`（沿用 Example / PlumBlossom / SiZhuBaZi 同构形态）。
- **网关汇合语义（BPMN）**：G1 分出「直接排盘 / 验盘」两支——验盘支含 [V] 与 G1b（可回流重排），二支于 **J1** 汇聚；G2 三分支（W/C/男命）于 **J2** 汇聚；G3 三分支（支内 13→14→15 顺序链）于 **J3** 汇聚；G4 二分支（[A]/不触发）于 **J4** 汇聚后**进节点 18（大模型命书详解）→ 节点 17**。
