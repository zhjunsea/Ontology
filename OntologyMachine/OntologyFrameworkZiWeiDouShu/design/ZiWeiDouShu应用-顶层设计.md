## 1. 概述与定位

`OntologyFrameworkZiWeiDouShu`（应用简称 **ZiWeiDouShu**）是本工程中的一个**本体应用模块**，用于将以**星曜—宫位—四化**为核心的**紫微斗数**推命过程建模为可执行的本体应用。

**业务定位**：用户输入**命主的出生时间信息**（出生年、月、日、时，公历或农历，性别；必要时含出生地以校正真太阳时），应用按紫微斗数「**安星排盘 → 观星曜宫位 → 推本命/大限/流年**」的主干流程，推断命主的**性格禀赋、六亲关系、事业财帛、婚姻健康与人生走势**——即回答：

1. **命盘如何？**（命宫身宫、十二宫、五行局、宫干、诸星庙陷、星曜化气、十二长生、四化落宫 → 盘象）
2. **先天格局如何？**（星曜组合成格 / 破格、命格高低 → 本命格局）
3. **大限流年吉凶、应于何事？**（大限小限流年引动、叠宫三盘、羊陀迭并、七杀重逢 → 运限断）
4. **六亲、婚姻、事业、财帛、疾病等分类事项如何？**（星曜所主 + 宫位 + 三方四正 → 分类断）

> 出处：《紫微斗數全書》卷一「太微賦」「形性賦」「星垣論」立论本命格局；卷一「斗數骨髓賦」「諸星問答論」定诸星所主；卷二「安南北斗諸星訣」「論星辰生克制化」定安星与星曜关系；卷三「談星要論」「論大限十年禍福」「論流年太歲吉凶星殺」定运限断法。

它与 `OntologyFrameworkExample`（Example）、`OntologyFrameworkPlumBlossom`（梅花易数）、`OntologyFrameworkSiZhuBaZi`（四柱命理）等是**同工程内并列、独立**的应用模块，共享底层的 `OpenlletResolver`、`OntopOBDAHandler` 与 `Utilities` 三个能力模块。

**核心特征：**

- **本体即约束**：星曜归属、宫位关系、四化规则、庙陷等级、化气、十二长生、格局判据等业务约束由 OWL TBox 表达，Openllet 推理器在运行时判定，非硬编码。
- **两类「化」须在 ontology 中区分表达**：**星曜化气**（静态、星曜固有属性，如紫微化气为尊）与**四化飞星**（动态、由生年干/宫干引动的流转，化禄/权/科/忌）分属不同本体概念（§2.1·C2·#57 与 §2.1·B·#19 / ·I·#53）。
- **BPMN 管编排**：「安星→观星→推运→综合断」流程拓扑定义在 BPMN 中，部署到 Camunda 8 / Zeebe 由引擎驱动。
- **Ontop 虚拟取数**：历法数据（农历干支、节气、五行局查表、诸星安星表等）留在 MySQL，经 Ontop OBDA 映射以 SPARQL 视角读写。
- **前端可交互**：Web 页面提供生辰信息录入，启动流程并轮询显示命盘与批断结果。
- **消息外发**：重大判定（大凶、寿元关、重大疾病提示等）经 SWRL 推理自动触发 RabbitMQ 消息外发。
- **与八字体系相区别**：紫微斗数重**星曜象义、宫位结构与四化引动**，非以日干为中心的五行生克制化；十二宫义、十四主星、四化飞星为其骨架。
- **流派基线（三合派 + 飞星派并重）**：以 **《紫微斗數全書》所载正统三合派**（安星法 + 三方四正 + 格局）与 **飞星派**（四化飞星「化入化出」流转）**并重为主干**建模；两派差异**如实并陈、不混用、分列标注**；河洛派、南派/北派差异一并标注（详见 §2.4）。

## 2. 范围与边界

> **口径**：本应用力求覆盖 **《紫微斗數全書》**（三卷）所载的紫微斗数业务，并按客户闸门⓪两轮复核意见（2026-10-31）增补**领域遗漏项**与**范围元数据**。仅**确属另一术数体系**（紫微斗数之外）者列为「不在范围」（§2.3）；**本期不做但预留扩展点**者列为「预留接口」（§2.2）。

### 2.0 范围项元数据说明

> 应闸门⓪第二轮评审要求，本节新增**执行约定**，供 §2.1 各表统一遵循。

**(1) 优先级（P0/P1/P2）**——标注于 §2.1 各表「优先级」列：

| 级别 | 含义 | 判定口径 |
|---|---|---|
| **P0** | 核心主干，缺则应用不成立（无法出盘或主干断法断裂） | 排盘/安星主干、主星宫位、庙陷、四化、运限骨架、流派基线、核心输出 |
| **P1** | 重要，影响断准度，可随迭代完善 | 辅煞细节、化气/长生、分类论断扩项、进阶断法 |
| **P2** | 增强/长尾，锦上添花 | 杂曜细目、小儿命、阴骘延寿、行限宫歌等 |

**(2) 验收标准**——标注于 §2.1 各表「验收标准」列。**统一基线**：凡涉及排盘/安星/庙陷/四化等**有客观正确答案**之项，一律以**「金标准盘」比对**为主要验收手段——即由领域专家（陈希夷）依《紫微斗數全書》手工排定若干**标准样例命盘**（覆盖不同年干、五行局、闰月、昼夜生、男女命等），作为测试基准；推理/计算结果须与之**逐宫逐星一致**。凡属**断语类**（吉凶、性情、六亲等）之项，验收标准为「断语可溯源至《全書》原文且不越出原文口径」。

**(3) 依赖关系**——标注于 §2.1 各表「依赖」列，用于消解闸门⓪评审指出的**范围项重叠**问题（如「星曜组合断法」依赖「星曜格局」「诸星所主」；「叠宫断法」依赖各运限项）。被依赖项须先于依赖项实现。

**(4)【待考】分级**——应评审要求，将原单一【待考】标记分为三级：

| 标记 | 含义 | 处置 |
|---|---|---|
| 【待考·轻】 | 细节待补，不影响主干 | 随实现阶段补录，不阻塞 |
| 【待考·中】 | 口径待定，影响某安星/断法环节 | 须在第 2/3 步前澄清或选定默认口径 |
| 【待考·重】 | 核心争议（如紫微起宫、闰月归属），须客户裁定 | **阻塞相关 P0 项**，须闸门确认后方可实现 |

### 2.4 流派基线（关键决策）

> 客户闸门⓪明确指出：**「不先定流派基线，后面开发会走弯路」**——故单列本节。各流派在**安星法**（如紫微起宫、闰月归属、大限起法）与**断法**（重格局 vs 重飞化）上差异显著，须先确定本应用之**主基线**，其余流派差异**如实并陈、不混用**。

| 流派 | 主要特征 | 本应用拟处置 |
|---|---|---|
| **正统三合派**（南派/北派同源） | 以《紫微斗數全書》为宗；**安星法 + 三方四正 + 星曜格局**为断 | **主干之一**（与飞星派并重；与黄金标准同源） |
| **飞星派**（中州派/钦天门等） | 重**四化飞星「化入化出」**流转、宫干飞化、飞星落宫断事 | **主干之一**（与三合派并重）：四化飞星流转作为与三合派并列的建模主干（§2.1·I·#53、#60） |

| **南派 / 北派** | 安星细节差异（紫微起宫、起大限、闰月等） | 差异点登记，随 §2.1·A 待裁定项一并裁定 |

> **已裁定（2026-10-31，闸门⓪）**：采用「**三合派 + 飞星派并重**」——**两派均作为主干建模，差异并陈、分列标注**（工作量相应增大）。
