## 1. 概述与设计理念

ZiWeiDouShu 的本体是应用的**业务真相来源**：用 OWL 表达「基础历法 → 安星排盘 → 观星曜宫位 → 星曜状态/所主 → 格局 → 本命/大限/流年断 → 综合结论」的约束与关系，由 Openllet 在运行时推理判定，程序**只查询不判断**、不硬编码业务规则。

**核心设计理念（六条）**：

- **本体即约束**：星曜归属（南北斗）、宫位关系、安星落宫、四化规则、庙陷等级、星曜化气、十二长生、格局成格判据、运限叠宫等业务约束由 TBox 定义；断命逻辑尽量下沉为类约束（`owl:Restriction`）与 SWRL 规则，而非 Java 分支。
- **节点概念与运转支撑并重**：本体不仅表达「流程每个节点自身所需」的概念（排盘 / 观星 / 格局 / 运限 / 断语），还须表达**流程运转所依赖的支撑体系**（基础历法 / 时辰校正 / 出处与流派标注 / 术语同义 / 告警标志与命例）——缺之则排盘、观星、断验无法完成（详见 §2.1(B)）。
- **两类「化」严格分列**（本域关键约束）：**星曜化气**（`StarCharacter`，十四主星**静态固有属性**，如紫微化气为尊）与**四化飞星**（`Transformation`，由生年干/宫干引动的**动态流转**，化禄/权/科/忌）分属不同子本体（`state` vs `layout`/`fortune`）与不同类，**不得混淆**（顶层设计 §2.1·C·#57 与 B·#19 / I·#53；流程设计 §3「两类化分列声明」）。
- **TBox/ABox 分层**：术语定义（类、属性、约束、规则）与实例断言（个体）分层组织——TBox 稳定，ABox 可变（六十甲子 / 安星查表 / 星曜 / 样例命盘实例）。
- **数据虚拟化**：农历干支 / 节气 / 真太阳时校正 / 五行局 / 安星查表 / 庙陷表 / 神煞起例等**运行态数据**留在 MySQL，经 Ontop OBDA 映射以 SPARQL 统一访问，不迁入本体文件（★铁律 13/14）。
- **规则驱动事件**：SWRL 规则在推理时自动推导「大凶 / 寿元关 / 重大疾病」标志个体，触发 RabbitMQ 告警外发（对应流程节点 A）。

> 出处：《紫微斗数应用-顶层设计》§1「核心特征」（本体即约束 / BPMN 管编排 / Ontop 虚拟取数 / 前端可交互 / 消息外发 / 两类化区分 / 流派基线）；`Example应用-本体设计.md`§1 设计理念；《全書》卷一·太微賦/形性賦（立本命格局）、卷二·安南北斗諸星訣（定安星）、卷三·談星要論（定断法）。
