# 公共铁律 · 强制基线（22 条落地检查表）

> **权威源**：`../../Reference/公共铁律.md`（全文以该文件为准，本表仅做**操作化**）。
> **适用范围**：`OntologyMachine` 下**所有模块**，本技能产出的新应用模块**必须**满足。
> **★** = 用户明确下达的硬约束（最高优先级，不可协商）。
> 本表新增一列「在本 14 步流程中的落点」与「校验方式」，供 `ontology-app-builder` 执行时逐条自检。

| # | 铁律 | 落点（步骤） | 校验方式 |
|---|---|---|---|
| 1 | 必须走 reactor，不能单模块编译 | 第 7/8/14 步构建 | 用 `-am` 连带构建依赖模块；单模块编译报「程序包不存在」即违规 |
| 2 | surefire 必须关闭 manifest-only jar | 第 8 步 `pom.xml` | 新应用 `pom.xml` 的 surefire `configuration` 含 `<useManifestOnlyJar>false</useManifestOnlyJar>` |
| 3 | 区分「离线可跑」与「必须真实环境」的测试 | 第 8 步测试分层 | 测试设计文档显式标注每个类的环境依赖；回归时排除真实环境类 |
| 4 | BPMN 流程用 zeebe-process-test 内存引擎离线测 | 第 8 步 | 存在 `@ZeebeProcessTest` 用例或真实引擎用例；`streamEnabled` 在 `handler` 之后 |
| 5 | 一个超时会被伪装成几十个失败 —— 先看耗时分布 | 第 8/14 步排障 | 看 surefire `Time elapsed`：首错接近阈值=真故障，其余≈0=连坐；每类单跑 |
| 6 | 改完 Java 必须重启进程 | 第 7/8 步 | 比对 class mtime 与进程启动时间；页面新 ≠ 代码新 |
| ★7 | 绝对禁止修改 `OntopOBDAHandler` 与 `OpenlletResolver` 任何文件 | 全流程 | `git status --porcelain -- OpenlletResolver OntopOBDAHandler` 必须为空 |
| ★8 | 测试目标是「完整正确地构建本体」，不是「让所有测试通过」 | 第 4/8/12 步 | 失败先判「本体错 or 测试期望错」；禁止为过测改本体 |
| ★9 | 本体正确性 > 测试通过率；本体定义必须以领域权威为准 | 第 4/6 步 | 冲突优先级：领域权威 > 本体 > 代码 |
| ★10 | 一切改动必须有领域依据，严禁编造 | 第 2/4/6/13 步 | 每条公理/分支指向出处；查不到 → 标「待考」，不硬写 |
| 11 | TBox/ABox 分离的正确落地方式 | 第 9/11 步 | 第 9 步分两个 owl（主本体 ABox import 注释掉）；第 11 步入库 + `ontology.abox-path` + 复用 `OntologyService` |
| 12 | 约束写成 `owl:Restriction`；属性「值/约束」不混用；数值用数值类型 | 第 4/6 步 | 扫描本体：约束不得写在注释里；数值属性为 `xsd:integer/decimal` |
| 13 | Openllet 负责「分类+校验」，计算负责「设计生成」 | 第 4/7 步 | 数值计算/单位换算外置到 Java/BPMN，本体只承载约束与分类 |
| 14 | 程序中不得硬编码业务数据 —— 迁入本体 | 第 7 步 | Java 只保留「语义键 → 值」；变量名/注释/模板迁入本体 |
| 15 | 禁改工程必须用 `git status --porcelain` 核验 | 全流程 | 同上（★7 的核查命令） |
| ★16 | 非工程文件统一写入**工作目录下** `HWCodeArtsDir/` | 全流程 | 工程目录内不新建临时/调试/备份文件；所有新建工程的码道临时文件/脚本都在 `<工作目录>/HWCodeArtsDir/` |
| 17 | 业务 Service 只读本体、只经 `BackendService` 公开 API | 第 7 步 | 不修改底层模块；写库走 `safeVerifyAndDBExecution` 统一入口 |
| 18 | 启动/测试耗时测量必须重复取样 | 第 12/14 步 | A/B 背靠背交错，至少 3 次取中位数/最小值 |
| ★19 | 本体固化后才跑回归；回归期间禁改本体 | 第 12/14 步 | 顺序：本体固化 → 回归；回归期只改应用 Java/资源/测试 |
| ★20 | 改动前需找用户确认；不允许 AI 自行发挥 | 第 2/3/4/6/7/8/9/10/11/12/13 步 | 对应 §3.1 **十一个闸门（①~⑪）**；记录确认人、时间与结论 |
| ★21 | 有现存 API 必须复用 | 第 7/11 步 | 见 `API复用清单.md`；违规先报清单，用户确认后修 |
| ★22 | realize 慢时用 `MiniReasoningContextManager` | 第 7 步 | 单次 `flush` > 5s 或反复注入临时公理 → 建迷你推理上下文，禁用全本体反复 realize |
