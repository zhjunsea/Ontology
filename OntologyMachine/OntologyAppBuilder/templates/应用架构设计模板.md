### 3.3 环境启停脚本（`<模块根>/start-env.cmd`）
> **照 `OntologyFrameworkExample/start-env.cmd` 的形态**生成，一键**准备并启动**运行环境；与 `<Xxx>Application` 及 `EnvPrepare-<version>.jar` 同目录。

| 步骤 | 命令 | 说明 |
|---|---|---|
| 1 | `EnvPrepare-<version>.jar createdb` | 建库 + 灌典型 ABox 数据（errorlevel 校验） |
| 2 | `EnvPrepare-<version>.jar start` | **新窗口常驻**拉起 application.yaml 中的 RabbitMQ / MySQL / Ontop / Camunda |
| 3 | `EnvPrepare-<version>.jar create-rabbitmq` | 建 MQ 资源 |

- 脚本用 `%~dp0` 定位自身（**不硬编码路径**）、先 `chcp 936 >nul`、逐步 `errorlevel` 校验并在失败时 `pause`。
- **须在模块根放置 `EnvPrepare-<version>.jar`（可执行 fat jar）**：脚本以 `%~dp0EnvPrepare-<version>.jar` 定位它，**缺失则运行即报「未找到 EnvPrepare 可执行 jar」而失败**；来源 `OntologyMachine/build/EnvPrepare-<version>.jar`（由 `OntologyFrameworkPlatform` 构建产出）或 `OntologyFrameworkExample-*-project.zip` 内已注入的同名 jar。
- **停止环境 = 关闭该常驻窗口**（脚本回显「关闭此窗口即停止全部服务」）。
- **编码/换行硬约束**：`.cmd` 须存 **GBK(ANSI) + CRLF**（UTF-8 或 LF 会被 cmd 按 GBK 解析致行错位 / `set` 失效）。
- 由 `scripts/validate_structure.py` 做机检（`start-env.cmd` 与 `EnvPrepare-*.jar` 缺失均报 ERROR）。

### 3.4 IDEA 运行配置（`<工作区根>/.idea/runConfigurations/<Xxx>Application.xml`）
> **Spring Boot 类型**运行配置，主类 = `<Xxx>Application`——**启动该 Spring Boot 应用，随之由 Spring 注册并运行 `<Xxx>OntologyJobWorker` 的全部 `@JobWorker`**。
> ⚠️ **落点：工作区根（IDEA 工程根）的 `.idea/runConfigurations/`，不要放模块目录内**——IDEA 只加载**工程根**的 `.idea/runConfigurations/`；聚合工程下子模块目录的 `.idea` 不被加载，放模块内将导致运行配置**在 IDEA 中不可见**。
> **最关键**：`Working directory` 设为 `$MODULE_WORKING_DIR$`（IDEA 内建宏，解析为该模块根 `<Xxx>模块名/`）。原因：`application.yaml` 的相对路径（`ontology/...`、`ontology/database/...`）与 EnvPrepare 向上查找均以**模块根**为基准，沿用默认 `$PROJECT_DIR$` 会解析错误。

| 项 | 值 |
|---|---|
| 配置名 | `<Xxx>Application` |
| 类型 | `SpringBootApplicationConfigurationType`（Spring Boot） |
| `<module name>` | `<Xxx>模块名`（如 `OntologyFramework<Xxx>`） |
| `SPRING_BOOT_MAIN_CLASS` | `com.ocean.ontologyframework.<xxx>.<Xxx>Application` |
| `WORKING_DIRECTORY` | `$MODULE_WORKING_DIR$` |
| `VM_PARAMETERS` | 按需（如 `--enable-native-access=ALL-UNNAMED --sun-misc-unsafe-memory-access=allow`） |

- 由 `scripts/validate_structure.py` 做机检：**在「工作区根（`--workdir`）」的 `.idea/runConfigurations/<Xxx>Application.xml` 检查**（缺失报 ERROR；若误置于模块内则告警）。
