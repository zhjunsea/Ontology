## 1. 目的与范围

**目的**：明确 <Xxx> 应用的质量保证方式——测什么、怎么测、用什么数据、判定依据、如何执行。

**范围**：
- 覆盖 BPMN 流程端到端编排（主干节点顺序、无 incident、网关分支）；
- 覆盖 Ontop OBDA 读写（增/删/改/查、多表拆分事务、正向映射完整性）；
- 覆盖 Openllet 推理（子类检索、SWRL 推导与动态响应、一致性校验）；
- 覆盖 SWRL 触发回调与 RabbitMQ 消息投递；
- 覆盖 OWL 本体合规校验与 SKOS 术语结构/交叉校验。

**不含**：<非本模块的相邻能力，显式声明>。

## 3. 测试分层与策略

| 层级 | 测试类 | 依赖引擎 | 是否需环境 | 关注点 |
|---|---|---|---|---|
| 集成（OBDA + 推理） | <...Tests>（N 项） | 无 | 是 | 推理检索/增删改/事务/SWRL/MQ/合规 |
| 端到端（内存引擎） | <...InMemoryTest> | `EngineFactory` | 是 | BPMN 编排、节点顺序、无 incident |
| 端到端（真实引擎） | <...BpmnRealEngineTest> | 真实 Zeebe `localhost:26500` | 是 | 真实部署与消费 |
| 本体术语（纯 Jena） | `validation/<...SkosTerminologyTest>` | 无 | 否 | SKOS 结构 + OWL 交叉校验 |

**设计原则**：① 分层解耦可离线回归；② 端到端由**生产 Worker 驱动**（不写桩）；③ 本体为唯一裁判；④ 用例间本体快照/恢复隔离。
