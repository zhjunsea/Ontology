## 1. 概述与定位

`OntologyFrameworkNEInsight`（简称 **NEInsight**）把华为**「五看三定」战略洞察方法论**落地为一个**可运行的本体应用**：以**新能源行业**的「**IT 空间**」（企业 IT 基础设施 / 数据中心 / 信息系统）与「**云空间**」（云平台 / 云服务）为**洞察对象**，按 BPMN 流程逐环节执行——

> **五看**（洞察输入）：看行业/趋势 → 看市场/客户 → 看竞争 → 看自己 → 看机会
> **三定**（决策输出）：定战略控制点 → 定目标 → 定策略

每个环节由 JobWorker 驱动**本体推理**与 **Ontop 虚拟取数**，逐环节产出结构化洞察素材（即「要洞察的内容」），并在机会点环节做 SPAN 定位与优先级判定；最终由汇总环节**产出一份「给大模型生成洞察报告的 SKILL」**（以「角色设定 + 任务指令」为骨架、内嵌本次采集的洞察内容，落盘供大模型使用），由大模型据此输出一套可追溯的「新能源 IT/云空间」战略洞察报告。

它与 `OntologyFrameworkExample`（Example）、`OntologyFrameworkPizza`（Pizza）是同工程内**并列、独立**的应用模块，共享底层 `OpenlletResolver`、`OntopOBDAHandler`、`Utilities` 三个能力模块。

**核心特征**（与 Example 同构）：

- **本体即约束**：五看三定的分析框架与判据（如 SPAN 定位规则、SMART 目标校验、战略控制点类型判定）由 OWL TBox 表达，Openllet 运行时判定，**非硬编码**。
- **BPMN 管编排**：「五看三定」8 个分析环节与分支（洞察对象选择、机会点优先级）定义在 BPMN，部署到 Camunda 8 / Zeebe 由引擎驱动。
- **Ontop 虚拟取数**：洞察素材（行业趋势 / 市场客户 / 竞争 / 自身 / 机会等）留在 MySQL，经 Ontop OBDA 映射以 SPARQL 视角读写。
- **前端可交互**：Web 页面选择洞察对象（IT 空间 / 云空间）与场景，启动流程并轮询显示洞察摘要与生成的洞察 SKILL 路径。
- **消息外发**：高优先级机会点 / 关键风险经 SWRL 推理自动触发 RabbitMQ 消息外发（供战略例会订阅）。

> **一句话定位**：NEInsight 是「五看三定」方法论的**本体化执行器**——把一套纸面战略洞察框架，变成有流程、有本体约束、有数据支撑、可复现、可追溯的应用。

## 2. 范围与边界

### 2.1 在范围

1. **方法论编排**：把「五看三定」拆成 8 个可执行的流程环节，落成 BPMN `serviceTask`，由 JobWorker 逐环节执行。
2. **洞察对象建模**：行业/趋势、市场/客户、竞争、自身、机会点、战略控制点、目标、策略——8 类概念的本体建模（类 / 属性 / 约束 / 规则）。
3. **两个洞察域**：「IT 空间」与「云空间」，可分别或联合洞察（由流程网关选择）。
4. **判据本体化**：
   - 机会点 **SPAN 定位**（市场吸引力 × 竞争地位 → 优先级分级）；
   - 目标 **SMART** 校验（具体 / 可衡量 / 可实现 / 相关性 / 有时效）；
   - **战略控制点**类型判定（技术领先 / 成本优势 / 品牌 / 市场份额 / 价值链控制）。
5. **结构化输出**：汇总环节产出「**给大模型生成洞察报告的 SKILL**」——以「角色设定 + 任务指令」为骨架、内嵌本次采集的洞察内容（含各环境结论、机会点优先级、控制点、目标、策略），落盘供大模型生成洞察报告，并回显前端。
6. **事件外发**：高优先级机会点 / 关键风险经 SWRL 触发消息外发。

### 2.2 不在范围（显式声明，不建模）

1. **替代人的战略决策**：本应用只做「洞察的结构化与判定辅助」，最终战略决策仍由业务方作出（★20）。
2. **真实一手市场数据采集**：不接入付费数据库 / 一手调研；洞察素材来自**公开信息**，缺失处标 **【待考】**（见 §3）。
3. **财务测算 / 估值 / 财务模型**：不做营收预测与 ROI 精算（如需，另立模块）。
4. **组织人事 / 绩效考核**：不涉及部门编制、KPI 分配等人事内容。
5. **具体行业子赛道的深度技术方案**：如光伏逆变器拓扑、风机控制算法等工程细节，不在洞察层建模。
