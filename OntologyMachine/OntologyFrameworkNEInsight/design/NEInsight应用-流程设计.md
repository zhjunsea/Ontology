## 1. 概述与范围

本应用含**一条可执行流程**（全自动，无 userTask），部署到 Camunda 8 / Zeebe，由引擎按 BPMN 拓扑驱动，`serviceTask` 派发作业给 `NEInsightOntologyJobWorker`：

| 流程 | process id | 名称 | 定位 | 角色任务 |
|---|---|---|---|---|
| 洞察流程 | `NewEnergyInsightProcess` | 新能源「五看三定」场景洞察流程 | **全自动**：给定**洞察场景**，先调大模型做**输入分析**（抽取身份/场景等关键信息并精炼场景），再按「五看」逐项扫描、按 SPAN 判机会点优先级，再按「三定」产出控制点/目标/策略，汇总环节产出一份**围绕该场景**的「洞察报告生成 SKILL」 | 无 userTask（全 serviceTask） |

> **前置（流程外）**：启动前由 Web 层澄清接口（POST `/api/neinsight/analyze`）确保**必要信息** `{scenario, identity, industry, objective}` 齐全（缺失则向客户追问补齐）；BPMN 流程本身**保持全自动、拓扑不变**，入口节点的输入分析作为流程内兜底。

## 2. 流程总览

```
【洞察流程 NewEnergyInsightProcess —— 场景驱动】
Start（输入：洞察场景 insightScenario）
  → 输入分析（流程内兜底；大模型解析客户输入、抽取身份/场景等关键信息并精炼场景。启动前已由 Web 层澄清接口确保必要信息 `{scenario,identity,industry,objective}` 齐全）
  → 看行业/趋势 → 看市场/客户 → 看竞争 → 看自己 → 看机会（SPAN 定位）
  → 机会点优先级（网关②） ─┬─ 高优先级：标记 + 触发外发 ─┐
                            └─ 非高优先级：直接继续 ───────┤→ 汇合
  → 定战略控制点 → 定目标（SMART） → 定策略 → 汇总输出（生成围绕场景的 SKILL）
  → 生成洞察报告（按 SKILL 各环节「🔎 联网检索指令」应用侧联网采集外部数据 → 连同 SKILL 导入大模型，生成《洞察报告》供下载）
  → End
```

> 节点数量：**1 个开始事件、12 个 ServiceTask、1 个排他网关（机会点优先级）、1 个结束事件**。原「洞察域选择」网关（网关①）与 3 个域扫描节点已随「输入 = 洞察场景」改造移除（13 → 10 ServiceTask）；随后起点新增「输入分析」环节（10 → 11 ServiceTask）；再于汇总之后新增「生成洞察报告」环节（11 → 12 ServiceTask）。

## 3. 环节明细（业务语言，不写技术实现）

| # | 环节（五看三定映射） | 输入 | 处理（业务规则） | 输出 | 待业务裁定 |
|---|---|---|---|---|---|
| 1 | **输入分析（入口）** | 洞察场景（原始文本；必要信息 `{scenario, identity, industry, objective}` 已由启动前澄清补齐） | 调用大模型解析客户输入，抽取**身份 / 场景 / 行业 / 客户 / 目标**等特别关键的信息，并**对场景做准确、专业的精炼**（忠于原文、不添加原文没有的信息），作为后续五看三定与 SKILL 生成的统一语境；**缺失必要信息时由 Web 层澄清接口前置追问，不进入流程** | 结构化解析结果 + 精炼场景（`refinedScenario`）+ 身份（`inputIdentity`）+ 缺失必要信息（`inputMissingFields`） | 大模型未配置/失败时的降级口径（Q11）；必要信息清单与追问口径（Q12） |
| 2 | **看行业/趋势** | 洞察场景 + 宏观环境 | 围绕输入洞察场景，分析**政治/经济/社会/技术**环境、行业发展趋势、产业链；识别「价值转移」方向（趋势＞优势）——依据 S1/S2/S3/S4 | 行业趋势条目（含出处） | 趋势清单口径 |
| 3 | **看市场/客户** | 洞察场景 + 行业趋势 | 分析目标市场规模与需求变化；研究客户**场景 / 痛点（Pains）/ 潜在需求（Wants）**（不止显式要求 Requirements）——依据 S5 | 客户画像 + 痛点/需求条目 | 客户细分口径 |
| 4 | **看竞争** | 洞察场景 + 市场客户 | 识别主要竞争对手的**战略 / 优势 / 劣势 / 动向**，找出差异化发力的空白点 | 竞争格局表 | 竞品清单（【待考】具体对手与数据） |
| 5 | **看自己** | 洞察场景 + 竞争格局 | 客观评估自身**资源 / 能力 / 优势 / 短板**，确定在产业链中的位置与定位——依据 S6 | 自身能力评估 | 自身能力项（【待考】） |
| 6 | **看机会（SPAN 定位）** | 前四看结论 | 综合前四看，用 **SPAN 图**（市场吸引力 × 竞争地位）定位机会点，判定**优先级**（高/中/低）；本应用不内嵌机会点实例数据，故 **`opportunityPriority` 恒为 `NONE`** | 机会点清单 + 优先级（恒 NONE） | 分档阈值（Q5） |
| 7 | **机会点优先级分流** | 机会点清单 | 判定是否存在**高优先级机会点**（或关键风险）；是则标记并触发外发，否则直接进入三定 | 标记结果 | 触发条件（Q8） |
| 8 | **定战略控制点** | 机会点清单 | 确定不易被模仿/超越的中长期核心竞争力，类型取自 {技术领先、成本优势、品牌、市场份额、价值链控制}——依据用户输入 | 战略控制点条目 | 控制点类型集合（Q6） |
| 9 | **定目标（SMART）** | 战略控制点 | 制定可量化、可细化的目标，按 **SMART**（具体/可衡量/可实现/相关性/有时效）校验；本应用不内嵌目标实例数据，故 **`smartCompliant` 恒为 `false`**（SMART 规则 R3 定义保留） | 目标条目（含 SMART 校验结果；恒 false） | SMART 判据量纲（Q7） |
| 10 | **定策略** | 目标 | 制定实现目标的行动方案（组织策略 / 产品策略 / 市场策略），并考虑资源配置与优化 | 策略条目 | 策略维度口径 |
| 11 | **汇总输出** | 全部环节结论 | 生成**围绕输入场景**的「洞察报告生成 SKILL」：以「角色设定 + 任务指令」为骨架，**按「五看三定」逐节点写入两部分**——①**🔎 联网检索指令**（据「场景 × 本节点方法论」生成检索关键词 / 信息源 / 需采集字段，方法论基线取自本体 `core:InsightMethod`）；②**🧮 数据加工与分析要求**（对检索所得数据如何加工分析），并附 **📚 方法论来源**；**不内嵌本体业务实例数据**（内部知识基线不通用）。做一致性校验并落盘 | 洞察摘要 + 洞察 SKILL（落盘路径） | 展示/留档口径（Q10） |
| 12 | **生成洞察报告** | 汇总产出（洞察 SKILL） | 先按「洞察报告生成 SKILL」各环节的「🔎 联网检索指令」**逐环节联网采集外部公开数据**，再将该 SKILL 连同检索结果**导入大模型**，由其加工分析生成一份《洞察报告》（外部数据标注来源）并落盘；检索通道不可用时退回「仅据 SKILL 与本体基线」生成，大模型不可用/失败时**降级为直接落盘 SKILL 内容**（流程不阻断） | 洞察报告（落盘路径） | 报告展示/下载口径（Q13、Q14） |

> 「五看」「三定」全部环节均**以输入的洞察场景为语境**组织内容；原「洞察域扫描」环节（IT 空间 / 云空间 / 联合三选一）已随改造移除。
>
> **改造 v12（2026-10-14）**：本应用**不再内置本体业务实例数据**（内部知识基线不通用，应据输入场景确定所需知识）。表中环节 2–6「五看」与环节 8–10「三定」共 **8 个节点保留流程拓扑**，但**不再检索/输出本体实例数据**——其知识基线为**本体逐节点方法论**（`core:InsightMethod`，给出检索关键词 / 信息源 / 需采集字段 / 加工步骤 / 产出 / 来源），各节点输出仅为**方法论说明 + 「场景 × 方法论」检索指令**；实际外部数据由环节 12（生成洞察报告）按 SKILL 各节点「🔎 联网检索指令」经检索通道**联网采集**后交大模型加工分析。因此 **`opportunityPriority` 恒为 `NONE`、`smartCompliant` 恒为 `false`**，环节 7 高优先级外发（RabbitMQ）与 SMART 规则 R3/SWRL R1/R2/R4 **定义保留但不触发**。

|---|---|---|---|

## 5. 前端交互设计（含 UI）

### 5.1 交互流程
```
用户输入洞察场景（自由文本）
  │
  ▼
POST /api/neinsight/analyze {insightScenario, ...}
  │ 返回 {analysis, missingFields, questions, ready, source}
  ├── ready=false → 展示已提取信息与追问，引导用户多轮补充（可编辑必要字段），回到上一步重新分析
  └── ready=true  → 必要信息齐全，进入启动
  ▼
POST /api/neinsight/insight {insightScenario, scenario, identity, industry, objective}
  │ 服务端校验必要信息齐全（不齐返回 400 附 missingFields/questions）
  │ 返回 {instanceKey, processId, insightScenario, analysis}
  ▼
每秒轮询 GET /api/neinsight/insight/{instanceKey}
  │ 返回 {status, variables, insightSummary, instanceIri, ontologyValidationStatus, insightSkillPath, insightReportPath}
  ├── RUNNING    → 显示"洞察进行中"
  ├── COMPLETED  → 显示洞察摘要、生成的洞察 SKILL 路径与洞察报告路径，并提供「⬇ 下载洞察报告」入口
  └── INCIDENT / TERMINATED → 显示错误
```

### 5.2 输入
| 项 | 形态 | 说明 |
|---|---|---|
| 洞察场景 | 文本（自由输入） | 前端多行文本输入；系统据此抽取**必要信息**。示例：面向双碳目标的新能源企业 IT 与云协同数据平台建设 |
| 必要信息（澄清） | 结构化（必填） | `scenario`（场景）/`identity`（身份）/`industry`（行业）/`objective`（洞察目标）；缺失时经 `/api/neinsight/analyze` 追问、齐全后方可启动；其余字段（`customer`/`region`/`timeframe`/`keyEntities`）可选、不阻断 |

> 原「洞察域三选一」输入已取消；域概念并入场景内容表达，检索根域固定为联合域（覆盖 IT 空间与云空间全部要素）。

## 6. 消息/事件

```
高优先级机会点 / 关键风险（SWRL 推导） → RabbitMqHandler.send()
  │
  ▼
Exchange: neinsight.opportunity.exchange (direct)
  │ routing-key: opportunity.high.priority
  ▼
Queue: neinsightOpportunityQueue
```
载荷为 JSON：`{event, domain, opportunityIri, opportunityLabel, marketAttractiveness, competitivePosition, priority, flaggedForAlert}`（`domain` 为检索根域，固定联合域；`event=NEINSIGHT_HIGH_PRIORITY_OPPORTUNITY`），`content_type=application/json`。
