## 1. 概述与范围

本应用含**一条可执行流程**（全自动，无 userTask），部署到 Camunda 8 / Zeebe，由引擎按 BPMN 拓扑驱动，`serviceTask` 派发作业给 `NEInsightOntologyJobWorker`：

| 流程 | process id | 名称 | 定位 | 角色任务 |
|---|---|---|---|---|
| 洞察流程 | `NewEnergyInsightProcess` | 新能源 IT/云空间「五看三定」洞察流程 | **全自动**：给定洞察对象与洞察域，按「五看」逐项扫描、按 SPAN 判机会点优先级，再按「三定」产出控制点/目标/策略，汇总环节产出「给大模型生成洞察报告的 SKILL」 | 无 userTask（全 serviceTask） |

---

## 2. 流程总览

```
【洞察流程 NewEnergyInsightProcess】
Start
  → 洞察域选择（网关①） ─┬─ IT 空间扫描 ─┐
                          ├─ 云空间扫描 ──┤→ 汇合
                          └─ 联合扫描 ────┘
  → 看行业/趋势 → 看市场/客户 → 看竞争 → 看自己 → 看机会（SPAN 定位）
  → 机会点优先级（网关②） ─┬─ 高优先级：标记 + 触发外发 ─┐
                            └─ 非高优先级：直接继续 ───────┤→ 汇合
  → 定战略控制点 → 定目标（SMART） → 定策略 → 汇总输出
  → End
```

> 节点数量：**1 个开始事件、13 个 ServiceTask、2 个排他网关（洞察域选择 / 机会点优先级）、1 个结束事件**。

## 3. 环节明细（业务语言，不写技术实现）

| # | 环节（五看三定映射） | 输入 | 处理（业务规则） | 输出 | 待业务裁定 |
|---|---|---|---|---|---|
| 1 | **洞察域扫描** | 洞察对象（IT 空间 / 云空间 / 联合） | 按所选洞察域，梳理该域的现状与范围；联合域则同时覆盖两者 | 洞察域基线清单 | 域边界定义（Q2/Q3） |
| 2 | **看行业/趋势** | 域基线 + 宏观环境 | 分析**政治/经济/社会/技术**环境、行业发展趋势、产业链；识别「价值转移」方向（趋势＞优势）——依据 S1/S2/S3/S4 | 行业趋势条目（含出处） | 趋势清单口径 |
| 3 | **看市场/客户** | 行业趋势 | 分析目标市场规模与需求变化；研究客户**场景 / 痛点（Pains）/ 潜在需求（Wants）**（不止显式要求 Requirements）——依据 S5 | 客户画像 + 痛点/需求条目 | 客户细分口径 |
| 4 | **看竞争** | 行业趋势 + 市场客户 | 识别主要竞争对手的**战略 / 优势 / 劣势 / 动向**，找出差异化发力的空白点 | 竞争格局表 | 竞品清单（【待考】具体对手与数据） |
| 5 | **看自己** | 域基线 + 竞争格局 | 客观评估自身**资源 / 能力 / 优势 / 短板**，确定在产业链中的位置与定位——依据 S6 | 自身能力评估 | 自身能力项（【待考】） |
| 6 | **看机会（SPAN 定位）** | 前四看结论 | 综合前四看，用 **SPAN 图**（市场吸引力 × 竞争地位）定位机会点，判定**优先级**（高/中/低） | 机会点清单 + 优先级 | 分档阈值（Q5） |
| 7 | **机会点优先级分流** | 机会点清单 | 判定是否存在**高优先级机会点**（或关键风险）；是则标记并触发外发，否则直接进入三定 | 标记结果 | 触发条件（Q8） |
| 8 | **定战略控制点** | 机会点清单 | 确定不易被模仿/超越的中长期核心竞争力，类型取自 {技术领先、成本优势、品牌、市场份额、价值链控制}——依据用户输入 | 战略控制点条目 | 控制点类型集合（Q6） |
| 9 | **定目标（SMART）** | 战略控制点 | 制定可量化、可细化的目标，按 **SMART**（具体/可衡量/可实现/相关性/有时效）校验 | 目标条目（含 SMART 校验结果） | SMART 判据量纲（Q7） |
| 10 | **定策略** | 目标 | 制定实现目标的行动方案（组织策略 / 产品策略 / 市场策略），并考虑资源配置与优化 | 策略条目 | 策略维度口径 |
| 11 | **汇总输出** | 全部环节结论 | 生成「给大模型生成洞察报告的 SKILL」：以「角色设定 + 任务指令」为骨架，内嵌本次采集的洞察内容（各环境结论 + 机会点优先级 + 控制点 + 目标 + 策略），做一致性校验并落盘 | 洞察摘要 + 洞察 SKILL（落盘路径） | 展示/留档口径（Q10） |

## 4. 分支条件

| 网关 | 分支 | 条件（互斥且完备） | 依据 |
|---|---|---|---|
| ① 洞察域选择 | IT 空间 | `insightDomain = IT_SPACE` | 用户输入（Q2） |
| ① 洞察域选择 | 云空间 | `insightDomain = CLOUD_SPACE` | 用户输入（Q3） |
| ① 洞察域选择 | 联合 | `insightDomain = COMBINED` | 用户输入（Q4） |
| ② 机会点优先级 | 高优先级 | 存在 `opportunity.priority = HIGH`（或 `risk = CRITICAL`） | SPAN 规则（Q5/Q8） |
| ② 机会点优先级 | 非高优先级 | 不存在上述情况 | 同上 |

> 两个网关的分支**两两互斥、合起来完备**：网关①三分支覆盖全部洞察域取值；网关②两分支覆盖「有/无高优先级」。

## 5. 前端交互设计（含 UI）

### 5.1 交互流程
```
用户选择洞察域（IT 空间 / 云空间 / 联合）
  │
  ▼
POST /api/neinsight/insight {insightDomain}
  │ 返回 {instanceKey, processId, insightDomain}
  ▼
每秒轮询 GET /api/neinsight/insight/{instanceKey}
  │ 返回 {status, variables, insightSummary, instanceIri, ontologyValidationStatus, insightSkillPath}
  ├── RUNNING    → 显示"洞察进行中"
  ├── COMPLETED  → 显示洞察摘要与生成的洞察 SKILL 路径（供大模型生成报告）
  └── INCIDENT / TERMINATED → 显示错误
```

### 5.2 输入选项
| 选项 | 标识 | 特点 |
|---|---|---|
| IT 空间 | `IT_SPACE` | 洞察企业 IT 基础设施 + 业务信息系统 |
| 云空间 | `CLOUD_SPACE` | 洞察云平台 / 云服务 |
| 联合 | `COMBINED` | 同时洞察 IT 空间与云空间 |

## 6. 消息/事件

```
高优先级机会点 / 关键风险（SWRL 推导） → RabbitMqHandler.send()
  │
  ▼
Exchange: neinsight.opportunity.exchange (direct)
  │ routing-key: opportunity.high.priority
  ▼
Queue: neinsightOpportunityQueue
```
载荷为 JSON：`{opportunityName, domain, spanQuadrant, priority, rationale}`，`content_type=application/json`。
