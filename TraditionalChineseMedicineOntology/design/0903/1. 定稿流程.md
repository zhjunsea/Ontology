# 经方辨证推理全流程（本体驱动·证据链双层裁决版）

> 本流程依据《伤寒论》经方体系（胡希恕·方证对应）设计，采用“基层症状投票 + 高层证型裁定”的双层证据链架构，完全基于OWL本体驱动，杜绝硬编码，具备高度扩展性。

---

## 📋 流程总览

```
患者就诊
  │
  ▼
【采集四诊信息】症状 + 脉象 + 舌象 + 体质 + 治疗史
  │  ★ 所有输入统一映射为标准化证据（URI）
  ▼
【Step 1】八纲综合判定（证据链双层裁决）
  ├─ 1.1 基层证据采集（症状→八纲投票）
  ├─ 1.2 证型预匹配（无硬编码模式匹配）
  ├─ 1.3 高层八纲裁决（证型补全“未定”维度）
  └─ 1.4 证据链完整性检查 → 若≥2维未定，触发问诊/参考方
  ▼
【Step 2】主病判定 + 合病/并病识别（六经兼病层）
  ├─ 急症优先检查（亡阳/阳明热盛/亡阴/腑实/除中）
  ├─ 常规主病判定（基于八纲）
  ├─ 合病/并病识别（表+里、表+半、里+半等）
  └─ 治疗策略输出（先解表/先攻里/表里双解等）
  ▼
【Step 3】六经归属（病位+阴阳→查表）
  ├─ 标准映射：表+阳=太阳，表+阴=少阴，里+阳=阳明，里+阴=太阴，半+阳=少阳，半+阴=厥阴
  ├─ 三阴底线：必须阴阳=阴
  ├─ 厥阴强制：病位=半 + 寒热错杂 + 阴阳=阴
  ├─ 少阳特权：脉弦 + 病位=半 + 主症≥1 + 排除阳明/太阳
  └─ 证据不足则“六经难定”
  ▼
【Step 4】方证匹配（排它证 + 核心病机 + 否决 + 加减 + 合方 + 证据链排序 + 条文锚定）
  ├─ 候选池筛选（症状反向索引）
  ├─ 硬性排除（真寒假热/真热假寒/六经排它/体质禁忌/津液胃气）
  ├─ 核心病机匹配（主症覆盖）
  ├─ 特异性否决（否决症状→淘汰）
  ├─ 特异性加减（或然症触发加减）
  ├─ 双重一致性校验（方证-八纲一致性、方证-六经一致性）
  ├─ 兼病与兼夹的并行处理
  │   ├─ A. 确定六经方证底方（合方优先→主方+加减→合方）
  │   └─ B. 叠加兼夹加药（水饮→半夏/茯苓；瘀血→桃仁/红花；食积→山楂/神曲；气滞→柴胡/枳壳）
  ├─ 证据链分级排序
  ├─ 条文锚定
  └─ 兜底：候选集为空→最高分→partial_match→参考方
  ▼
【Step 5】禁忌校验 + 煎服法 + 传变预警 + 处方输出
  ├─ 禁忌校验（各经/津液胃气/体质/十八反十九畏/有毒药物安全）
  ├─ 传变预警（太阳→阳明、太阳→少阳，含正向+反向证据）
  ├─ 干预结果（无需调整/已调整/建议调整）
  ├─ 煎服法 + 饮食起居禁忌 + 停药条件
  └─ 输出最终处方 + 安全等级 + 禁忌警告 + 传变预警 + 处方证据链
  ▼
出方（医师确认后执行）
```

## 🧬 各步骤详细说明

### Step 1：八纲综合判定（证据链双层裁决）

**服务**：`step1-bagang-judgment`

#### 1.1 基层证据采集
- 输入：标准化症状/脉象/舌象URI列表
- 映射：通过 `zhengzhuangtizheng.owl` 中每个症状的 `symptom_indicates_bagang` 属性，统计各八纲维度（表、里、寒、热、虚、实、阴、阳）的证据票数。
- 输出：八纲初稿（可能含“未定”），并记录每条证据来源。

#### 1.2 证型预匹配（新增·核心）
- 输入：当前症状集合（全量）
- 匹配范围：`bingzheng.owl` 中所有 `DiseasePattern` 个体
- 匹配规则（无硬编码）：
  - **主症命中率**：计算该证型的 `has_symptom` 中命中的比例
  - **否决症状检查**：若触发了任一 `has_exclusion_symptom`，则直接否决该证型
  - **或然症加分**（可选）：匹配 `has_or_symptom` 可提升置信度
  - **置信度分级**：
    - **高置信度**：主症命中率 ≥ 80% 且无否决症状
    - **中置信度**：主症命中率 50%~80% 且无否决
    - **低置信度**：主症命中率 < 50% 或存在否决
- 输出：最佳候选证型列表（按置信度排序），并读取每个证型上挂载的 `tcm:has_bagang_element` 标签。

#### 1.3 高层八纲裁决（通用算法）
- 输入：基层投票初稿 + 最佳候选证型（若高置信度则取第一个，否则取前三个）
- 裁决逻辑（纯通用，不依赖任何具体证型名）：
  ```
  对于每个八纲维度（表、里、寒、热、虚、实、阴、阳）：
    若初稿该维度 == "未定"：
       从高置信度证型的八纲标签中查找是否有该维度的明确赋值；
       若有，则采用该值，并在证据链中记录“高层裁定：由证型 <URI> 补充”；
       若无，则保留“未定”。
    若初稿该维度有值但和高置信度证型提供的值冲突：
       记录冲突警告，但仍以初稿为准（或可配置为以证型为准）。
  ```
- 特殊标记：若匹配的证型带有 `bz:special_mark` 等标记（如厥阴、太少两感），则原样保留至输出。

#### 1.4 证据链完整性检查
- 若裁决后仍有 ≥2 个维度为“未定”，标记“辨证依据严重不足”，触发迭代补充问诊或参考方兜底。
- 若仅有 1 个维度未定，标记“证据链部分不足”，仍可进入后续步骤，但整体置信度降低。

**输出**：
- 八纲各维度最终判定（表里寒热虚实阴阳）
- 兼夹证标记（水饮、瘀血、食积、气滞）
- 特殊标记（厥阴、太少两感）
- 完整证据链记录（含基层投票 + 高层裁定）

### Step 2：主病判定 + 合病/并病识别

**服务**：`step2-primary-judgment`

#### 急症优先检查（最高优先级，跳过六经）
| 急症类型 | 判定条件 | 方药 | 后续动作 |
|----------|----------|------|----------|
| 亡阳 | 脉微欲绝/浮大无根 + 大汗冷稀 + 肢厥过肘膝 + 精神萎靡 | 四逆汤/通脉四逆汤 | 跳至Step 5 |
| 阳明热盛伤津 | 大热+大渴+大汗+脉洪大有力 | 白虎加人参汤 | 跳至Step 5 |
| 亡阴 | 汗出如油 + 脉细数无力 + 身热肢温 + 渴引饮 + 唇舌干红 | 炙甘草汤/加减复脉汤 | 跳至Step 5 |
| 阳明腑实危重 | 潮热/谵语/腹满硬痛≥2 + 不大便≥5日/手足濈然汗出≥1 | 大承气汤 | 跳至Step 5 |
| 除中 | 脉微细欲绝 + 久病危重 + 突然暴食 | — | 危候警示 |

#### 常规主病判定（无急症时）
- **主病依据**：以 Step 1 八纲结果确定主病（如“表证”为主则主病在表）。
- **合病/并病识别**：检查是否存在多经证据（采用连续型证据强度，阈值≥0.3表示该经有显著证据）：
  - 表+里均>0.3 → 太阳阳明合病
  - 表+半均>0.3 → 太阳少阳合病
  - 里+半均>0.3 → 少阳阳明合病
  - 三经均>0.3 → 三阳合病
  - 若有先后顺序 → 并病（先治未罢之经）
- **治疗原则（表里同病时）**：
  - 里实危急 → 先治里
  - 里虚寒 → 先温里
  - 表里俱实 + 里危急 → 表里双解
  - 表里俱实 + 里未危急 → 先解表后攻里
  - 表里俱虚 → 先补里后解表

**输出**：
- 主病（六经归属前的病位定性）
- 合病/并病标记（含组合名称）
- 治疗策略（解表/攻里/双解/温里/补里等）
- 急症标记（若有）

### Step 3：六经归属

**服务**：`step3-liujing-mapping`

#### 查表规则（标准映射）
| 病位 | 阴阳 | 六经 |
|------|------|------|
| 表   | 阳   | 太阳 |
| 表   | 阴   | 少阴 |
| 里   | 阳   | 阳明 |
| 里   | 阴   | 太阴 |
| 半   | 阳   | 少阳 |
| 半   | 阴   | 厥阴 |

#### 特殊规则
- **三阴病底线**：判太阴/少阴/厥阴的前提必须是 Step 1 阴阳 = 阴。
- **厥阴病强制要求**：病位=半 + 寒热错杂（证据链中有明确寒热错杂标记） + 阴阳=阴（脉无力/肢冷/精神萎靡）。若病位=半 + 寒热错杂 + 阴阳=阳 → 判少阳，非厥阴。
- **少阳特权限制**：必须满足脉弦 + 病位=半 + 少阳主症（口苦/咽干/目眩/往来寒热/胸胁苦满等）≥1项 + 排除阳明/太阳证据。
- **三阴不典型识别**：
  - 太阴典型：腹满喜按 + 舌淡苔白滑 + 口和不渴
  - 少阴典型：精神萎靡 + 脉沉细无力
- **证据不足**：经迭代补充问诊后仍难定，则输出“六经难定”，候选池不限六经。

**输出**：
- 六经归属（太阳/阳明/少阳/太阴/少阴/厥阴/六经难定）
- 六经病程（复诊时累加，如“太阳病第3日”）

### Step 4：方证匹配（排它证 + 核心病机 + 否决 + 加减 + 合方 + 证据链排序 + 条文锚定）

**服务**：`step4-fangzheng-match`

#### 4.1 候选池筛选
- 使用症状反向索引，从 `bingzheng.owl` 中快速检索包含当前症状的方证，形成候选池。

#### 4.2 硬性排除
- 真寒假热 → 排除白虎/承气类
- 真热假寒 → 排除四逆/理中类
- 六经排它（如太阳病禁用下法）
- 体质禁忌（如平素便溏者禁用大黄）
- 津液胃气排它（如胃气虚者禁用苦寒）

#### 4.3 核心病机匹配
- 必需主症覆盖关键核心症状（不强制100%机械覆盖，但需达到病机一致）。

#### 4.4 特异性否决
- 若存在该方证的否决症状（`has_exclusion_symptom`），则直接淘汰。
- 示例：桂枝汤见“无汗、脉紧” → 否决；小青龙汤见“脉弱、汗出” → 否决；小柴胡汤见“纯阳明腑实” → 否决。

#### 4.5 特异性加减
- 核心病机匹配，但出现某些或然症 → 触发方剂加减。
- 示例：
  - 小柴胡汤证见“渴” → 去半夏加人参瓜蒌根（第96条）
  - 桂枝汤证见“项背强几几” → 桂枝加葛根汤（第14条）
  - 小青龙汤证见“烦躁” → 小青龙加石膏汤

#### 4.6 双重一致性校验
- 方证-八纲一致性：候选方证挂载的八纲与Step 1最终八纲必须一致，否则淘汰。
- 方证-六经一致性：候选方证归属的六经（由 `belongs_to_liujing` 或推理得到）与Step 3的六经必须一致，否则淘汰。

#### 4.7 兼病与兼夹的并行处理（关键修正）
- **步骤 A**：确定六经方证底方
  - 若 Step 2 标记了“合病/并病” → 优先使用仲景合方（如柴胡桂枝汤、大柴胡汤等）作为底方。
  - 若无仲景合方，则采用“主方+加减”策略。
  - 若单方覆盖不足，则采用合方（最后手段）。
  - 若无合病/并病 → 以 Step 3 六经归属确定的主方作为底方。
- **步骤 B**：叠加兼夹加药
  - 若 Step 1 标记了“兼夹证” → 在底方基础上叠加加药：
    - 水饮 → 加半夏、茯苓
    - 瘀血 → 加桃仁、红花
    - 食积 → 加山楂、神曲
    - 气滞 → 加柴胡、枳壳
- **步骤 C**：合并输出 → 最终处方 = 底方（合方或主方） + 兼夹加药

#### 4.8 证据链分级排序
- 高特异辅助证（`evidenceLevel = 高特异铁证`）优先于一般辅助证（`一般线索`）考虑。

#### 4.9 条文锚定
- 每个方证标注《伤寒论》或《金匮要略》条文依据（`clause_number`）。

#### 兜底策略
- 若候选集为空 → 取最高分候选 → 标记 `partial_match` → 经禁忌校验后输出“参考方”。

**输出**：
- 候选方证列表（含条文、证据链、加减建议、合方建议）
- Top1 方证（最终推荐）
- 否决记录（被淘汰的方证及原因）

### Step 5：禁忌校验 + 煎服法 + 传变预警 + 处方输出

**服务**：`step5-contraindication-output`

#### 5.1 禁忌校验
- 各经禁忌（如太阳病禁下、阳明病禁汗等）
- 津液胃气保护（如津亏者慎用汗吐下）
- 体质禁忌（如素体阳虚者慎用苦寒）
- 十八反十九畏（中药配伍禁忌）
- 有毒药物安全控制（如附子先煎、细辛不过钱）

#### 5.2 传变预警
- **太阳→阳明**：
  - 正向证据：太阳病≥3日 + 口渴加重 + 恶寒转恶热
  - 反向证据：舌苔仍白 / 脉不数 / 小便清长
- **太阳→少阳**：
  - 正向证据：太阳病≥5日 + 口苦/胸胁满/往来寒热
  - 反向证据：脉不弦 / 无往来寒热 / 胸胁不满

#### 5.3 干预结果
- 无需调整（禁忌检查通过）
- 已调整（系统自动加减或替换药物）
- 建议调整需医师确认（存在潜在风险）

#### 5.4 煎服法 + 饮食起居禁忌 + 停药条件
- 煎服法：如“桂枝汤：以水七升，微火煮取三升，去滓，适寒温，服一升。服已须臾，啜热稀粥一升余，以助药力。”
- 饮食禁忌：忌生冷、油腻、五辛、酒酪、臭恶等。
- 停药条件：如“若一服汗出病差，停后服，不必尽剂。”

**输出**：
- 最终处方（含药物、剂量、煎服法）
- 安全等级（安全/需谨慎/高危）
- 禁忌警告列表
- 传变预警列表
- 处方证据链（包含从Step 1到Step 5的所有关键决策依据）

## ⚙️ 关键机制说明

### 证据链双层裁决机制
- **基层证据**：由原子症状的 `symptom_indicates_bagang` 直接投票，体现“无征不信”。
- **高层裁定**：由匹配到的高置信度证型补全基层未定的八纲维度，体现“方证是辨证的尖端”。
- **裁决冲突处理**：若基层与高层冲突，默认以高层为准（可配置），但记录冲突供医师审阅。

### 无硬编码原则
- 所有知识（症状→八纲、证型→八纲、主症/否决/加减规则）均存储在OWL本体中，Java代码仅实现通用逻辑。
- 新增症状或证型时，只需修改OWL文件，无需改动代码。

### 置信度与证据链完整性
- 每个步骤的输出都携带置信度（High/Medium/Low）和完整的证据来源列表。
- 当多个维度为“未定”时，系统会主动建议补充问诊，避免盲目出方。
