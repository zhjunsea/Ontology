# 经方加减药规则本体设计（v1.0）

> **依据**：《伤寒论》《金匮要略》原文方后注、胡希恕“方证对应”思想、黄煌“药证”理论。
>
> **设计原则**：加减规则是独立于方根/家族/方证三层的**第四层（规则层）** ，通过 `owl:AnnotationProperty` 挂载于三层之上，由应用层读取并执行。规则只写原文有据的加减，不臆造。


## 一、规则层的定位

```text
第一层：方根层（Fanggen）
  └── 最小配伍单元，提供“最小变更单元”
       │
第二层：家族层（Jiazu）
  └── 类方家族，提供“家族级加减规则”挂载点
       │
第三层：方证层（Fangzheng）
  └── 具体方证，提供“方证级加减规则”挂载点
       │
第四层：规则层（Rule）← 本设计核心
  └── addHerb / removeHerb / replaceHerb 注释属性
       └── 应用层读取 → 匹配患者症状 → 执行加减动作
```

**关键原则**：
- **方根层规则**：方根级加减，适用于该方根衍生的所有方证
- **家族层规则**：家族级加减，适用于该家族的所有方证（含本体未收录的方证）
- **方证层规则**：方证级加减，精确到该方证的原文加减法
- **优先级**：方证层 > 家族层 > 方根层（越具体越优先）

## 三、规则层使用说明

### 1. 规则优先级

| 优先级 | 挂载层 | 适用范围 | 例 |
|---|---|---|---|
| 低 | 方根层 | 该方根衍生的所有方证 | 桂枝芍药姜枣草方根 + 项强 → 加葛根 |
| 中 | 家族层 | 该家族的所有方证（含本体未收录的） | 桂枝汤类 + 腹中急痛 → 小建中汤 |
| 高 | 方证层 | 精确到该方证的原文加减法 | 小柴胡汤证 + 渴 → 去半夏加人参栝蒌根 |

### 2. 应用层执行流程

```text
输入：患者症状集合 S，命中方证 F（或其家族）
输出：最终处方（母方 + 加减药物）

Step 1：确定命中的方证 F 及其所属家族族 F_family、方根 F_root
Step 2：按优先级从高到低读取规则：
   - 先读 F 的方证级规则（addHerbRule / removeHerbRule / replaceHerbRule）
   - 再读 F_family 的家族级规则
   - 最后读 F_root 的方根级规则
Step 3：对每条规则，检查 S 是否满足规则的条件（IF 部分）
Step 4：满足则执行规则的动作（THEN 部分）：
   - addHerb：在方剂中增加药物
   - removeHerb：从方剂中删除药物
   - replaceHerb：以药物A替换药物B
Step 5：输出最终方剂组成
```

## 四、方证不在本体时的自动加减生成

假设本体中**没有** `Guizhijiagegentangzheng`（桂枝加葛根汤证）这个类，但患者录入：

```text
症状：发热、汗出、恶风、项背强几几
```

推理过程：

1. **方证层**：命中 `Guizhitangzheng`（桂枝汤证）
2. **家族层**：`Guizhitangzheng` 属于 `Guizhitangleifangzheng`（桂枝汤类）
3. **规则层**：家族级规则 `桂枝汤类 + 项强 → 加葛根四两` 触发
4. **方剂层**：在桂枝汤基础上加葛根，自动生成“桂枝加葛根汤”

**这样，即使本体里没有“桂枝加葛根汤证”，系统也能通过家族级加减规则生成它。** 这正是方根—家族—方证三层 + 规则层的核心价值。
