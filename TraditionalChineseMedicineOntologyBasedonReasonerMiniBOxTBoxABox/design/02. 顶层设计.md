## 一、系统定位

把《伤寒论》「病脉证并治」体系编译成**可计算本体**，由 **Camunda 编排的 10 个 JobWorker**
串成一条**全自动**诊断流水线：

```
自然语言四诊输入 → 症状实例个体 → 一致性检查 → 八纲 → 六经 → 方证
                 → 兼夹证 → 母方 → 方后注加减 → 诊断解释
```

**架构目标**：

| 目标 | 手段 |
|---|---|
| **全自动** | BPMN 无 userTask，JobWorker 一路跑到结束事件 |
| **可追溯** | 每步结论回溯到四诊发现与条文依据 |
| **单向性** | 判据 → 八纲 → 六经 → 方证，严禁反推（铁律 32/60） |
| **高性能** | 三阶段 minibox + 每步物化 + Openllet 调优 |
| **不硬凑** | 结果三态化，只有完全命中才算结论（铁律 16） |

## 三、应用层

### 3.1 REST 契约

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/diagnosis` | 启动一次诊断。Body `{text}`；返回 `202 Accepted` + 快照 |
| `GET` | `/api/diagnosis/{key}` | 查询进度与结果 |
| `POST` | `/api/diagnosis/{key}/confirm` | 提交症状映射确认（**历史遗留**，当前流程无 userTask） |
| `GET` | `/api/diagnosis/{key}/tasks` | 列出待办人工任务（同上） |
| `POST` | `/api/diagnosis/{key}/tasks/{taskKey}` | 完成指定人工任务（同上） |
| `GET` | `/api/diagnosis/catalog` | 症状实例个体目录（前端自动补全），支持 `category` / `q` / `limit` |
| `GET` | `/api/diagnosis/health` | 健康检查：`engineAvailable` / `catalogSize` / `processId` |

**快照结构**：`processInstanceKey`、`status`、`mapping`、`diagnosis`、`pendingTasks`。
`status` 取值：`AWAITING_CONFIRMATION` / `AWAITING_REVISION`（遗留）/ `COMPLETED` / `RUNNING`。

### 3.2 启动收敛

`start()` 启动流程实例后 `awaitSettled(key, 30_000ms)`，每 `250ms` 轮询一次快照，
直到状态不再是 `RUNNING` 或超时。

> ⚠️ **实现约定**：Controller 所有 `@PathVariable` / `@RequestParam` **必须显式写出参数名**。
> 原因：`_harness/build.sh` 用 javac 直调编译，未加 `-parameters`，Spring 无法通过反射取到
> 参数名，会抛 `IllegalArgumentException: Name for argument of type [...] not specified`。

## 四、编排层（Camunda BPMN）

### 4.1 流程定义

`Process_Jingfang_Diagnosis`（`ontology/Jingfang_Diagnosis.bpmn`）：**10 个 serviceTask**
↔ **10 个 job 类型**，**2 个网关**，**无 userTask**。

| # | 节点 ID | 名称 | job 类型 |
|---|---|---|---|
| ① | `Task_SymptomMapping` | 症状映射 | `symptom-mapping` |
| ② | `Task_InputSizhen` | 录入四诊信息 | `sizhen-input` |
| ③ | `Task_ConsistencyCheck` | 一致性检查 | `ontology-consistency-check` |
| ④ | `Task_Bagang` | 八纲分类 | `bagang-classification` |
| ⑤ | `Task_Liujing` | 六经分类 | `liujing-classification` |
| ⑥ | `Task_Fangzheng` | 方证分类 | `fangzheng-classification` |
| ⑦ | `Task_JianJiaZheng` | 兼夹证分类 | `jianjiazheng-classification` |
| ⑧ | `Task_Prescription` | 方剂药物推荐（母方） | `prescription-recommendation` |
| ⑨ | `Task_HerbModification` | 加减药（方后注派生） | `herb-modification` |
| ⑩ | `Task_Explanation` | 生成诊断解释 | `diagnosis-explanation` |

### 4.2 网关与结束事件

| 节点 | 条件 | 去向 |
|---|---|---|
| `Gateway_Consistent` | `=consistent = true` | → 八纲 |
| | `=consistent = false` | → `EndEvent_NoResult` |
| `Gateway_HasRecommendation` | `=fangzhengRealized = true` | → `EndEvent_Success` |
| | `=fangzhengRealized = false and fangzhengCandidates != null and fangzhengCandidates != []` | → `EndEvent_Candidates` |
| | `=fangzhengRealized = false and (fangzhengCandidates = null or fangzhengCandidates = [])` | → `EndEvent_NoResult`（default） |

### 4.3 全自动约束（BPMN 头注原文）

> 前端只负责「输入症状」与「展示结果 + 依据」，流程内部**不得出现任何人工任务（userTask）**，
> 必须由 JobWorker 一路跑到结束事件。一致性检查不通过 / 无方证推荐时，直接落到 `EndEvent_NoResult`。

> ⚠️ **实现现状**：`TCMDiagnosisService` 仍保留 `TASK_CONFIRM_SYMPTOMS` / `TASK_REVISE_SIZHEN`
> 常量与确认端点，但当前 BPMN **不产生任何 userTask**，属历史遗留（铁律 13）。

## 五、推理层

### 5.1 10 个 JobWorker

`TCMOntologyJobWorker` 中每个 `@JobWorker(type=..., autoComplete=false)` 方法**显式
complete / throwError**（异常时抛 BPMN error 而非静默成功）。

| job 类型 | 核心处理 | 错误码 |
|---|---|---|
| `symptom-mapping` | L1 检索 → L2 LLM 白名单映射 → L3 门控 | `SYMPTOM_MAPPING_FAILED` |
| `sizhen-input` | 建患者个体、断言四诊、检测互斥 | `SIZHEN_INPUT_FAILED` |
| `ontology-consistency-check` | 互斥索引判定 `conflicts` | `CONSISTENCY_FAILED` |
| `bagang-classification` | 阶段0 minibox → 八纲 + 阴阳消解 + 物化 | `BAGANG_FAILED` |
| `liujing-classification` | 阶段1 minibox → 六经 + 交叉积消解 + 合病标记 + 物化 | `LIUJING_FAILED` |
| `fangzheng-classification` | 阶段2 minibox → realize 命中 + 候选打分 + 双路径 | `FANGZHENG_FAILED` |
| `jianjiazheng-classification` | 兼夹证抽取 | `JIANJIAZHENG_FAILED` |
| `prescription-recommendation` | 母方 + 方后注加减 + 兼夹加味 + 禁忌 | `PRESCRIPTION_FAILED` |
| `herb-modification` | 与⑧共用 `computeHerbModification` | `HERB_MODIFICATION_FAILED` |
| `diagnosis-explanation` | 生成中文解释 + 清理缓存 | `EXPLANATION_FAILED` |

### 5.2 三阶段 minibox + 每步物化（核心机制）

> 铁律 37：真正的生产推理路径**不是** `SixChannelInferenceEngine`，而是 Worker 的
> 「模块抽取」。铁律 40：八纲/六经/方证**各用各的模块**。

| 阶段 | 方法 | 模块 seed |
|---|---|---|
| **阶段 0 · 八纲** | `extractBagangModule` | 患者症状 + 八纲类 + **判据层** + 顶层类 + ABox 个体类型 |
| **阶段 1 · 六经+兼夹** | `extractLiujingModule` | 患者症状 + **六经白名单** + 八纲类 + 兼夹证 + 顶层类 +（八纲未物化时才加判据层） |
| **阶段 2 · 方证** | `extractFangzhengModule` | 患者症状 + `filterFangzheng` 筛出的相关方证 + **物化八纲/六经** + 顶层类 |

公共步骤：`collectClassClosure` → `extractTBoxModule` → **`stripDisjointAxioms`**。

**每步物化**：

```
八纲阶段结束 → input.bagangTypes = 八纲fragments
             → input.panjuTypes  = 命中的判据fragments
             → miniCtxMgr.clearByPrefix(patientIri)
六经阶段结束 → input.liujingTypes = 六经fragments
             → miniCtxMgr.clearByPrefix(patientIri)
方证阶段     → 消费 input.bagangTypes + input.liujingTypes
```

物化使「上游结论」作为**固定值**进入下游模块 seed，下游无需重推上游，
既保证单向性（铁律 60），又显著缩小模块、缩短推理时间。

### 5.3 互斥公理剔除

`stripDisjointAxioms` 把 `owl:disjointWith` 从**分类推理模块**中剔除，
互斥关系只保留在「四诊互斥索引」中，用于：① 追问过滤；② 四诊参合矛盾检测。

> 铁律 64.4：互斥公理**不得**进入分类推理模块——一旦进入，矛盾四诊会让推理机
> 判定本体不一致而中断整条流程。

### 5.4 Openllet 调优

TBox 含约 366 条 `owl:equivalentClass` 充要定义，Openllet 的 CD 优化分类路径对其呈
**强非确定性耗时**（15s ~ 数小时，偶发挂起）→ Worker 启动卡死。
关闭 CD 分类 + 高级缓存后 precompute 中位数 **84.7s → 18.7s**（铁律 50）。

`tcm-all.owl` 导入 **20 个模块**：

| **SKOS** | `skos/zhengzhuang`（737 `skos:Concept`） |

### 6.2 TBox / ABox 分离（铁律 55、56）

- ABox 已从 TBox 入口移出，改由 `tcm-all-abox.owl` **单独加载**。
- 原因：`gettBoxOntology()` 合并所有已加载本体公理，ABox 混入使 Openllet 分类对每个类
  做 ABox 一致性检查，988 个体使 `CLASS_HIERARCHY` 达 345s。移出后 **345s → 47s**。
- **ABox 不能删，只能「搬家」**：诊断链路靠它查「症状个体 → 类」。
- `fangji-abox` / `yaowu-abox` 已迁入 MySQL。

> 本体的类/公理细节见 `本体顶层设计.md`。

| 措施 | 效果 |
|---|---|

## 十一、附：与初版蓝图（2026-09-05）的差异

| 维度 | 初版蓝图 | 当前实现 |
|---|---|---|
| 八纲定义 | `EquivalentTo: has_symptom some 腹满 and ...` 直接充要 | **判据层（Panju，38 个）** → 八纲，八纲为**原子类** |
| 六经定义 | 各经独立 `EquivalentTo` 列症状 | **六经 ≡ 病位 ⊓ 病性**，由判据传导 |
| 推理方式 | 一次性全本体分类出方证 | **三阶段专用 minibox + 每步物化** |
| 编排 | 未涉及 | **Camunda 8.9.6 BPMN**，10 个 JobWorker 全自动串跑 |
| 加减 | SWRL 规则（设想） | **`rules.owl` 方后注规则引擎**（46 方证 / 84 规则）+ 药证兜底 |
| 合病 | SWRL 推 `太阳阳明合病` 类型 | **注解 + 合病标记**（等价类会交叉推出 4 个六经） |
| 一致性检查 | 依赖 Openllet 判本体不一致 | **互斥索引**（互斥公理已剔出推理模块） |
| 症状输入 | 手工录入 OWL 个体断言 | **自然语言 → SKOS 词表 + LLM 白名单映射**（737 个体 / 1231 同义词） |
| 无结论时 | 未定义 | **三态结果 + 双路径**（路A 追问 / 路B 或然症候选） |
| ABox | 与 TBox 同文件 | **TBox/ABox 分离**（345s → 47s） |
| 性能 | 未涉及 | 关 CD 分类 + 高级缓存（84.7s → 18.7s） |
