# 塔架中段本体 — Openllet 推理适配与属性类型设计规范

> 目的：本体后续要用 **Openllet** 做自动推理与设计，属性类型必须按 **OWL 2 DL 的语义**来选，而不能按"文档记录"的习惯来选。
> 适用版本：v9.3 → v10.0 → v11.0 → … → **v15.8**（v14.0 起的变更详见《塔架中段设计本体.md》变更记录）
> 依据：W3C OWL 2 DL 规范、Openllet（Pellet 分支）支持范围、GB/T 19072-2022 / GB/T 42600-2023 / NB/T 10216-2019

---

## 一、先明确 Openllet 的能力边界

属性怎么建，取决于推理机能做什么。先把边界钉死：

| 能力 | Openllet | 对本体的影响 |
|------|----------|--------------|
| OWL 2 DL 推理（分类、一致性、实例化） | ✅ | 类与属性必须符合 DL 语法 |
| XSD 数据类型推理（integer / decimal 比较） | ✅ | **数值属性必须用数值类型，不能用 string** |
| `owl:inverseOf` | ✅ | 逆关系必须显式声明，才能双向查询 |
| `owl:FunctionalProperty` / `owl:InverseFunctionalProperty` | ✅ | 唯一值 / 唯一标识要声明 |
| `owl:hasKey`（OWL 2 键） | ✅ | 筒节编号等可作为身份键 |
| `owl:propertyChainAxiom`（属性链） | ✅ | 可推导组合关系 |
| `owl:AllDisjointClasses` | ✅ | 已使用，保留 |
| 基数限制（`owl:cardinality` / qualified） | ✅ | 做"必须有且仅有 1 个"的完整性校验 |
| SWRL（DL-safe + 部分 `swrlb:` 内置） | ⚠️ 部分支持 | 简单判断可用，**复杂计算不可靠** |
| 单位换算 | ❌ | 本体不管单位，必须全局统一 |
| 封闭世界假设（CWA） | ❌ | "缺值"检测只能靠基数限制或 SHACL |
| 数值公式计算（乘除、取整） | ❌ | 必须外置到 BPMN / 脚本 |

### 两条最容易踩的坑

**坑 1：`rdfs:domain` / `rdfs:range` 是推理规则，不是约束。**
写了 `:扶持位置 rdfs:domain :扶持`，任何带该属性的个体都会被**推断**为 `:扶持`。这通常是想要的（也是分类的依据），但要清楚它会带来推断——如果 domain 写错，错误会沿着推理链扩散。

**坑 2：`rdfs:comment` 里的"≥650mm"对 Openllet 完全无效。**
约束必须写成 `owl:Restriction`。当前本体把大量约束（≥650、>100、=1250）写在注释里，属性既当"值"又当"约束"，推理机无法据此做任何校验。

### 核心原则

> **属性承载"实例值"，约束用公理表达。**
> 一个属性要么是"某个体测得的值"，要么是"某类必须满足的范围"，两者不能混在同一个属性上。

## 二、属性类型选择总原则（决策顺序）

1. **能独立存在、可被标识的物理对象** → `owl:Class`
2. **是"某类东西的一种"** → `rdfs:subClassOf`（**不要**用 string 数据属性表达分类）
3. **指向另一个对象** → `owl:ObjectProperty`
4. **数值 / 布尔 / 日期** → `owl:DatatypeProperty` + 正确的 XSD 类型
5. **取值范围约束** → `owl:Restriction` + `owl:withRestrictions`
6. **计算得到的值** → SWRL 或外部计算后写回
7. **单位** → 全局统一，用注释属性标注

### 3.3 类层次的推理隐患（与属性类型强相关）

| 类 | 当前公理 | 问题 | 建议 |
|----|----------|------|------|
| `:塔架` | `subClassOf :风机` | 会推断"塔架是风机"，且与注释"塔架由塔架段组成"自相矛盾 | 独立顶层类，用 `:有塔架` 组成 |

## 四、推荐的目标属性体系

### 4.1 约束公理示例（把 comment 变成公理）

```xml
<!-- 平台宽度 ≥ 650mm -->
<owl:Class rdf:about="#Platform">
    <rdfs:subClassOf>
        <owl:Restriction>
            <owl:onProperty rdf:resource="#platformWidth"/>
            <owl:onDataRange>
                <rdfs:Datatype>
                    <owl:onDatatype rdf:resource="http://www.w3.org/2001/XMLSchema#integer"/>
                    <owl:withRestrictions rdf:parseType="Collection">
                        <rdf:Description>
                            <xsd:minInclusive rdf:datatype="http://www.w3.org/2001/XMLSchema#integer">650</xsd:minInclusive>
                        </rdf:Description>
                    </owl:withRestrictions>
                </rdfs:Datatype>
            </owl:onDataRange>
        </owl:Restriction>
    </rdfs:subClassOf>
</owl:Class>
```

### 4.2 基数限制示例（完整性校验）

```xml
<!-- 塔架中段必须有且仅有 1 个塔筒 -->
<owl:Class rdf:about="#TowerMidSection">
    <rdfs:subClassOf>
        <owl:Restriction>
            <owl:onProperty rdf:resource="#hasTowerTube"/>
            <owl:qualifiedCardinality
                rdf:datatype="http://www.w3.org/2001/XMLSchema#nonNegativeInteger">1</owl:qualifiedCardinality>
            <owl:onClass rdf:resource="#TowerTube"/>
        </owl:Restriction>
    </rdfs:subClassOf>
</owl:Class>
```

### 4.3 逆属性示例

```xml
<owl:ObjectProperty rdf:about="#hasTowerTube">
    <owl:inverseOf rdf:resource="#belongsToTowerMidSection"/>
    <rdfs:domain rdf:resource="#TowerMidSection"/>
    <rdfs:range rdf:resource="#TowerTube"/>
    <rdfs:label xml:lang="zh">有塔筒</rdfs:label>
</owl:ObjectProperty>

<owl:ObjectProperty rdf:about="#belongsToTowerMidSection">
    <rdfs:label xml:lang="zh">属于塔架中段</rdfs:label>
</owl:ObjectProperty>
```

### 4.4 键（身份识别）

```xml
<owl:Class rdf:about="#TubeSection">
    <owl:hasKey rdf:parseType="Collection">
        <owl:DatatypeProperty rdf:about="#tubeSectionNumber"/>
    </owl:hasKey>
</owl:Class>
```

### 4.5 属性链（推导组合关系）

```xml
<!-- 塔架中段 有附件 ?a，?a 固定在塔筒 ?t  ⇒  该附件所在塔筒 -->
<owl:ObjectProperty rdf:about="#hasAccessoryOnTube">
    <owl:propertyChainAxiom rdf:parseType="Collection">
        <owl:ObjectProperty rdf:about="#hasAccessory"/>
        <owl:ObjectProperty rdf:about="#attachedToTowerTube"/>
    </owl:propertyChainAxiom>
</owl:ObjectProperty>
```

### 4.6 枚举型属性的正确做法

`:升降机类型`、`:机型`、`:区域` 这类"分类值"，三种做法按优先级：

1. **类层次**（最优）：`:钢绳导向升降机` / `:爬梯导向升降机` 已是子类，类型由类成员身份承载 → 删除 `:升降机类型`
2. **对象属性 + 个体**：`:机型` 改为对象属性，指向 `:机型` 类的个体（如 `:GW155-5MW`）→ 可推理"同机型"
3. **数据范围枚举**（次选）：`owl:oneOf` 限定取值集合

**不要**用 `xsd:string` 承载分类值——它既不能参与推理，也无法与类层次做一致性校验。

## 五、支撑"自动设计"的推理路径

必须分清：**Openllet 负责"分类 + 校验"，计算负责"设计生成"。**

| 设计环节 | 能否用 Openllet 完成 | 实现方式 |
|----------|---------------------|----------|
| 分类（判断个体是钢绳导向还是爬梯导向升降机） | ✅ | 类层次 + 属性推断 |
| 一致性校验（附件距焊缝 > 100、平台宽 ≥ 650） | ✅ | Restriction + SWRL |
| 完整性校验（缺值检测） | ✅（有限） | 基数限制 |
| 同机型 / 同区域匹配 | ✅ | 对象属性 + 个体 |
| 数值计算（扶持位置 =(筒高−1250)/2） | ❌ | 外置到 BPMN / 脚本，结果写回本体 |
| 筒节划分、附件排布、灯位排布 | ❌ | 外置 |

> 结论：把"算"的部分留在 BPMN / 脚本，把"判"的部分交给 Openllet。本体只承载**结果值 + 约束公理**。

## 六、改造优先级

### P0 — 不改会导致推理出错
1. 删除 `:升降机类型`（与子类冗余，矛盾无法发现）
2. `:焊缝位置` 由 string 改为数值
3. 补齐 `owl:inverseOf`（文档已声明、OWL 缺失）
4. 删除 `:塔架尺寸` 冗余 string 属性
5. 修正 `:塔架 subClassOf :风机`、`:灯 subClassOf :照明系统`

### P1 — 推理能力缺失
6. 约束由 comment 改为 `owl:Restriction`
7. 区间属性拆 min/max（栏杆高度、踏级间距、附件中心间距、第一灯安装高度、倒数第二附件到平台）
8. `:机型` / `:区域` 改为对象属性
9. 补齐缺失对象关系（偏航轴承、爬梯导向、线槽灯、平台/螺柱/线槽固定）

### P2 — 增强
10. 基数限制、`owl:hasKey`、`owl:propertyChainAxiom`
11. 单位全局统一（建议长度统一 mm）
12. 明确 `:塔架中段` 段级尺寸与 `:塔筒` 筒体级尺寸的分工

**关于"区间属性是否拆分"的最终结论（对本文档 3.1 节 P1-7 的修正）**：

并非所有区间都要拆成两个属性，需区分两类：

- **实际存在两个值** → 拆分。例：`:壁厚最小值` / `:壁厚最大值`——塔架沿高度壁厚不同，是真实的两端值。
- **单一实际值 + 允许范围** → **不拆分**，用 `owl:Restriction` 表达。例：`:栏杆高度`（实际只有一个值，900~1100 是允许范围）、`:踏级间距`、`:第一灯安装高度`。

v10.0 采用此原则：仅壁厚拆分，其余区间改为 restriction。

## 十、v11.2 补充（遗留项确认）

### 10.1 塔架顶法兰归属 `:搭建顶段`

| 项 | 变更 |
|----|------|
| 属性 | `:固定在塔架`（`yawBearingAttachedToTower`） |
| 值域 | `:塔架` → **`:搭建顶段`**（收窄） |
| 依据 | 塔架顶法兰位于 `:搭建顶段`，偏航轴承外圈固定在顶法兰上 |

**对推理的影响**：

- 收窄前：`:偏航轴承 —:固定在塔架→ :塔架`，推理机只能知道"固定在某个塔架"。

- 这是"值域收窄 = 增强一致性校验能力"的典型用法：domain/range 在 OWL 2 DL 中虽为推理规则而非硬约束，但配合 Openllet 的**一致性检查**，指向错误类型的个体会被标记为 unsatisfiable/不一致。

| 项 | 说明 |
|----|------|

- `:托架长度` / `:托架右弦长` / `:托架左弦长` 域由 `:电缆托架规格` **改挂 `:电缆托架`**。

> **取舍**：原设计（v11.0）用规格类 + 对象属性，便于 Openllet 推断「两个机型共用同一规格个体」。v15.8 依业务决策改为直挂，因为托架尺寸随设计计算写入，不再需要「规格个体」这一中间层。
