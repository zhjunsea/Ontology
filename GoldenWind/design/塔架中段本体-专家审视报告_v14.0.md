## 一、P0 — 必须修正

### P0-1　`:塔架` 并非"抽象父类"，注释与事实矛盾

**现象**（本体 L1065-1075、L1602-1619）：

```xml
<owl:Class rdf:about="#Tower">
    <rdfs:comment>塔架，独立顶层类。…v14.0 保留为抽象父类</rdfs:comment>
</owl:Class>
<owl:Class rdf:about="#TowerSection">
    <rdfs:comment>塔架分段，塔架由塔架段组成（组成关系，非继承关系）</rdfs:comment>
</owl:Class>
```

`Tower` 与 `TowerSection` **同时出现在同一组 `owl:AllDisjointClasses` 中**（L1605-1606），且 `TowerSection` 没有 `rdfs:subClassOf #Tower`。因此：

- `:塔架中段 ⊂ :塔架段` 成立；
- `:塔架段 ⊄ :塔架`，`:塔架中段 ⊄ :塔架`。

**结论**：`:塔架` 目前**不是任何类的父类**，注释"保留为抽象父类"与事实不符；它唯一的联系是 `:有塔架段`（L20-26）。

**建议**（二选一）：

- **方案 A（推荐，若需保留"塔架"概念）**：让 `:塔架段 ⊂ :塔架`，并把 `:塔架段` 从该组不相交声明中移除（子类不能与父类不相交）。这样 `:塔架中段 ⊂ :塔架段 ⊂ :塔架` 成为真正的抽象层次。
- **方案 B（若严格按"中段范围"裁剪）**：删除 `:塔架` 与 `:有塔架段`/`:塔架段属于`，`:塔架段` 直接作为顶层抽象类。

### P0-2　`:螺柱` 与 `:线槽` 归入 `:附件`，继承了错误的排布约束

**现象**（本体 L1437-1476、L1497-1507）：

`:附件` 上挂了 `:附件中心间距` 的约束公理：

```xml
<owl:Restriction>
    <owl:onProperty rdf:resource="#accessoryCenterSpacing"/>
    <owl:allValuesFrom>… 1680 ~ 1960 …</owl:allValuesFrom>
</owl:Restriction>
```

而 `:螺柱 ⊂ :附件`、`:线槽 ⊂ :附件`。

**依据**：

- 流程 5.2：附件中心间距 **≤280×7、≥280×6（1680~1960mm）**，其"附件"在 5.1 明确为 **"爬梯支撑 + 电缆托架（两者平齐）"**；
- 流程 5.5：**螺柱间距 = 500mm**（与 1680~1960 相差一个数量级）；
- 老工具 `infoformat.py:181`：`爬梯支撑定位点 = L_LADDER/280`（按 280 排布的是爬梯支撑，不含螺柱）；
- 老工具 `infoW.py:584`：`L_C_I = 16200`（线槽是**连续纵向构件**，非点状排布件）；
- 流程 5.6：**线槽灯**豁免焊缝距离约束，说明线槽本体也穿越焊缝区，不应受"与焊缝上下距离 >100mm"约束。

**结论**：`:螺柱`、`:线槽` 不属于"附件排布清单"，把它们放在 `:附件` 下会让 `:有附件`（≥1）、`:附件中心间距`、`:附件到焊缝距离`、`:相对于环焊缝位置` 的适用范围被错误放大，下游推理/排布程序若遍历 `:有附件` 取值会误纳入螺柱与线槽。

**建议**（推荐方案 B）：

- **方案 A**：把 `:螺柱`、`:线槽` 移出 `:附件`，另立 `:构件`（Component）顶层类。
- **方案 B（改动更小）**：新增 `:排布附件`（LayoutAccessory）子类，把 `:附件中心间距`、`:附件到焊缝距离` 两条约束**从 `:附件` 下移到 `:排布附件`**；`:爬梯支撑`/`:电缆托架`/`:电缆线夹`/`:安全锚点`/`:扶持` 归入 `:排布附件`，`:螺柱`/`:线槽` 留在 `:附件`。这样既保留"都是附件"的语义，又让排布约束只作用于清单内的件。

### P0-3　`:是否隔开电缆线夹` 取值自相矛盾，且无实现依据

**现象**：

- 本体 L1058 注释：**"国内一般隔开，国外不隔开"**；
- 设计文档 `塔架中段设计本体.md:234`：**"国内 true / 国外 false"**；
- 设计文档 `塔架中段设计本体.md:596` 示例：`:区域_中国 :是否隔开电缆线夹 "false"^^xsd:boolean`。

**依据**：老工具全量检索（`grep 隔开|separate|is_sep`）**无任何对应实现**——该属性是 v11.0 新增，无老工具或流程文档出处。

**结论**：注释说"国内 = 隔开（true）"，示例却给中国 `false`，二者矛盾；且该属性的业务依据缺失。

**建议**：确认"隔开"的准确定义与国内/国外取值，统一注释与示例；若业务上无法确认，建议标注为"待业务确认"并暂不赋示例值。

### P0-4　逆属性约定与实现不符

**现象**：v13.0 确立的约定为（本体 L11、设计文档 L434）：

> **仅组成关系（`:有X`）建逆属性**；固定/安装/连接/位置/映射类关系**不建**逆属性。

但实际存在两条非组成关系的逆属性：

| 属性 | 类别 | 逆属性 | 位置 |
|---|---|---|---|
| `:平台到筒顶` | 位置关系 | `:筒顶定位平台` | L256-267 |
| `:与…平齐` | 位置关系 | `:平齐于` | L307-320 |

**结论**：约定与实现不一致。这两条逆属性**本身有实用价值**（`:筒顶定位平台` 支持反向查询；`:与…平齐` 是 Functional + InverseFunctional，逆属性有语义），因此**问题在约定表述，不在实现**。

**建议**：把约定修正为——"仅**组成关系**与**双向定位/平齐关系**建逆属性；固定/安装/连接/映射类关系不建逆属性"。这样约定与实现自洽，无需改动本体。

## 二、P1 — 建议修正

### P1-1　`:直径`（塔筒）与锥段几何矛盾

**现象**：`:塔筒` 只有单值 `:直径`（L548-554，`xsd:integer`），而 `:塔架中段` 有 `:外径底部` / `:外径顶部`（L507-521）。

**依据**：

- 流程"输入条件"明确塔架尺寸含 **dbottom（外径）、dtop（外径）** 两个值；
- 老工具 `tool.py:diCal(h, n)` 按高度**插值**内径，`infoformat.py:156`：`α=atan((DA_BOTTOM-DA_TOP)/2/SEC_H_TOTAL)` —— 说明中段是**锥段**，直径沿高度线性变化。

**结论**：单值 `:直径` 无法表达锥度，且与 `:外径底部`/`:外径顶部` 语义重叠。

**建议**：删除 `:直径`，统一由 `:外径底部`/`:外径顶部`（段级）+ `:筒节内径`（筒节级）承载；或把 `:直径` 明确为"名义直径/平均直径"并写入注释。

### P1-2　`:环焊缝 :连接筒节` 基数应为 =2

**现象**：L1143-1149 用 `minQualifiedCardinality = 2`。

**依据**：环焊缝是**两个相邻筒节之间**的对接焊缝，恰好连接 2 个筒节（老工具 `infoW.py:280-282` 电缆夹板/焊缝定位均以"上法兰/筒节"为界）。

**建议**：改为 `owl:qualifiedCardinality = 2`（精确基数），比 `≥2` 更贴合物理事实。

### P1-3　`:电缆托架规格` 缺 `owl:hasKey`

**现象**：`:电缆托架规格`（L1560-1563）无 `owl:hasKey`，而同类分类值类 `:机型`/`:区域`/`:材料`/`:附件连接方式`/`:灯类型`/`:配件类型` **全部**有 `hasKey`。

**结论**：分类值类的一致性缺口——无身份键则无法做"两个机型是否共用同一规格个体"的等价推理（而这正是 v11.0 引入该类的目的）。

**建议**：补 `owl:hasKey`（如 `:托架长度` + `:托架右弦长` + `:托架左弦长`，或新增 `:规格名称`）。

### P1-4　可用 DL 表达却缺失的约束

| 属性 | 流程依据 | 建议约束 |
|---|---|---|
| `:第一附件到底部` | 流程 5.3：**980mm** | `owl:hasValue 980` |
| `:最后电缆托架到平台` | 流程 5.3：**距平台 200mm** | `owl:hasValue 200` |
| `:倒数第二附件到平台` | 流程 5.3：**5×280~7×280（1400~1960）** | `allValuesFrom [1400,1960]` |

**说明**：设计文档 L414 把 `:倒数第二附件到平台` 列为"无法用 DL 表达"，但该属性承载的是**单值区间**（1400~1960），完全可用 `owl:allValuesFrom` 表达；真正无法表达的是"相邻两附件之间的实际中心距"（跨个体比较，需 SWRL 9.3）。建议更正该判断并补上三条约束。

### P1-5　命名歧义

| 属性 | 问题 | 建议 |
|---|---|---|
| `:壁厚最小值` / `:壁厚最大值` | `Min`/`Max` 易被读作"区间上下限"，实为**顶部值/底部值**（注释已澄清，但命名仍误导） | 改名 `:壁厚顶部` / `:壁厚底部` |
| `:螺柱间距`（=500）vs `:灯上螺柱最小/最大间距`（5000/10000） | 二者都叫"螺柱间距"，实际前者是**同一灯上相邻螺柱间距**，后者是**相邻灯（螺柱组）间距** | 改名 `:灯上螺柱间距` / `:灯与灯间距` |

### P1-6　`:标高下` / `:标高上` 注释与定义域不符

**现象**：L496、L504 注释写作"**塔架**底部标高 / **塔架**顶部标高"，但定义域是 `:塔架中段`。

**建议**：注释改为"塔架**中段**底部/顶部标高"。

### P1-7　扶持位置公式：流程 1250 vs 老工具 1200

**现象**：

- 流程 9.1：扶持位置 = **(中段筒高 − 1250) ÷ 2**；
- 老工具 `infoW.py:507`：`SUPPORT2FL = secNLength()[n] / 2 - 1200`（注释"扶持位置，至下法兰下端面"），`infoW.py:608` 注释"此高度扶持在上下平台的中间"。

**结论**：两个公式不等价（若 H=25000，流程得 11875，老工具得 11300），且常数 1250 与 1200 不一致。本体采用 1250（依流程文档，v11.1 用户已确认），但**与老工具实现冲突**。

**建议**：确认以哪个为准，并核对"扶持位置"的基准面（筒底 / 下法兰下端面 / 上下平台中点）——这直接影响 `:扶持位置` 的取值正确性。

## 三、P2 — 约束值依据待补

以下 8 条约束公理在 **《塔架中段设计流程》文档、老工具代码、v9.3 报告的标准清单**中均**找不到对应条款**，目前仅存在于本体与本体说明文档：

| 约束 | 值 | 位置 |
|---|---|---|
| `:平台宽度` | ≥ 650mm | L1163-1178 |
| `:平台集中荷载` | ≥ 1500N | L1179-1194 |
| `:栏杆高度` | 900~1100mm | L1195-1213 |
| `:踢脚板高度` | ≥ 150mm | L1214-1229 |
| `:踏级间距` | 250~300mm | L1236-1254 |
| `:踏面宽度` | ≥ 80mm | L1255-1270 |
| `:爬梯净宽` | ≥ 340mm | L1271-1286 |
| `:爬梯与塔壁净距` | ≥ 150mm | L1287-1302 |

**说明**：v9.3 报告把 `GB/T 17888.4-2020《固定式直梯》`、`GB/T 17889.2《梯子》` 列为"爬梯尺寸"依据，但**未落到具体条款**；平台类约束（宽度/荷载/栏杆/踢脚板）连标准名都未列出。老工具中亦无这些量的任何实现（`grep 栏杆|踢脚|踏级|踏面|净宽|1500|650` 无结果）。

**建议**：为每条约束补注**标准号 + 条款号**（或金风内部设计规范编号），写入 `:来源` 注释属性。若某值确无出处，应删除该公理而非保留"看起来合理"的数字——这正是"不能瞎编"的要求。

## 四、确认无误的部分（合理之处）

1. **类层次**：`:塔架中段 ⊂ :塔架段`；`:钢绳导向升降机`/`:爬梯导向升降机 ⊂ :升降机`；`:焊接灯`/`:线槽灯 ⊂ :灯`；7 个 `:附件` 子类 —— 与流程 9 步涉及的对象一一对应。
2. **组成关系与逆属性**：`:有塔筒`/`:有筒节`/`:有环焊缝`/`:有平台`/`:有爬梯`/`:有升降机`/`:有照明系统`/`:有灯`/`:有附件`/`:有扶持`/`:有法兰`/`:有材料` 等均一一配对，无复用。
3. **匹配链覆盖**：流程步骤 2 的 6 个匹配维度（平台所在处内径 → 筒节 → 高度 → 直径 → 附件连接方式 → 机型及升降机类型）均有属性承载（`:平台所在处内径`、`:筒节编号/高度/内径`、`:高度`、`:直径`、`:有连接方式`、`:有机型`）。
4. **与流程一致的关键约束**：`:平台到筒顶距离 = 1250`（步骤4）、`:附件到焊缝距离 > 100`（5.1）、`:附件中心间距 1680~1960`（5.2）、`:第一灯安装高度 2600~3000`（5.4）、`:灯上螺柱间距 5000~10000` + `:螺柱间距 = 500`（5.5）、`:灯螺柱到焊缝距离 > 100`（5.6）—— 全部有流程原文出处。
5. **`:第一附件到底部`**：老工具 `infoformat.py:158` `第一个电缆夹板相对于爬梯底段距离 = 980*cos(α)`、`infoformat.py:134` `$H1_S = -980*cos(Alpha)` —— 与流程 5.3 的 980mm 一致。
6. **`:电缆托架规格` 三参数**：老工具 `infoW.py:462-463` `L_CABLE`（V17=800、V19=560）、`L1_CABLE_I`/`L2_CABLE_I`（650）—— 与 `:托架长度`/`:托架右弦长`/`:托架左弦长` 一致，且"随机型变化"成立。
7. **分类值 + hasKey 模式**：`:机型`/`:区域`/`:材料`/`:附件连接方式`/`:灯类型`/`:配件类型` 用"对象属性 + 个体 + hasKey"，比 string 数据属性更利于"同机型/同区域"推理 —— 方向正确。
8. **`:线槽灯` 豁免焊缝约束**：`:焊接灯` 有 `:灯螺柱到焊缝距离 > 100` 约束，`:线槽灯` 无 —— 与流程 5.6 一致。
9. **`:爬梯导向升降机 :有扶持 = 0`**：与流程"爬梯导向不需要扶持"一致。
