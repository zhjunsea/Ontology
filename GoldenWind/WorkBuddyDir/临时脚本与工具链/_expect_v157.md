# 塔架中段 — 本体对象模型

> 基于《塔架中段设计流程》构建，用于结构化表达物理对象及其关系。
> 设计原则：**真实存在的物理对象定义为类，其余定义为属性**；**属性承载实例值，约束用 owl:Restriction 表达**。
> 设计步骤（机型及升降机类型→附件的连接方式→直径→高度→筒节→平台所在处内径）放到 BPMN 中，不在本体中出现。
> **下游用途：Openllet 自动推理与设计**，故属性类型按 OWL 2 DL 语义选择。

## 一、本体概览

### 命名空间

| 前缀 | URI |
|------|-----|
| `:` | `http://goldwind.com/ontology/tower-mid-section#` |
| `rdfs:` | `http://www.w3.org/2000/01/rdf-schema#` |
| `owl:` | `http://www.w3.org/2002/07/owl#` |
| `xsd:` | `http://www.w3.org/2001/XMLSchema#` |

### 设计原则

- **父子关系（rdfs:subClassOf）**：表示"是一种"的关系
- **组成关系（对象属性）**：表示"有"的关系
- **约束（owl:Restriction）**：表示"必须满足的范围"，不写在注释里
- **分类值**：用类层次或对象属性指向个体，不用 `xsd:string`

### 单位约定

| 类别 | 单位 | 说明 |
|------|------|------|
| 构件尺寸 | **mm** | 外径/内径、壁厚、高度、间距、位置等，全局统一 |
| 场地标高 | **m** | `:标高下` / `:标高上`，不与构件尺寸比较 |

> Openllet **不做单位换算**，混用单位会让跨属性比较（如"梯子高度 = 筒高"）直接失效。

> **为什么 `:塔架`/`:灯` 为独立顶层类**：按"父子关系表示**是一种**"的原则，"塔架是一种风机""灯是一种照明系统"均不成立，它们是**组成**关系。v9.2 已对机头做过同样修正，v10.0 补齐一致性。
> **v15.6 层级扁平化**：删除中间类 `:塔架段`，`:塔架中段` **直接作为 `:塔架` 的子类**（`:塔架中段 ⊂ :塔架`）；塔架"由"塔架中段组成（对象属性 `:有塔架中段`）。原 v15.0 的 `:塔架段 ⊂ :塔架` 中间层已取消。
> **v15.0 附件边界（P0-2）**：业务确认「附件不包括螺柱，也不包括线槽」，故新增顶层类 `:构件`，`:螺柱`/`:线槽` 由 `:附件` 子类改挂 `:构件` 子类；新增对象属性 `:有构件`/`:构件属于`，`:固定在塔筒` 定义域扩为 `:附件 ∪ :构件 ∪ :平台`。
> **v15.1 附件边界再扩（业务确认）**：`:扶持` **不算附件**（其属性 `:扶持位置` 与附件不同），由 `:附件` 改挂 `:构件`；扶持不再继承 `:附件到焊缝距离` / `:附件中心间距`，**仅保留焊缝距离约束**——单建数据属性 `:扶持到焊缝距离`（>100），不参与附件中心间距排布。
> **v14.0 裁剪**：本本体仅服务于「塔架中段定制化设计流程」，`:风机`、`:风机机头`、`:偏航轴承`、`:塔架底段`、`:塔架顶段` 与该流程无关，已整体删除；`:塔架` 作为**抽象父类**保留（v15.6 起 `:塔架中段 ⊂ :塔架`），`:有机型`/`:有区域` 由 `:风机` 改挂至 `:塔架中段`。

## 九、SWRL 规则示例

### 9.1 附件间距约束（相对约束，DL 无法表达）

```swrl
(?a :附件到焊缝距离 ?d) ∧ swrlb:lessThanOrEqual(?d, 100)
  → (?a :约束违反 "附件与焊缝距离不足")
```

### 9.2 梯子高度与筒高一致

```swrl
(:塔架中段 ?m) ∧ (:有塔筒 ?m ?t) ∧ (:高度 ?t ?h)
  ∧ (:有爬梯 ?m ?l) ∧ (:梯子高度 ?l ?lh) ∧ swrlb:notEqual(?h, ?lh)
  → (?l :约束违反 "梯子高度与筒高不一致")
```

### 9.3 相邻附件实际间距校验（v11.0 新增，v12.0 阈值修正）

> DL 只能校验单值区间（1680~1960mm），"相邻两附件之间的实际中心距"需跨个体比较，须用 SWRL。

```swrl
(:附件 ?a) ∧ (:附件 ?b) ∧ swrlb:notEqual(?a, ?b)
  ∧ (:支撑位置 ?a ?pa) ∧ (:支撑位置 ?b ?pb)
  ∧ swrlb:subtract(?d, ?pa, ?pb) ∧ swrlb:greaterThan(?d, 0)
  ∧ swrlb:lessThan(?d, 1680)
  → (?a :约束违反 "相邻附件中心距小于 6×280mm")
```

### 9.4 爬梯支撑与电缆托架平齐校验（v12.0 新增）

> 流程 5.1：这两个附件是平齐的。DL 无法表达"两个数据属性值相等"，须用 SWRL。

```swrl
(:爬梯支撑 ?s) ∧ (:电缆托架 ?b) ∧ (:平齐 ?s ?b)
  ∧ (:支撑位置 ?s ?ps) ∧ (:托架位置 ?b ?pb)
  ∧ swrlb:notEqual(?ps, ?pb)
  → (?s :约束违反 "爬梯支撑与电缆托架不平齐")
```

### 9.5 灯类型推导（v12.0 新增）

> 流程 5.4：灯的类型由「机型 + 区域」确定。属规则推导，可用 SWRL 或外置规则表。

```swrl
(:塔架中段 ?m) ∧ (:有灯 ?m ?l)
  ∧ (:有机型 ?m ?model) ∧ (:有区域 ?m ?region)
  ∧ (:灯类型表 ?model ?region ?lt)
  → (:有灯类型 ?l ?lt)
```

> `:灯类型表` 为外置映射表（机型 × 区域 → 灯类型），本体不臆造具体取值。

## 十一、Openllet 推理适配说明

### 11.1 推理机能做什么

| 用途 | 实现方式 |
|------|----------|
| 分类（判断个体是钢绳导向还是爬梯导向升降机） | 类层次 + `:有扶持` / `:以爬梯为导向` 属性推断 |
| 一致性校验（附件距焊缝 >100、附件中心间距 1680~1960、第一附件到底部=980、最后电缆托架到平台=200） | `owl:Restriction` |
| 完整性校验（缺值检测） | `owl:qualifiedCardinality` |
| 同机型 / 同区域匹配 | `:有机型` / `:有区域` 对象属性 + 个体 |
| **连接方式匹配**（匹配链第 3 环） | `:有连接方式` → `:附件连接方式`（粘贴式/焊接式个体） |
| **附件类型联动**（步骤 8.1 替换附件类型） | `:选用附件类型` → `:附件类型` |
| **灯类型推导**（机型+区域 → 灯类型） | `:有灯类型` + SWRL 规则 9.5 |
| 规格联动（机型 → 电缆托架规格 → 托架尺寸） | `:有电缆托架规格` 对象属性链 |
| 构件归属查询（法兰/附件等属于哪个塔筒） | `:有法兰` / `:固定在塔筒`（v13.0 合并后统一）+ `owl:inverseOf`（v15.6 删除 `:有材料` / `:有安全锚点`） |
| 平台定位查询（某平台相对哪个塔筒顶端定位） | `:平台到筒顶` / `:筒顶定位平台`（对象属性）+ `owl:inverseOf` |

| 身份识别 | `owl:hasKey`（**6 组**，v15.0 新增 `:电缆托架规格`；v15.6 删除 `:附件类型` / `:材料`） |

### 11.2 推理机不能做什么（必须外置到 BPMN / 脚本）

| 事项 | 原因 |
|------|------|
| 扶持位置 =(筒高−1250)÷2 | DL 不支持数值公式计算 |
| 筒节划分、附件排布、灯位排布 | 属设计生成，非逻辑推理 |
| 相邻附件实际中心距校验 | 需跨个体比较，DL 无法表达（单值区间已入公理，实际间距须 SWRL 9.3） |
| 单位换算 / 单位校验 | Openllet 不处理单位；v13.0 仍未引入单位个体（可选增强） |
| 爬梯支撑与电缆托架平齐（等高）校验 | 跨属性相等，须 SWRL 9.4 |
| 平台所在处内径（锥段插值） | 数值计算 |
| 单位换算 | Openllet 不处理单位 |
| 封闭世界下的"缺值"完备检测 | OWA 假设，仅能用基数限制近似 |

> **结论：Openllet 负责"分类 + 校验"，计算负责"设计生成"。** 计算完成后把结果值写回本体，再由推理机校验一致性。
