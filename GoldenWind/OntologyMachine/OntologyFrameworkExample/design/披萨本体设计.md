## 1. 概述与范围

披萨本体是 Pizza 应用的**业务真相来源**：用 OWL 表达「披萨类别 → 组件构成/取值范围/工艺步骤」的约束，由 Openllet 在运行时推理判定，程序不硬编码业务规则。本体按 **TBox / ABox / SKOS 术语 / 映射** 四类资产组织：

| 资产类别 | 文件 | 作用 |
|---|---|---|
| TBox | `pizza.owl`（core）、`pizza-components.owl`、`pizza-components-rules.owl`、`pizza-processes.owl` | 定义类、属性、约束、SWRL 规则 |
| ABox | `pizza-abox.owl`、`pizza-components-abox.owl`、`pizza-processes-abox.owl` | 静态示例个体（披萨实例、组件实例、工序实例） |
| 总入口 | `pizza-all.owl` | 一次性 import 全部模块 |
| 术语 | `pizza-terminology.ttl` | SKOS 中英术语（概念/定义/上下位） |
| 解析目录 | `catalog-v001.xml` | 本体 IRI → 本地文件映射（离线解析） |
| 运行数据 | `ontology/database/*` | MySQL 表 + OBDA 映射，经 Ontop 虚拟访问 |

> **两套实例来源并存**：静态 ABox（`.owl`）用于本体推理/一致性/SKOS 交叉校验；运行态数据来自 MySQL（经 OBDA 映射），二者个体命名约定不同（见 §8.3）。

## 3. TBox 设计

### 3.1 `pizza.owl`（core）—— 披萨类别体系

**顶层类 `Pizza`**：
- 约束：`hasCrust` **基数 = 1**（qualifiedCardinality，onClass `Crust`）。
- 等价类：`Pizza ≡ TomatoBasedPizza ⊔ WhitePizza ⊔ MarinaraPizza ⊔ NoSaucePizza`。

**酱汁分类（抽象，`SauceCategoryPizza` 之下）**：

| 类 | 约束 | 备注 |
|---|---|---|
| `SauceCategoryPizza` | `⊑ Pizza` | 抽象类，不挂个体 |
| `TomatoBasedPizza` | `hasSauce someValuesFrom TomatoSauce`；`hasCheese someValuesFrom Cheese` | 抽象 |
| `WhitePizza` | `hasSauce someValuesFrom WhiteSauce`；`hasSauce allValuesFrom ¬TomatoSauce`；`hasCheese someValuesFrom Cheese` | 抽象 |
| `MarinaraPizza` | `hasSauce someValuesFrom TomatoSauce`；`hasCheese` **基数 = 0** | 叶子类（可挂个体） |
| `NoSaucePizza` | `hasSauce` **基数 = 0** | 叶子类 |

- 互斥声明：`AllDisjointClasses( TomatoBasedPizza, WhitePizza, NoSaucePizza )`——**`MarinaraPizza` 不参与互斥**（源码注释明示：MarinaraPizza 是 SauceCategoryPizza 直接子类，不再与 TomatoBasedPizza 互斥）。

**地域分类（抽象，`RegionalStylePizza` 之下）**：

| 类 | 约束/说明 |
|---|---|
| `RegionalStylePizza` | `⊑ Pizza`，抽象 |
| `ItalianTraditionalPizza` | `hasCrust=1`；`hasSauce=1`；`hasCheese=1`；`hasTopping min≥1` |
| `AmericanPizza` | 抽象 |
| `ChineseStylePizza` | 抽象 |
| `OtherGlobalPizza` | 抽象 |

**风味/食材分类**：`FlavorBasedPizza ⊑ Pizza`（抽象，与地域维度正交）。

**具体披萨类（叶子/抽象）**：

| 类 | 父类 | 关键约束 |
|---|---|---|
| `NeapolitanPizza` | `ItalianTraditionalPizza` + `TomatoBasedPizza` | `hasCrust someValuesFrom NeapolitanCrust`；`hasSauce someValuesFrom NeapolitanTomatoSauce`；`hasCheese someValuesFrom BuffaloMozzarella`；**9 个 `hasProcessStep hasValue <Task_*>`**（见 §3.5）。源码标注「抽象类，不挂个体」 |
| `MargheritaPizza` | `NeapolitanPizza` | `hasTopping` **基数 = 1**；`hasTopping hasValue <components-abox/Basil>` |
| `GenericNeapolitanPizza` | `NeapolitanPizza` | 叶子类，用于挂实例 |
| `ChicagoDeepDishPizza` | `AmericanPizza` | `stackingOrder hasValue "inverted"` |
| `DetroitPizza` | `AmericanPizza` | `stackingOrder hasValue "inverted"` |
| `RomanTondaPizza` | `ItalianTraditionalPizza` + `TomatoBasedPizza` | — |
| `RomanAlTaglioPizza` | `ItalianTraditionalPizza` + `TomatoBasedPizza` | — |
| `SicilianPizza` | `ItalianTraditionalPizza` + `TomatoBasedPizza` | — |
| `NewYorkPizza` | `AmericanPizza` + `TomatoBasedPizza` | — |
| `StLouisPizza` / `CaliforniaPizza` / `HawaiianPizza` | `AmericanPizza` | — |
| `PekingDuckPizza` / `MalatBeefPizza` / `DurianPizza` | `ChineseStylePizza` | — |
| `FrenchPizza` / `ArgentinianPizza` / `JapaneseKoreanPizza` | `OtherGlobalPizza` | — |
| `WhiteSaucePizza` | `FlavorBasedPizza` + `WhitePizza` | — |
| `SeafoodPizza` | `FlavorBasedPizza` | — |
| `VegetarianPizza` | `FlavorBasedPizza` | **等价类**：`hasTopping allValuesFrom VegetableTopping ⊓ hasCheese someValuesFrom Cheese` |
| `ItalianStyleWhiteSeafoodPizza` | `WhiteSaucePizza` + `SeafoodPizza` | 多继承叶子类 |

**对象属性**：

| 属性 | 特征 | domain | range |
|---|---|---|---|
| `hasCrust` | Functional | `Pizza` | `components/Crust` |
| `hasSauce` | Functional | `Pizza` | `components/Sauce` |
| `hasCheese` | Functional | `Pizza` | `components/Cheese` |
| `hasTopping` | —（可多值） | `Pizza` | `components/Topping` |
| `isCrustOf` | inverseOf `hasCrust` | `Crust` | `Pizza` |
| `isSauceOf` | inverseOf `hasSauce` | `Sauce` | `Pizza` |
| `isCheeseOf` | inverseOf `hasCheese` | `Cheese` | `Pizza` |
| `isToppingOf` | inverseOf `hasTopping` | `Topping` | `Pizza` |

**数据属性**：`stackingOrder`（xsd:string，堆叠顺序）。

### 3.2 `pizza-components.owl`—— 组件类体系

**抽象与叶子**：

| 类 | 父类 | 注解 |
|---|---|---|
| `PizzaComponent` | —（抽象） | 组件根类 |
| `Crust` | `PizzaComponent` | 抽象；`minStockThreshold = 20` |
| `Sauce` | `PizzaComponent` | 抽象；`minStockThreshold = 15` |
| `Cheese` | `PizzaComponent` | 抽象；`minStockThreshold = 10` |
| `Topping` | `PizzaComponent` | 抽象；`minStockThreshold = 10` |

**饼底叶子子类（10 个，均带内联厚度约束）**：
- 薄饼类（`crustThicknessMm ∈ [3.0, 7.0]`）：`NeapolitanCrust`、`NewYorkCrust`、`StLouisCrackerCrust`、`RomanTondaCrust`、`FrenchThinCrust`。
- 厚饼类（`crustThicknessMm ∈ [20.0, 80.0]`）：`ChicagoDeepDishCrust`、`DetroitCrust`、`SicilianCrust`、`RomanAlTaglioCrust`、`ArgentinianThickCrust`。
- 约束形式：`owl:Restriction / owl:onProperty crustThicknessMm / owl:allValuesFrom <rdfs:Datatype withRestrictions min/maxInclusive>`。

**酱汁叶子子类（6 个）**：`TomatoSauce`（抽象，`NeapolitanTomatoSauce`/`AmericanTomatoSauce` 之父）、`NeapolitanTomatoSauce`、`AmericanTomatoSauce`、`WhiteSauce`、`OtherSauce`。
- `WhiteSauce disjointWith TomatoSauce`。

**奶酪叶子子类（4 个）**：`BuffaloMozzarella`、`LowMoistureMozzarella`、`Parmesan`、`ProvelCheese`。

**配料叶子子类（5 个，互斥）**：`MeatTopping`、`VegetableTopping`、`SeafoodTopping`、`HerbTopping`、`FruitTopping`；用 `AllDisjointClasses` 声明五者两两互斥。

**低库存类**：
- `LowStockComponent ⊑ PizzaComponent`（抽象父类）。
- `LowStockCrust`（<20）、`LowStockSauce`（<15）、`LowStockCheese`（<10）、`LowStockTopping`（<10）——由 SWRL 规则推理得到（见 §4）。

**数据属性**：`crustThicknessMm`（float）、`bakingTemperatureCelsius`（int）、`bakingTimeSeconds`（int）、`flourType`（string）、`fermentation`（string）、`status`（string）、`supplier`（string）、`batchNumber`（string）、`price`（decimal）、`purchaseDate`（date）、`shelfLife`（int）、`stockQuantity`（int）、`isDataValid`（boolean）。
**注解属性**：`minStockThreshold`（int，阈值）。

### 3.3 `pizza-processes.owl`—— 工序类体系

| 元素 | 类型 | domain/range | 说明 |
|---|---|---|---|
| `ProcessStep` | 类 | — | 独立工序节点，**具体串接由 BPMN 定义**（本体不含顺序/网关） |
| `ProcessExecution` | 类 | — | 某披萨实例中某步骤的执行记录 |
| `hasProcessStep` | ObjectProperty | Pizza → ProcessStep | 披萨所需工序 |
| `hasProcessExecution` | ObjectProperty | Pizza → ProcessExecution | 披萨关联执行记录 |
| `executesStep` | ObjectProperty | ProcessExecution → ProcessStep | 执行对应步骤 |
| `producesComponent` | ObjectProperty | ProcessStep → PizzaComponent | 步骤产出组件 |
| `usesComponent` | ObjectProperty | ProcessStep → PizzaComponent | 步骤使用组件 |
| `operator` | DatatypeProperty | ProcessStep → string | 操作人员 |
| `startTime` / `endTime` | DatatypeProperty | ProcessStep → dateTime | 起止时间 |
| `duration` | DatatypeProperty | ProcessStep → integer | 操作时长（分钟） |

> `pizza.owl` 中 `NeapolitanPizza` 用 **9 条 `hasProcessStep hasValue`** 关联 9 个工序个体：`Task_DoughMix`、`Task_DoughFerment`、`Task_CrustForm`、`Task_TomatoSauce`、`Task_BaseCheese`、`Task_ToppingSpread`、`Task_Bake`、`Task_Decorate`、`Task_Finish`（注意不含 `Task_WhiteSauce`/`Task_TopCheese`）。

### 3.4 TBox 约束汇总

| # | 约束 | 所在类 | 形式 |
|---|---|---|---|
| 1 | 必有 1 个饼底 | `Pizza` | `hasCrust` 基数 1 |
| 2 | 番茄基底披萨必有番茄酱 + 奶酪 | `TomatoBasedPizza` | someValuesFrom ×2 |
| 3 | 白披萨必有白酱、必无番茄酱、必有奶酪 | `WhitePizza` | some + all(¬TomatoSauce) + some |
| 4 | 玛瑞纳拉必有番茄酱、无奶酪 | `MarinaraPizza` | some + 基数0 |
| 5 | 无酱基底披萨无酱 | `NoSaucePizza` | 基数0 |
| 6 | 意式传统：饼底/酱/奶酪各 1、配料 ≥1 | `ItalianTraditionalPizza` | 基数 1/1/1 + min1 |
| 7 | 玛格丽特配料恰 1 且为罗勒 | `MargheritaPizza` | 基数1 + hasValue Basil |
| 8 | 深盘/底特律堆叠倒置 | `ChicagoDeepDishPizza`/`DetroitPizza` | `stackingOrder hasValue "inverted"` |
| 9 | 素食定义（全素配料 + 有奶酪） | `VegetarianPizza` | equivalentClass 交集 |
| 10 | 饼底厚度区间（薄 3–7 / 厚 20–80） | 10 个饼底类 | allValuesFrom 数值区间 |
| 11 | 白酱与番茄酱互斥 | `WhiteSauce` | disjointWith |
| 12 | 五类配料两两互斥 | 5 个 Topping 子类 | AllDisjointClasses |
| 13 | 三类酱汁分类互斥 | Tomato/White/NoSauce | AllDisjointClasses |
| 14 | 那不勒斯必含 9 道工序 | `NeapolitanPizza` | 9× hasValue |

## 4. SWRL 规则（`pizza-components-rules.owl`）

本体 IRI `http://example.org/pizza/components-rules`，命名空间基址 `.../components-rules#`；显式 `rdf:List` 格式编写。共 **5 条**规则（`swrl:Imp`），用于**库存预警**推理：

| # | 规则 | body（条件） | head（结论） |
|---|---|---|---|
| 1 | NeapolitanCrust 低库存 | `NeapolitanCrust(?neapolitan) ∧ stockQuantity(?neapolitan, ?qty_n) ∧ swrlb:lessThan(?qty_n, 20)` | `LowStockCrust(?neapolitan)` |
| 2 | Crust 低库存 | `Crust(?crust) ∧ stockQuantity(?crust, ?qty_c) ∧ swrlb:lessThan(?qty_c, 20)` | `LowStockCrust(?crust)` |
| 3 | Cheese 低库存 | `Cheese(?cheese) ∧ stockQuantity(?cheese, ?qty_ch) ∧ swrlb:lessThan(?qty_ch, 10)` | `LowStockCheese(?cheese)` |
| 4 | Sauce 低库存 | `Sauce(?sauce) ∧ stockQuantity(?sauce, ?qty_s) ∧ swrlb:lessThan(?qty_s, 15)` | `LowStockSauce(?sauce)` |
| 5 | Topping 低库存 | `Topping(?topping) ∧ stockQuantity(?topping, ?qty_t) ∧ swrlb:lessThan(?qty_t, 10)` | `LowStockTopping(?topping)` |

- 阈值与各类 `minStockThreshold` 注解一致（Crust=20 / Sauce=15 / Cheese=10 / Topping=10）。
- 规则1 是对 NeapolitanCrust 的**冗余特化**（规则2 已覆盖所有 Crust）——注释明示「包含针对 NeapolitanCrust 的额外规则」。
- 规则命中产生的低库存个体，经 `SwrlRuleTriggerListener` 触发 → RabbitMQ 外发（见《披萨应用-顶层设计》§6）。

## 6. SKOS 术语体系（`pizza-terminology.ttl`）

- `http://example.org/pizza/term` 同时是 `owl:Ontology` 与 `skos:ConceptScheme`，`prefLabel "披萨业务术语体系"@zh / "Pizza Business Terminology"@en`，`dct:created 2026-06-24`。
- 结构：`skos:Concept` + 中英 `skos:prefLabel` + 中文 `skos:definition` + `skos:broader`（上下位）。
- 覆盖概念族：
  - 总体：`Pizza`。
  - 组件：`Crust`、`Sauce`、`Cheese`、`Topping`。
  - 饼底细分（broader=Crust）：Neapolitan/NewYork/ChicagoDeepDish/Detroit/StLouisCracker/Sicilian/RomanTonda/RomanAlTaglio/FrenchThin/ArgentinianThick。
  - 酱汁细分（broader=Sauce）：TomatoSauce（→ Neapolitan/American）、WhiteSauce、OtherSauce。
  - 奶酪细分（broader=Cheese）：BuffaloMozzarella/LowMoistureMozzarella/Parmesan/ProvelCheese。
  - 配料细分（broader=Topping）：Meat/Vegetable/Seafood/Herb/Fruit，及 21 个具体配料概念。
  - 地域分类（broader=Pizza）：ItalianTraditional/American/ChineseStyle/OtherGlobal。
  - 风味分类（broader=Pizza）：FlavorBasedPizza。
  - 具体披萨品类（broader 分别为地域/父类）。
- **与 OWL 的交叉绑定**：TBox 类通过 `skos:exactMatch` 反向引用术语（如 `components/Crust skos:exactMatch term/Crust`），`pizza.owl` 的 `hasCrust/hasSauce/hasCheese/hasTopping` 亦 `skos:exactMatch` 对应术语，实现「同名同义」。

## 8. 运行态数据：MySQL + OBDA 映射

### 8.1 关系表（`createdb_tables.ddl`）

| 表 | 主键 | 关键列 |
|---|---|---|
| `pizza_components` | `id`（自增）；`uk_name` 唯一 | name、type、price、supplier、shelf_life_days、batch_number、status、purchase_date、stock_quantity |
| `crust_components` | `name` | crust_thickness_mm、baking_temperature_celsius、baking_time_seconds、flour_type、fermentation、status、supplier、batch_number、price、purchase_date、shelf_life_days、stock_quantity；`CHECK(crust_thickness_mm IS NULL OR > 0)` |
| `myPizza` | 无主键 | name、type、price、production_date、crust_name、cheese_name、sauce_name、topping_name |

- 库名 `mypizzadb`（utf8mb4）；DDL 幂等（`DROP TABLE IF EXISTS` 后重建）。
- 表间逻辑外键：`myPizza` 引用 `pizza_components`/`crust_components`。
- 种子数据 `data.sql`：饼底 10 + 酱汁 4 + 奶酪 4 + 肉类 7 + 海鲜 4 + 蔬菜 6 + 香草 3 + 水果 2 条组件，及 10 条 `myPizza` 成品记录。

### 8.2 OBDA 映射（`myPizza.obda`，3 条 MappingDeclaration）

| mappingId | 目标类/属性 | 数据源 |
|---|---|---|
| `component_business` | `components-abox/{name} a :{type}` + label/name/type/status/supplier/batchNumber/price/purchaseDate/shelfLife/stockQuantity | `SELECT ... FROM pizza_components` |
| `crust_mapping` | `components-abox/{name}` + crustThicknessMm/bakingTemperatureCelsius/bakingTimeSeconds/flourType/fermentation | `SELECT ... FROM crust_components JOIN pizza_components` |
| `mypizza_complete` | `core-abox/{name} a core/{type}` + name/type/price/productionDate/hasCrust/hasCheese/hasSauce/hasTopping | `SELECT ... FROM myPizza LEFT JOIN pizza_components` |

- 前缀声明：`:`/`comp:`→components、`pizza:`→core、rdf/rdfs/owl/xsd 标准前缀。
- 映射把**关系行虚拟成 RDF 个体**：`pizza_components.name` → IRI `.../components-abox/{name}`，`type` 决定其 rdf:type。

### 8.3 运行数据 vs 静态 ABox 的命名差异（重要）

- **数据库个体名以 `Instance` 结尾**（`data.sql` 注释明示：name 均以 Instance 结尾，如 `NeapolitanCrustInstance`）。
- **静态 ABox（`.owl`）个体名多为驼峰无后缀**（如 `NeapolitanCrust`、`buffaloMozzarellaInstance` 混用）。
- 因此经 OBDA 查询得到的运行态个体 IRI（`.../components-abox/NeapolitanCrustInstance`）与静态 `components-abox.owl` 中同名个体（若有）**并非同一 IRI**。运行态数据以 MySQL 为准，静态 ABox 主要服务推理/一致性/SKOS 校验。

## 9. 关键设计与待确认项

**关键设计：**
1. **TBox/ABox 分离 + 总入口聚合**：`pizza-all.owl` 一次加载全部模块，OWL 解析器自动去重 import。
2. **约束内联在类上**：饼底厚度、组件基数、堆叠顺序等直接以 `Restriction` 挂在类定义上。
3. **冗余与特化并存**：规则1（NeapolitanCrust）是规则2（Crust）的特化冗余，保证细粒度命中。
4. **本体与 SKOS 双轨**：OWL 管推理约束，SKOS 管术语词义，靠 `skos:exactMatch` 交叉绑定。
5. **虚拟数据**：组件/价格/库存不迁入本体，留在 MySQL 经 OBDA 按需访问，本体只管约束。

**待确认项：**

| # | 事项 |
|---|---|
| ① | `pizza-all.owl` 注释掉了 `core-abox`/`components-abox` 的 import，运行态是否仍需加载这两份 ABox（决定实例来源）。 |
| ② | 静态 ABox 个体名与 DB 个体名后缀不一致（`Instance`），是否需统一以避免 IRI 混淆。 |
| ③ | `Anchovy` 在 OWL ABox 中 typed 为 `SeafoodTopping`，但 SKOS 中同时 broader 于 MeatTopping 与 SeafoodTopping，双归属是否预期。 |
| ④ | 规则1 与规则2 语义重叠，是否为刻意保留。 |
| ⑤ | `isDataValid`、`operator`、`startTime`/`endTime` 等属性在样本数据/BPMN 中未见使用，是否为预留扩展。 |
