## 0. 变更说明（相对旧流程）

| 维度 | 旧流程（v1，现有 TMSD） | 新流程（v2，正向） |
|---|---|---|
| 设计范式 | 以**历史设计**为模板，按「机型/升降机 → 连接方式 → 中径 → 高度 → 筒节 → 平台内径」**从后往前逐级匹配**；命中即复用，未命中逐级回退 | **完全正向**：不依赖历史设计匹配，由「主体信息表 + 布局表」两张输入表 + 设计规则**一次性算出**全部参数 |
| 依赖 | 需要历史设计实例库（ABox）与匹配容差 | **不依赖历史设计**；输入即唯一事实来源 |
| 执行环节 | 命中越多 → 执行越少（0~6 个环节） | 6 个设计环节**全部必做**（升降机9、配件8、直径7、高度6、筒节5、平台4） |
| 输出 | 需修改的模型参数 txt（增量式） | 下一阶段 3D 模型的**完整参数表**（全量、可驱动 Creo） |

> 新流程 = 旧流程「全未命中」分支去掉"匹配"后的**唯一路径**，但每个环节改为**由输入正向求解**，而非"在历史图上改"。

### 1.4 直径 / 中径 / 壁厚定义（已确认）

| 术语 | 定义 | 关系 |
|---|---|---|
| 外径 `D_out` | 塔筒**外壁圆**直径 | `D_out = D_in + 2T` |
| 内径 `D_in` | 塔筒**内壁圆**直径 | `D_in = D_out − 2T` |
| 壁厚 `T` | 筒壁厚度 | — |
| 中径 `D_mid` | 内外壁中线圆直径 | **`D_mid = D_in + T = D_out − T`** |

- 与老应用 `get_mid_dim()`（取 `外径 − 壁厚`，`tool.py` L115–121）**完全一致**。
- 老应用 `diCal()` 输出的"内径" = 按标高线性插值的外径 − 2×该处壁厚，与本定义同源。

## 3. 正向设计步骤（按数据依赖排序，全部必做）

```
S0 输入解析 ─► S1 塔筒外形/分段几何 ─► S2 升降机/扶持(9) ─► S3 配件类型(8)
   ─► S4 直径(7) ─► S5 高度(6) ─► S6 筒节(5) ─► S7 平台(4) ─► S8 输出参数表
```

### S0 输入解析
- 读主体信息表 4 个 sheet + 布局表中间段 sheet（见 §1）。
- 校验：法兰数 ≥ 2；每段筒节 ≥ 1；布局表每段列存在。缺失即报错（不静默降级）。

### S1 塔筒外形设计与分段几何（旧"步骤1"）
- **段索引**：`section_qty = flange_qty − 1`；下段=i0，中段=i1..i_{q−2}，顶段=i_{q−1}。
- **逐筒节几何**（`mgeoRead(n)`）：读取段内每个筒节的 高= (标高上−标高下)×1000、下外径 Db、上外径 Dt、壁厚 t；段**含上下法兰**。
- **段总长** `SEC_H_total = Σ筒节高`（`secNLength()`）。
- **累计焊缝位置**（`get_weld_positions(n)`）：逐筒节高整数累加（环焊缝）。
- **任意高度处内径** `diCal(h,n)`：锥段线性插值 `Di(h) = d + (D−d)(L−h_m)/L`，再减 2×对应筒节壁厚（`tool.py` L240–250）。
- **中径对齐**：`中径 = 外径 − 壁厚`（`get_mid_dim()` L115–121，用于分片/参考）。

### S2 升降机设计：扶持（旧"步骤9"）
- **前置**：升降机类型固定 = 钢绳导向 ⇒ **本节必做，恒有扶持**。
- 老应用 `midSkelW` **直读**布局表 (12,n) 作为 `H_SUPPORT`（`infoW.py` L448），不做计算。
- **取值 = 直读布局表 (12,n)**（✅ 已确认 2026-09-28，沿用老应用）。注：老应用 `support()`（`tool.py` L541–548，`SEC_H_total/2 − H_PLATFORM`）经全仓检索**未被任何位置调用（死代码）**，不采用。
- **避焊缝**：校验与环焊缝距离 `> 100`（本体 `supportToWeldDistance`）。
- 输出 `H_SUPPORT`。（爬梯导向分支在本流程不适用，保留为规则说明。）

### S3 附件连接方式设计：配件类型替换（旧"步骤8"）
- 由连接方式（焊接/粘贴）决定配件类型总成（`ACCESSORY_TYPE` / `ACCESSORY_CONNECTION_TYPE`）。
- 连接方式**固定 = 焊接**（§1.3，已确认）⇒ 取焊接型配件类型总成。

### S4 直径设计（旧"步骤7"）
- **电缆托架参数按机型映射**（`midSkelW` L459–468 `windturbine_models`）：

  | Model | L_CABLE | L1_CABLE_I | L2_CABLE_I |
  |---|---|---|---|
  | V12 | 420 | 800 | 800 |
  | V15 | 420 | 800 | 800 |
  | V17 | 800 | 650 | 650 |
  | V19 | 560 | 650 | 650 |

- `di_cable_top = diCal(SEC_H_total − 1000, n)`；`di_cable_down = diCal(980, n)`。
- 弦长映射关系（"电缆托架中心距同侧爬梯支撑的弦长"，访谈 7.1）由上表弦长值承载。

### S5 高度设计（旧"步骤6"）
- **与塔筒等高**：爬梯 / 线槽 `L_LADDER = L_C = SEC_H_total`（`midSkelW` L437/446），**直接取段高，不做取整**。
- 爬梯梯档**阵列数** `N_LADDER = L_LADDER / 280`（老应用 `infoW.py` L279 明写 `L_LADDER/280`）⇒ 梯档间距 280；即段高按 280 的整数倍设计。
- **第一个踏棍离下法兰（第一法兰）`140`mm**（老应用 `$H_LADDER_FIXED_SUPPORT = −L_LADDER + 140`，`infoW.py` L275）。
- 爬梯支撑长度/宽度 `L_LADDER_I`/`W_LADDER_I` 取布局表 (3,n)/(4,n)。
- ✅ 已确认（2026-09-28）：段高 `SEC_H_total` **恒为 280 的整数倍** ⇒ `N_LADDER = L_LADDER/280` 天然为整数，**无需任何取整**。

### S6 筒节设计（旧"步骤5"）—— 正向排布
1. **爬梯支撑/电缆托架（平齐）排布**（核心，`ls_heights()` L550–635 的正向化）：
   - 起点 `H1_L = 980`（本体 `firstAccessoryToBottom hasValue 980`，**已裁决取本体 980**；老应用 `980·cos(α)` 不采用）。
   - 后续间距**首选 `1960`（= 7×280）**，且**必为 280 的倍数**；仅当与焊缝干涉时降档（`1960 → 1680 → 1400`，均为 280 倍数；本体 `accessoryCenterSpacing ∈ [1400,1960]`）。原则：满足约束下**越大越好**。（恢复老应用 1400 应急降档档位——相位冲突下 1680/1960 无解时必须用 1400。）
   - **避焊缝判据（已确认）**：用**附件上/下边缘**到焊缝的距离判断，**不是附件中心到焊缝**——需结合附件安装方向尺寸（如 `L_LADDER_I`/`W_LADDER_I` 等）算出边缘；要求边缘到焊缝 `> 100`（本体 `accessoryToWeldDistance`），落入禁区则改用下一档增量。
    - **终止**：最后一个爬梯支撑到平台 ∈ `[840,1960]`（本体 `secondLastToPlatform`，**v16.2 放宽下界至 840**，采用老应用「平台下 840」终止口径）。排布口径为**贪心取大**（每步优先 1960，避焊缝才降 1680/1400），**取消双变体、仅保留单方案**。
   - **输出 `H{i}_L`：语义严格按老应用 = "第 i 组爬梯支撑安装高度（距上一组安装高度的增量）"**（`tool.py#ls_heights` L611–614）。TMSD 现有"绝对高度"实现须改为增量；`H{i}_L_Exist` 输出 H1..H20，缺失补 `no`。
2. **电缆线夹排布**（区域固定 = 中国 ⇒ `T_or_F = 1`）：
   - **隔开**：首组 = `H1_L`；其后每 **2** 个爬梯支撑增量合并为 1 组线夹（`cs = h_values[i] + h_values[i+1]`，`tool.py` L595–602）。
   - 输出 `H{i}_CABLE`（同样为**增量**语义）、`H{i}_CABLE_Exist`（H1..H20，缺失补 `no`）。

### S0–S8 的运行时映射（Camunda 8 / Zeebe + JobWorker，实现）

正向流程的可执行定义 = `ontology/bpmn/TowerMidDesign.bpmn`（Camunda 8 / Zeebe，`isExecutable="true"`）。
**BPMN 与 JobWorker 之间没有代码级调用关系**：BPMN 部署到流程引擎（Zeebe）后，由引擎按拓扑创建并推进流程实例；
每个 `serviceTask` 用 `zeebe:taskDefinition type` 声明作业类型，引擎在流程到达该节点时派发一个作业（job），
订阅**同名 jobType** 的 `@JobWorker`（`TMSDOntologyJobWorker`）被回调执行该环节计算、回写结果，作业完成后流程继续推进。
分工：**BPMN 管「怎么串」、引擎管「驱动」、Worker 管「每步怎么算」、本体管「约束」**，四者解耦，绑定仅靠 `type` 字面量一致。

| BPMN 节点 id | 环节 | `zeebe:taskDefinition type` | Worker 处理 |
|---|---|---|---|
| `Task_Step0` | S0 输入解析 | `tmsd-step0-parse-input` | 读入并校验两张输入表，建立设计会话（缓存输入 + 中段段号） |
| `Task_Step1` | S1 塔筒外形/分段几何 | `tmsd-step1-tube-shape` | 逐筒节几何、段长、焊缝位置，回填会话 |
| `Task_Step9` | S2 升降机/扶持 | `tmsd-step9-elevator` | 直读布局表 (12,n) 得 `H_SUPPORT` |
| `Task_Step8` | S3 配件类型替换 | `tmsd-step8-accessory` | 焊接型配件总成 |
| `Task_Step7` | S4 直径设计 | `tmsd-step7-diameter` | 机型→电缆托架、`di_cable_top/down` |
| `Task_Step6` | S5 高度设计 | `tmsd-step6-height` | 梯/线槽 = 段高、梯档 280 / 踏棍 140 |
| `Task_Step5` | S6 筒节设计 | `tmsd-step5-tubesection` | 附件/线夹/灯/防雷排布（`H{i}_*` 增量 + `_Exist`） |

| `Task_Output` | S8 输出参数表 | `tmsd-output-parameters` | 写 3 份 txt + 约束报告 |

- 流程实例按 `StartEvent_Start → Task_Step0 → Task_Step1 → … → Task_Output → End_Design` **单一顺序**推进，**无排他网关、无回退**。
- 引擎侧约束数值不硬编码，统一取自本体运行时解析入口 `TmsdVocabulary`（启动时解析 `ontology/TowerMidSection.owl` v16.3，16 条数值 + 9 条基数），与本体保持一致。
- 源图 `ontology/bpmn/塔架中段定制化设计流程.bpmn` 为 `isExecutable="false"` 的**同拓扑纯 BPMN 视图**，仅供审阅；运行以可执行副本 `ontology/bpmn/TowerMidDesign.bpmn` 为**唯一真值**（后续所有流程更新均改此文件）。

**部署与可见性（为何在 Camunda UI 里看不到"任务"）**

- 本流程 9 个节点**全部是 `serviceTask`（后台作业型），没有 `userTask`**：`serviceTask` 由引擎派发 job、`@JobWorker` 自动认领执行，属于「无人值守」环节。Camunda **Tasklist 只呈现 `userTask`**，因此 Tasklist 中**不会出现任何待办任务**——这是设计使然，并非流程缺失。
- 工程内**没有生产部署路径**：`src/main` 下无任何 `deployResource`/`ZeebeClient` 部署代码，`TMSDApplication` 是 `web-application-type: none` 的纯 JobWorker，只做「消费作业」，不会自行把 BPMN 部署到外部 Camunda。BPMN 的部署只发生在测试中：
  - `TMSDProcessTest`：`@ZeebeProcessTest` 使用**内存流程引擎**，测试进程结束即销毁，Camunda UI **不可见**；
  - `TMSDDesignProcessTest`：连接 `localhost:26500` 的**真实 Zeebe** 并 `deployResource`（需先本地启动 Zeebe，否则超时）。
- 故要在 **Camunda Operate / Modeler** 里看到该流程定义或实例，必须先把可执行副本 `ontology/bpmn/TowerMidDesign.bpmn` 部署到目标引擎；同目录的源图 `塔架中段定制化设计流程.bpmn`（`isExecutable="false"` 且无 zeebe 扩展）**不能部署**（在 Modeler 中打开它只会看到静态视图）。
