## 一、测试目标与原则

把「判据 → 八纲 → 六经 → 方证 → 方剂/药物加减」的单向推理链，用**可复跑的自动化用例**钉死，
确保：**每个方证在其典型四诊组合下，都能被推理机推到、且推到的是正确的方证与方剂**。

| 原则 | 说明 | 铁律 |
|---|---|---|
| **唯一真值来源** | 端到端测试的期望值必须由 `fangzheng/rules.owl`（唯一真值来源）经 **Openllet 推理**得到，禁止另写 Python「期望值生成器」 | 65 |
| **纯 Java 闭环** | 端到端测试由 Java + OWL API，走与生产**同一套加载/推理路径**；无 Python 参与 | 65 |
| **锚点取诊断六经** | 六经锚点一律取本体「诊断六经」（`equivalentClass` 的六经项），而非 `belongsToLiujing` 篇章归属 | 22/61 |
| **主证不全不冒充结论** | 主证不全时方证为「方证未定」，候选 Top1 不得包装成结论 | 16 |
| **互斥不阻断、不污染** | 与病例四诊互斥的锚点/追问项必须跳过 | 63/64 |
| **不硬凑** | 通过数不是目标；本体医理正确才是目标（测试是手段，不是裁决者） | 26 |

## 四、端到端测试基座（`JingfangTestSupport`）

### 4.1 关键常量

| 常量 | 值 |
|---|---|
| `NS` | `http://www.tcm-classics.org/jingfang#` |
| `PROCESS_ID` | `Process_Jingfang_Diagnosis` |
| `SIX_CHANNELS` | 六经集合（太阳/阳明/少阳/太阴/少阴/厥阴） |
| `LJ_ANCHOR_SYMPTOMS` / `LJ_ANCHOR_PULSES` | 每经的**锚点症状/脉象**（用于隔离跨经误触） |
| `LJ_ANCHOR_PULSE_FALLBACK_SYMPTOMS` | 脉路被互斥全部跳过时的**无脉替代症状** |
| `LIUJING_OF_MISC` / `LIUJING_OF_HEBING` | 杂病→六经、合病→六经的解析表 |

### 4.2 用例执行链（`assertFangzheng`）

```
用例给出：六经 lj、方证 fz、方剂 formula、症状/脉象/舌象/腹证 fragment
  ① anchorLiujingFor(fz, lj)          取本体「诊断六经」作锚点（非篇章归属）
  ② buildAnchoredVars(...)            注入六经锚点 → 构造流程变量
  ③ startProcessAndGetResult(vars)    启动真实流程实例，awaitSettled 取快照
  ④ printResult(...)                  打印结果（排障用）
  ⑤ assertSizhenMapped(...)           契约守护：首节点须把 extra fragment 原样映射回 IRI
  ⑥ assertBasicResult(...)            断言六经 / 方证 / 方剂
```

### 4.3 断言工具

| 断言 | 维度 |
|---|---|
| `assertSizhenMapped` | **契约守护**：`symptom-mapping` 必须把预置四诊 fragment 原样映射回 IRI；此处失败=上游契约被改，下游断言失败只是「症状」 |
| `assertBasicResult` | 六经 / 方证 / 方剂（`finalFormula`） |
| `assertFangzheng` | 方证 + 方剂 + 六经锚点（主断言，最常用） |
| `assertFangzhengAny` | **并列可接受集合**：医理等价/《金匮》并列方证（eq 相同）接受任一命中 |
| `assertBagang` | 八纲三维（表里/寒热/虚实） |
| `parseIris` | fragment → 完整 IRI |
| `assertInstancesExist` | 校验用例引用的 fragment 在本体中真实存在 |
| `resolveLiujingForAnchor` | 杂病/合病 → 参与断言的六经列表 |
| `isLiujing` | 是否六经名 |

### 4.4 锚点注入（`buildAnchoredVars`）—— 关键设计

为隔离跨经误触，每个用例注入明确的六经锚点；三条保护规则：

1. **能自证即不注入**：病例自身四诊已能自证某经时跳过该经锚点，避免「凭空补上兄弟方证的鉴别点」
   （如太阳锚点补「恶寒」，会把桂枝去芍药汤证误判为桂枝去芍药加附子汤证）。
2. **互斥即跳过**：与病例四诊互斥的锚点症状/脉象一律跳过（铁律 63/64）。
3. **脉路断绝补无脉替代**：某经的脉象锚点被全部跳过时，改用该经的**无脉替代症状**注入。

### 4.5 期望值来源

- 断言里的「期望方证/方剂」由**人工依 `rules.owl` 与本体定义**给出，并随本体固化锁定；
- 期望值的**权威来源是 `rules.owl`**（唯一真值来源，铁律 65）——即「有是证、用是方」的规则与定义，
  而非另写一套生成脚本；
- 用例输入（症状/脉象/舌象/腹证 IRI）为**人工手写 fragment**（拼 `NS+frag+"_instance"` 并经
  `assertInstancesExist` 校验存在）。

> ⚠️ **数据来源辨析**：`HWCodeArtsDir/scripts/e2e_cases.json` 是**反向抽取产物**
> （`extract_inputs.py` 从 Java 源码抽取），**不是**测试数据来源；测试数据以 Java 源码为准。

## 五、用例构造规范

1. **输入 base = DNF 最小充分分支**：每条析取规则取一个最小充分症状集作为用例基，保证**唯一触发集**。
2. **按唯一触发集拆例**：一个方证若有多条独立触发路径，拆成多例分别覆盖。
3. **注入六经锚点**：为每例注入明确六经锚点，隔离跨经误触（§4.4）。
4. **期望 = 所满足规则之并集**：一条规则含 OR 多通道时，**接受任一通道命中**即可（避免漏报/误报）。
5. **并列方证用 `assertFangzhengAny`**：本体 eq 相同、医理皆可的两方证，接受任一命中。

> 用例方法名惯例：`t_<方证拼音>`（如 `t_sinisanzheng`），十八反警告等专项用
> `shouldWarnOn<方>TangAntagonism`，合病检测用 `shouldDetect<…>Hebing`。

每个方证用例按需断言下列维度（越靠前为通用必测）：

| 方剂 | `finalFormula` | 完整方剂 IRI |

| 十八反 | `warnings` | 配伍禁忌 |

## 九、运行前置条件与并发纪律

### 9.1 前置条件

- **方证类（L3）**需先启动：Camunda/Zeebe 网关（26500）、本体推理 Worker（HTTP 9082）、
  Ontop（8080）、MySQL（3306）；否则首个方证用例会因等待流程结果而超时。
- **`HerbRuleEngineTest` 无此前置**（离线）。

### 9.2 超时连坐（`StopOnTimeoutExtension`）

`AbstractJingfangDiagnosisTest` 挂 `StopOnTimeoutExtension`，使用**静态中止标志**，且套件在
同一 JVM 内顺序执行——因此**任意一个方证用例超时，其后所有方证用例（含后续测试类）都会被跳过**。
`HerbRuleEngineTest` 未挂该扩展且排首位，不受影响。

> 需逐类看到真实结果时，改用 `run_all_fangzheng_tests.ps1 -Fork`（每类独立 JVM）。

### 9.3 回归纪律（铁律 69）

- **回归前强制重启 Worker**，确认加载的是当前本体/代码（避免 stale worker 掩蔽缺陷）；
- **回归期间禁改 `ontology/**.owl`**，只允许改 `OntologyFrameworkTCM/**`；
- 本体已固化，`rules.owl` v2.9 规则层一并冻结。
