# 塔架中段 — 本体对象模型

> 基于《塔架中段设计流程》构建，用于结构化表达物理对象及其关系。  
> 设计原则：**真实存在的物理对象定义为类，其余定义为属性**；**属性承载实例值，约束用 owl:Restriction 表达**。  
> 设计步骤（S0 输入解析 → S1 塔筒外形/分段几何 → S2 升降机/扶持 → S3 配件类型 → S4 直径 → S5 高度 → S7 平台 → S6 筒节 → S8a 判定 → S8b 汇总/输出）放到 BPMN 中，不在本体中出现（**单候选顺序设计 + 一条 S8a→S6 回退环**，无匹配；**S7 平台先于 S6 筒节**）。  
> **下游用途：Openllet 自动推理与设计**，故属性类型按 OWL 2 DL 语义选择。  
> **版本（2026-10-08 校核对齐）**：本体真值 `TowerMidSection.owl` **v16.10**；命名空间 `http://goldwind.com/ontology/tower-mid-section#`；元素计数：类声明 **46**（命名类，v16.9 为 **44**）、对象属性 **54**、数据属性 **76**（v16.9 为 **73**）、具名个体 **135**（机型 V12/V15/V17/V19 共 **4** + 输出规范 **131**）；可数值校验约束 **19** 条、基数约束 **9** 条、`hasKey` **3** 条、SWRL 规则 **0 条**、**合规等价类 14 条**（v16.8 新增）、**校验抽象基类 1 个**（v16.9 新增）、**输出行模板 125 条 + 输出文本块 6 个**（v16.10 新增）。
>
> **v16.7 定位（全面声明式改造，去 SWRL）**：把 v16.6 的 4 条 SWRL 规则**整体迁为 OWL 公理**，由 Openllet 分类/一致性完成校验，本体**不再含任何 SWRL**：① 净距越限改为等价类 `:约束违规 ≡ :焊缝净距校验 ⊓ ∃:净距.(xsd:decimal[≤ 100])`；② `:无附件段 ≡ :塔架中段 ⊓ (:附件数量 value 0)`；③④ 附件类型改为子类公理 `:附件 ⊓ (:附件连接方式 value「焊接式」) ⊑ (:附件类型 value「焊接式附件总成」)`（「粘贴式」同理）。删除数据属性 `:净距下限`（下限常量化进等价类）与全部 `swrl:Imp`/`swrl:Variable` 及 `swrl:`/`swrlb:` 前缀。硬约束门禁（`owl:Restriction` + `validateAxioms`）保留不变。
>
> **v16.8 定位（判定全迁 Openllet）**：把此前仍由 Java 逐项判定（`TmsdDesignPipeline.check` 的 `accepts`）的 **14 项数值约束**也迁为本体声明式校验。新增基类 `:数值约束校验`（`ValueCheck`）与数据属性 `:校验值`（`checkValue`，`xsd:decimal`）、`:校验属性名`（`checkProperty`，`xsd:string`）；为每项建一个**合规等价类**（如 `:平台到筒顶距离合规 ≡ :数值约束校验 ⊓ (:校验属性名 value "platformToTopDistance") ⊓ ∃:校验值.[1250,1250]`），由 Openllet 分类回读「校验个体 ∈ 合规类 ⇒ 该项通过」。范式与净距 `:焊缝净距校验`/`:约束违规` **对偶**（**Java 只算实测值、判在本体**）。合规等价类中的 facet 与对应宿主类 `owl:Restriction` **同源，两处须同步**。至此 `ConstraintCheck` 每条 `pass` 均来自本体回读，`actual` 列仍展示 Java 算值。14 类见 §9.7。
>
> **v16.9 定位（校验层结构收敛）**：新增抽象基类 `:校验`（`Check`），把此前两个并列的顶级校验类 `:焊缝净距校验`（`WeldClearanceCheck`，关系型：校验附件/螺柱/焊缝）与 `:数值约束校验`（`ValueCheck`，标量型：校验属性名/校验值）收为其子类。纯分类学收敛——不改各自属性域、不改等价类判定机制、不动硬约束门禁，**Java 侧零改动**（`assessAll` 回读逻辑不受影响）；类声明 **43 → 44**。
>
> **v16.10 定位（输出规范迁入本体，去硬编码）**：依「程序中不得硬编码业务数据」铁律，把 `TmsdOutputWriter` 生成骨架关系式 txt 时的**变量名、尾注释、空格标点、整块原样文本**从 Java 迁入本体，Java 只保留「语义键 → 值」计算。新增两个顶层类——`:输出行模板`（`OutputLine`，承载一行完整模板）与 `:输出文本块`（`OutputBlock`，承载整块原样文本）；新增三条功能型数据属性——`:输出行模板`（`outputTemplate`，含 `{{value}}` 注入位与 `{k}`/`{i}` 索引位）、`:输出块文本`（`outputText`）、`:输出适用域`（`outputScope`）；为 `TmsdOutputWriter` 逐行渲染所需的 **125 条行模板** + **6 个原样块**（`weightInfo`/`skelName`/`driveSize`/`skelComp`/`vflangeInfo`/`vflangeTail`）建个体。Java 侧 `fill(key, …)` 取模板注入、`outBlock(key)` 取整块，**不再硬编码任何变量名或注释文案**；渲染产物**逐字节不变**（除版本号 +1）；类声明 **44 → 46**、数据属性 **73 → 76**、具名个体 **4 → 135**。

## 一、本体概览

### 命名空间

| 前缀      | URI                                               |
| ------- | ------------------------------------------------- |
| `:`     | `http://goldwind.com/ontology/tower-mid-section#` |
| `rdfs:` | `http://www.w3.org/2000/01/rdf-schema#`           |
| `owl:`  | `http://www.w3.org/2002/07/owl#`                  |
| `xsd:`  | `http://www.w3.org/2001/XMLSchema#`               |

### 设计原则

- **父子关系（rdfs:subClassOf）**：表示"是一种"的关系
- **组成关系（对象属性）**：表示"有"的关系
- **约束（owl:Restriction）**：表示"必须满足的范围"，不写在注释里
- **分类值**：优先用类层次或对象属性指向个体（如 `:机型` / `:区域`）；仅当取值简单、无需独立推理时，才用物理对象上的 `xsd:string` 数据属性（如 `:附件连接方式` / `:附件类型` / `:灯类型`，**v15.8**）

### 单位约定

| 类别   | 单位     | 说明                       |
| ---- | ------ | ------------------------ |
| 构件尺寸 | **mm** | 外径/内径、壁厚、高度、间距、位置等，全局统一  |
| 场地标高 | **m**  | `:标高下` / `:标高上`，不与构件尺寸比较 |

> Openllet **不做单位换算**，混用单位会让跨属性比较（如"梯子高度 = 筒高"）直接失效。

> **为什么 `:塔架`/`:灯` 为独立顶层类**：按"父子关系表示**是一种**"的原则，"塔架是一种风机""灯是一种照明系统"均不成立，它们是**组成**关系。v9.2 已对机头做过同样修正，v10.0 补齐一致性。  
> **v15.6 层级扁平化**：删除中间类 `:塔架段`，`:塔架中段` **直接作为 `:塔架` 的子类**（`:塔架中段 ⊂ :塔架`）；塔架"由"塔架中段组成（对象属性 `:有塔架中段`）。原 v15.0 的 `:塔架段 ⊂ :塔架` 中间层已取消。  
> **v15.0 附件边界（P0-2）**：业务确认「附件不包括螺柱，也不包括线槽」，故新增顶层类 `:构件`，`:螺柱`/`:线槽` 由 `:附件` 子类改挂 `:构件` 子类；新增对象属性 `:有构件`/`:构件属于`，`:固定在塔筒` 定义域扩为 `:附件 ∪ :构件 ∪ :平台`。  
> **v15.1 附件边界再扩（业务确认）**：`:扶持` **不算附件**（其属性 `:扶持位置` 与附件不同），由 `:附件` 改挂 `:构件`；扶持不再继承 `:附件到焊缝距离` / `:附件中心间距`，**仅保留焊缝距离约束**——单建数据属性 `:扶持到焊缝距离`（>100），不参与附件中心间距排布。  
> **v14.0 裁剪**：本本体仅服务于「塔架中段定制化设计流程」，`:风机`、`:风机机头`、`:偏航轴承`、`:塔架底段`、`:塔架顶段` 与该流程无关，已整体删除；`:塔架` 作为**抽象父类**保留（v15.6 起 `:塔架中段 ⊂ :塔架`），`:有机型`/`:有区域` 由 `:风机` 改挂至 `:塔架中段`。

## 九、声明式校验公理（原 SWRL 规则迁入）

> §9.1~§9.5 为**历史/示意**规则（用于说明"哪些约束 DL 表达不了"，本体从未生效）；**§9.6 为 v16.7 实际写入本体并生效**的校验公理（由 v16.6 的 4 条 SWRL 规则迁入，本体已无 SWRL）。

### 9.1 附件间距约束（相对约束，DL 无法表达）

```swrl
(?a :附件到焊缝距离 ?d) ∧ swrlb:lessThanOrEqual(?d, 100)
  → (?a :约束违反 "附件与焊缝距离不足")
```


### 9.2 梯子高度与筒高一致

```swrl
(:塔架中段 ?m) ∧ (:有塔筒 ?m ?t) ∧ (:高度 ?t ?h)
  ∧ (:有爬梯 ?m ?l) ∧ (:梯子高度 ?l ?lh) ∧ swrlb:notEqual(?h, ?lh)
  → (?l :约束违反 "梯子高度与筒高不一致")
```

### 9.3 相邻附件实际间距校验（v11.0 新增，v12.0 阈值修正）

> DL 只能校验单值区间（`[1400,1960]`），"相邻两附件之间的实际中心距"需跨个体比较，须用 SWRL。

```swrl
(:附件 ?a) ∧ (:附件 ?b) ∧ swrlb:notEqual(?a, ?b)
  ∧ (:支撑位置 ?a ?pa) ∧ (:支撑位置 ?b ?pb)
  ∧ swrlb:subtract(?d, ?pa, ?pb) ∧ swrlb:greaterThan(?d, 0)
  ∧ swrlb:lessThan(?d, 1400)
  → (?a :约束违反 "相邻附件中心距小于 5×280mm")
```

### 9.4 爬梯支撑与电缆托架平齐校验（v12.0 新增）

> 流程 5.1：这两个附件是平齐的。DL 无法表达"两个数据属性值相等"，须用 SWRL。

```swrl
(:爬梯支撑 ?s) ∧ (:电缆托架 ?b) ∧ (:平齐 ?s ?b)
  ∧ (:支撑位置 ?s ?ps) ∧ (:托架位置 ?b ?pb)
  ∧ swrlb:notEqual(?ps, ?pb)
  → (?s :约束违反 "爬梯支撑与电缆托架不平齐")
```

### 9.5 灯类型推导（v12.0 新增；v15.8 改为数据属性）

> 流程 5.4：灯的类型由「机型 + 区域」确定。属规则推导，可用 SWRL 或外置规则表。

```swrl
(:塔架中段 ?m) ∧ (:有灯 ?m ?l)
  ∧ (:有机型 ?m ?model) ∧ (:有区域 ?m ?region)
  ∧ (:灯类型表 ?model ?region ?lt)
  → (:灯类型 ?l ?lt)
```

> `:灯类型表` 为外置映射表（机型 × 区域 → 灯类型），本体不臆造具体取值。  
> **v16.0 起**：`:灯类型` 统一固定为「焊接灯」，不再由机型 + 区域映射；本节 SWRL 推导规则仅作历史保留。

### 9.6 v16.7 已落地公理（由 4 条 SWRL 迁入，写入本体生效）

> v16.6 的 4 条 SWRL 规则已于 v16.7 **全部迁为 OWL 公理**（本体已删除 `swrl:` / `swrlb:` 前缀、全部 `swrl:Imp` / `swrl:Variable`）。Openllet 通过**分类**判定归属，引擎回读路径见 §十一。

**公理 1 — 净距越限 ⇒ 约束违规**（等价类；下限常量 100 写进类表达式）：

```turtle
:约束违规 ≡ :焊缝净距校验 ⊓ ∃:净距.(xsd:decimal[≤ 100])
```

**公理 2 — 附件数量 = 0 ⇒ 无附件段**（等价类）：

```turtle
:无附件段 ≡ :塔架中段 ⊓ (:附件数量 value 0)
```

**公理 3/4 — 连接方式 ⇒ 附件类型（派生）**（子类公理 GCI）：

```turtle
:附件 ⊓ (:附件连接方式 value "焊接式") ⊑ (:附件类型 value "焊接式附件总成")
:附件 ⊓ (:附件连接方式 value "粘贴式") ⊑ (:附件类型 value "粘贴式附件总成")
```

> 公理 1 是校验层核心：引擎把每对 (被校验实体, 环焊缝) 物化为 `:焊缝净距校验` 个体并断言 `:净距`，经 Openllet **分类**即把 `:净距 ≤ 100` 者归入 `:约束违规`，引擎回读 `:约束违规` 实例；公理 2 同理回读 `:无附件段` 实例。公理 3/4 演示「属性派生」（连接方式 → 附件类型），已实际落地。
>
> **与 SWRL 的差异**：OWL 等价类（分类）**不使本体 inconsistent**（不像 `allValuesFrom` 那样越界即崩本体），既能细粒度定位违规、又不破坏本体一致性——这正是 v16.6「门禁 vs 标记职能分离」的根因，v16.7 以声明式公理一并消解。

## 十一、Openllet 推理适配说明

### 11.1 推理机能做什么

| 用途                                                           | 实现方式                                                                        |
| ------------------------------------------------------------ | --------------------------------------------------------------------------- |
| 分类（判断个体是钢绳导向还是爬梯导向升降机）                                       | 类层次 + `:有扶持` / `:以爬梯为导向` 属性推断                                               |
| 一致性校验（附件距焊缝 >100、附件中心间距 1400~1960、第一附件到底部=980、最后电缆托架到平台=200、平台内径匹配容差=6、梯档 280/首踏棍 140、防雷螺柱距法兰面 50、极限法兰厚度 215/内径扣减 600） | `owl:Restriction`                                                           |
| **净距越限细粒度标记 / 无附件段判定**（**v16.6 引入，v16.7 改声明式**）                | **OWL 等价类**：物化 `:焊缝净距校验` 个体 → Openllet 分类 → 回读 `:约束违规` / `:无附件段` 实例（详见 §9.6） |
| **14 项数值约束逐项判定**（**v16.8 引入，判定全迁本体**）                | **OWL 等价类**：物化 `:数值约束校验` 个体（断言 `:校验属性名` + `:校验值`）→ Openllet 分类 → 回读个体是否 ∈ 对应 `*合规类`（详见 §9.7）；`ConstraintCheck` 每条 `pass` 均源于此 |
| 完整性校验（缺值检测）                                                  | `owl:qualifiedCardinality`                                                  |
| 同机型 / 同区域匹配                                                  | `:有机型` / `:有区域` 对象属性 + 个体                                                   |
| **附件连接方式**（正向流程固定为「焊接式」）                                         | `:附件连接方式`（字符串数据属性，粘贴式/焊接式）                                             |
| **附件类型联动**（步骤 8.1 替换附件类型，焊接型）                                    | `:附件类型`（字符串数据属性）                                                         |
| **灯类型**（本次固定「焊接灯」）                                       | `:灯类型`（字符串数据属性）                                                       |
| 规格联动（机型 → 电缆托架尺寸）                                     | `:托架长度` / `:托架右弦长` / `:托架左弦长` 直挂 `:电缆托架`（v15.8）                                                            |
| 构件归属查询（法兰/附件等属于哪个塔筒）                                         | `:有法兰` / `:固定在塔筒`（v13.0 合并后统一）+ `owl:inverseOf`（v15.6 删除 `:有材料` / `:有安全锚点`） |
| 平台定位查询（某平台相对哪个塔筒顶端定位）                                        | `:平台到筒顶` / `:筒顶定位平台`（对象属性）+ `owl:inverseOf`                                 |
| 双向查询（某塔筒属于哪个塔架中段）                                            | `owl:inverseOf`                                                             |
| 身份识别                                                         | `owl:hasKey`（**3 组**，v15.0 新增 `:电缆托架规格`；v15.6 删除 `:附件类型` / `:材料`；v15.8 删除 `:电缆托架规格` / `:附件连接方式` / `:灯类型`）           |


### 11.2 推理机不能做什么（必须外置到 BPMN / 脚本）

| 事项                | 原因                                      |
| ----------------- | --------------------------------------- |
| 扶持位置 直读布局表 (12,n) | 来自输入表，非逻辑推理                            |
| 筒节划分、附件排布、灯位排布    | 属设计生成，非逻辑推理                             |
| 相邻附件实际中心距校验       | 需跨个体比较，DL 无法表达（单值区间已入公理，实际间距须外置校验） |
| 单位换算 / 单位校验       | Openllet 不处理单位；v13.0 仍未引入单位个体（可选增强）     |
| 爬梯支撑与电缆托架平齐（等高）校验 | 跨属性相等，须外置校验                        |
| 平台所在处内径（锥段插值）     | 数值计算                                    |
| 单位换算              | Openllet 不处理单位                          |
| 封闭世界下的"缺值"完备检测    | OWA 假设，仅能用基数限制近似                        |

> **结论：Openllet 负责"分类 + 校验"，计算负责"设计生成"。** 计算完成后把结果值写回本体，再由推理机校验一致性。
