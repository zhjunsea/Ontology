# 塔架中段（TMSD）程序流程详解

> **目的**：按 BPMN 流程逐步还原「一个塔架中段是如何被设计出来的」——从输入两张表到输出下一阶段 3D 模型参数表的完整程序链路。
> **口径**：只依据仓库真实代码与 `ontology/bpmn/TowerMidDesign.bpmn`，不臆测；方法名/行号可回溯源码。
> **关联**：业务语义与设计裁决见《塔架中段-正向设计流程.md》；本体与约束见 `ontology/TowerMidSection.owl`。

---

## 0. 执行底座：BPMN ↔ JobWorker ↔ 设计引擎

- **可执行真值**：`ontology/bpmn/TowerMidDesign.bpmn`（Camunda 8 / Zeebe，流程 id `Process_TowerMid`，`isExecutable="true"`）。
  顺序设计 + 一条 **S8a→S6 回退环**（排他网关 `Gateway_Loop`，默认流回 S6）：
  ```
  StartEvent_Start → Task_Step0 → Task_Step1 → Task_Step9 → Task_Step8
                   → Task_Step7 → Task_Step6 → Task_Step4 → Task_Step5
                   → Task_Judge → Gateway_Loop ──judgeDone──→ Task_Output → End_Design
                                              └───未完成───→ Task_Step5（回退重排筒节）
  ```
  `Task_Judge`（S8a）逐段判定：合格则冻结、不合格则候选前进、候选用尽则标记未定；待全部段冻结/未定后 `judgeDone=true` 进入 `Task_Output`（S8b）。
  **回退发生在 S8a→S6**（而非 S6 内部）：某段不合格时回到 S6 以**下一个候选**重排该段，直到该段首个合格档位或被判未定。
- 三条泳道：`Lane_Input`（Start/Step0/Step1）、`Lane_Design`（Step9/8/7/6/4/5 + Judge）、`Lane_Output`（Output/End）。
- 注意最后两步的顺序：**`Task_Step4`（S7 平台设计）先于 `Task_Step5`（S6 筒节设计）**——筒节附件/灯的排布以平台标高 `platformHeight` 为基准，故先定平台再排筒节附件。
- **绑定机制**：每个 `serviceTask` 用 `zeebe:taskDefinition type` 声明 jobType；`TMSDOntologyJobWorker`
  （`@Component @Profile("TMSDBPMN")`，`autoComplete=false` 手动完成）按**同名 jobType** 订阅并回调执行。
  BPMN 与 Worker **没有代码级调用关系**，绑定仅靠 `type` 字面量一致。
- **状态传递**：重结果（各段 `SectionDesign`）**不进流程变量**，按 `processInstanceKey` 缓存在
  `sessions`（`ConcurrentHashMap<Long, DesignSession>`）；步骤间只传轻量标量/摘要。
  `DesignSession{ TowerDesignRequest request; Map<Integer, SectionDesign> sections; }`（`TMSDOntologyJobWorker.java:99`）——
  S1 建立各段对象并填几何，S2~S7 各步**回写本环节字段**，S8 汇总参数并校验。

| BPMN 节点 id | 环节 | `zeebe:taskDefinition type` | Worker 处理方法 |
|---|---|---|---|
| `Task_Step0` | S0 输入解析 | `tmsd-step0-parse-input` | `handleStep0ParseInput` |
| `Task_Step1` | S1 外形/分段几何（建立段对象 + 几何） | `tmsd-step1-tube-shape` | `handleStep1TubeShape` |
| `Task_Step9` | S2 升降机/扶持 | `tmsd-step9-elevator` | `handleStep9Elevator` |
| `Task_Step8` | S3 配件类型替换 | `tmsd-step8-accessory` | `handleStep8Accessory` |
| `Task_Step7` | S4 直径设计 | `tmsd-step7-diameter` | `handleStep7Diameter` |
| `Task_Step6` | S5 高度设计 | `tmsd-step6-height` | `handleStep6Height` |
| `Task_Step4` | S7 平台设计 | `tmsd-step4-platform` | `handleStep4Platform` |
| `Task_Step5` | S6 筒节设计 | `tmsd-step5-tubesection` | `handleStep5TubeSection` |
| `Task_Judge` | S8a 判定轮（逐段合格冻结 / 回退 / 未定） | `tmsd-step8a-judge` | `handleJudgeRound` |
| `Task_Output` | S8b 汇总参数 + 输出 | `tmsd-output-parameters` | `handleOutputParameters` |

> **关键认知（逐步设计）**：`SectionDesign` 已由不可变 record 改为**可变累积对象**
> （`TowerDesignEngine.SectionDesign`，`TowerDesignEngine.java:110`）：字段私有、按 S1~S7 分组，对外只暴露只读访问器与 `parameters()`。
> S1 只 `newSectionDesign` 建立对象并 `step1TubeShape` 填几何；S2~S7 各步由 `runStep`
> （`TMSDOntologyJobWorker.java:446`）调用对应的 `stepN*` 引擎方法**只求本环节字段并回写**；
> S8b 输出步才 `assembleParameters` 汇总参数；**逐项约束判定**分散在 S8a 判定轮（`handleJudgeRound`）与 S8b（`evaluate`），满足度/推荐方案在 S8b 汇总。
> 即"设计"真实分散在 S1~S7，与 BPMN 各环节「各设计一个内容」的意图一致；“跑完整条流程，最后再验证”。

**启动初始化**（`TMSDOntologyJobWorker.init()` → `afterBackendServiceReady()`，`:152`）：
`new TmsdOntologyService(backendService)` + `TmsdVocabulary.init(Paths.get(mainOntologyPath))`
（**零硬编码**：启动时解析本体一次并缓存，供引擎/校验/输出统一取值）。

## 1. S0 输入解析 —— 建立设计会话

**入口**：`handleStep0ParseInput`（`TMSDOntologyJobWorker.java:176`）→ `resolveRequest(vars)`（`:492`）。

**两条入口路径**：

- `caseIndex ≥ 0`：读历史几何/布局，机型按 `SAMPLE_MODELS[caseIndex % 4]` 轮换
  （`SAMPLE_MODELS = {V12, V15, V17, V19}`，`:483`）。
- 否则必须给 `geometryPath`（缺即抛 `IllegalArgumentException`），布局缺省用 `tmsd.historical-layout-path`。

**读表**：`TowerExcelReader.readGeometry(path)` → `TowerGeometry`；`readLayout(path)` → `LayoutSpec`。

**固定项**（`:478` / `:480`）：

| 项 | 值 |
|---|---|
| 升降机 | `ElevatorType.ROPE_GUIDED`（钢绳导向 ⇒ 必有扶持） |
| 区域 | `中国`（⇒ 线夹隔开 `T_or_F=1`） |
| 连接方式 | `AccessoryConnectionType.WELDED`（焊接） |

机型缺省顺序：流程变量 `model` → `layout.model()` → `geometry.description().productCode()`。

**组装**：`new TowerDesignRequest(caseName, geometry, model, elevatorType, region, connectionType, layoutReference)`
（`TowerDesignRequest.java:14`）。
**缓存**：`sessions.put(key, new DesignSession(req))`。
**输出变量**：`caseName / model / elevatorType / region / connectionType / middleSectionNumbers`。

**中段段号定义**（`TowerDesignRequest.middleSectionNumbers():29`）：
段数 = 法兰数−1（`geometry.sectionCount()`）；下段=第1段、顶段=最后一段，
**其余即中段 ⇒ 第 2 段 .. 第（段数−1）段**（不写死具体段号）。

## 2. S1 外形与分段几何 —— 建立段设计对象

**入口**：`handleStep1TubeShape`（`TMSDOntologyJobWorker.java:211`）。

```java
TowerDesignRequest req = session.request;
for (int s : req.middleSectionNumbers()) {
    TowerDesignEngine.SectionDesign sd = TowerDesignEngine.newSectionDesign(s); // 新建可变累积对象（:386）
    TowerDesignEngine.step1TubeShape(sd, geo, s - 1, lay);                      // 只求几何（:402）
    session.sections.put(s, sd);                                                // 缓存，供 S2~S7 回写
}
```

> S1 **不做任何约束判定**；设计计算分散到 S2~S7，判定 / 满足度 / 推荐统一在 **S8**（见 §5、§7）。

**输出变量**：`caseName / middleSectionNumbers / sectionCount`。

**便捷入口（离线复用）**：`TowerDesignEngine.designSection(geometry, sectionNo, request, layout, variant)`
（`TowerDesignEngine.java:369`）顺序调用
`step1TubeShape → step2Elevator → step3Accessory → step4Diameter → step5Height → step7Platform → step6TubeSection → assembleParameters`，
一次算全等价于生产路径 S1~S8 的计算（不含判定），供纯 Java 离线测试 / 无 BPMN 路径复用。

**逐项约束判定器**：`constraintJudge(key)`（`TMSDOntologyJobWorker.java:255`）返回 `ConstraintJudge`，内部调
`ontologyService.assessAll("TMSD_" + key + "_S" + sd.sectionNo(), req, sd)`——把一段设计的净距两两复核个体
与 14 项「数值约束校验」个体一并物化进本体，回读 `:约束违规` / `:无附件段` / 各「合规类」结论（**判定全迁 Openllet，Java 只算值**）；
**返回 null 时退回** `TmsdDesignPipeline.javaVerdicts(req, sd)`（保证生产/离线输出一致）。
在**生产路径**中该判定器被 **S8a 判定轮**（`handleJudgeRound`）与 **S8b 输出**（`handleOutputParameters` 调 `evaluate`）使用。

**流水线（仅离线/便捷）**：`TmsdDesignPipeline.design(req, judge)`（`TmsdDesignPipeline.java:152`）
对**唯一变型** `PREFER_MAX`（间距取大·数量最少）逐中段段求解：先 `designSection` 逐步算全各段，
再 `evaluate`（`:170`）逐段校验、`assemble`（`:189`）汇总。

```java
for (DesignVariant v : TowerDesignEngine.variants()) {                 // 只有 1 个变型（:80）
    Map<Integer, SectionDesign> sections = new LinkedHashMap<>();
    for (int s : req.middleSectionNumbers()) {
        sections.put(s, TowerDesignEngine.designSection(req.geometry(), s, req, req.layoutReference(), v));
    }
    results.add(evaluate(req, v, sections, judge));                    // 逐条本体约束判定
}
return assemble(req, results);
```

### 2.1 单段逐步设计 —— 引擎 `stepN*` 方法（每步只求本环节字段）

以第 `sectionNo` 段（`n = sectionNo - 1`，0 基）为例。各步由 Worker 的 `runStep` 逐段 invoke 对应方法，
**只写本环节字段**（方法见 `TowerDesignEngine.java`）：

**S1 `step1TubeShape`（`:402`）**
- `sc = geometry.sectionCourses(n)`；`sectionTotalHeight = sc.totalHeight()`（段总高 = Σ筒节高，含上下法兰）；
- `lower = geometry.flanges().get(n)`、`upper = geometry.flanges().get(n+1)` → 上下法兰外径/内径/厚度/颈厚；
- `alpha = degrees(atan((daBottom − daTop) / 2 / secH))`（`daBottom/daTop` 取自非法兰筒节）。

**S2 `step2Elevator`（`:427`）** —— 钢绳导向 ⇒ 必有扶持
- `supportHeight = lay.supportHeight()`（布局表 (13,n) 直读）；
- `supportToWeldDistance = minDistance(supportHeight, welds)`。

**S3 `step3Accessory`（`:435`）** —— 焊接 ⇒ 焊接式附件总成
- `accessoryType`（`WELDED ⇒ "焊接式附件总成"`，否则 `"粘贴式附件总成"`）；`connectionType`。

**S4 `step4Diameter`（`:444`）** —— 机型映射
- `TmsdVocabulary.modelParams(model)` → `bracketLength / bracketRightChord / bracketLeftChord`
  （`L_CABLE / L1_CABLE_I / L2_CABLE_I`）。

**S5 `step5Height`（`:454`）** —— 梯/线槽与塔筒等高
- `ladderLength = trayLength = sectionTotalHeight`；`ladderSupportLength / ladderSupportWidth` 取布局表；
  `rungSpacing / firstRungToBottom` 取本体。

**S7 `step7Platform`（`:467`）**（**先于 S6**）
- `platformDistance = lay.platformDistance()`（布局表 (2,n)）；`platformHeight = round1(secH − platformDistance)`；
  `platformInnerDiameter = geometry.innerDiameterAt(n, platformHeight)`（锥段线性插值内径）。

**S6 `step6TubeSection`（`:478`）** —— 依赖 S7 已定的 `platformHeight`
- 附件排布：`edgeOffset = rungWidth/2`；`acc = accessoryLayout(platformHeight, welds, edgeOffset)`（见 §3）；
- 电缆线夹：`cableClampIncrements(acc.increments())` → `cableClampHeights`（见 §4.1）；
- 照明：`lightType`（焊接灯，本体）；`lightSpacing = chi("lightToLightMaxSpacing")`；
  `lightHeights(...)` → `lightHeights / firstLightHeight`；
  `minLightStudToWeldDistance` = **两个螺柱（灯位 ± lightStudSpacing/2）各自到焊缝距离的最小值**（见 §4.2）；
- 防雷螺柱：`lightningStudAngles = valueSet("lightningStudInstallAngle")`（70/190/310）。

> 焊缝序列 `welds = geometry.weldPositions(n)`：**直读主体表 B 列标高、剔除法兰行**，换算为距段底 mm（S2/S6 共用）。

### 2.2 参数表汇总 —— `assembleParameters`（`:530`）

S8 输出步对每段调用，组装 `需修改的模型参数及值`（Creo 关系式参数表，供输出器渲染）：

- 几何：`SEC_H_total / DA_TOP / DI_TOP / TFL_TOP / S_TOP / DA_BOTTOM / DI_BOTTOM / TFL_BOTTOM / S_BOTTOM`；
- 平台/梯：`H_platform / L_LADDER / L_LADDER_I / W_LADDER_I / Alpha_deg / L_C`；
- 扶持/梯档：`H_SUPPORT / RUNG_SPACING / FIRST_RUNG_TO_BOTTOM`；
- 增量：`putIncrements(params,"H","L", accessoryIncrements)`、`putIncrements(params,"H","CABLE", cableClampIncrements)`；
- 电缆托架：`L_CABLE / L1_CABLE_I / L2_CABLE_I`；
- 内径插值：`di_cable_top = innerDiameterAt(n, secH − lastBracketToTopFlange=1000)`、
  `di_cable_down = innerDiameterAt(n, firstAccessoryToBottom)`；
- 灯：`H_LIGHT{i} / LIGHT_TYPE`；
- 螺柱角度：`B_B_A / B_T_A`（**直读布局表 (11/12,n)，不按本体推导**）、
  `LIGHTNING_STUD_ANGLES / LIGHTNING_STUD_FLANGE_DISTANCE`；
- 类型：`ACCESSORY_TYPE / ACCESSORY_CONNECTION_TYPE`。
- 结果写入 `sd.parameters()`（不可变快照）；`accessoryCount()` = `accessoryHeights.size()`。

## 3. 附件排布贪心算法（S6 核心）—— `accessoryLayout`（`:607`）

**约束（全部取自本体，零硬编码）**：

- 首组：`firstAccessoryToBottom = 980`（hasValue）；
- 相邻间距 = `m × rungSpacing(280)`，`m ∈ accessorySpacingMultiple` **降序** `{7,6,5}` ⇒ `1960 / 1680 / 1400`；
- 末组落带：`[platformHeight − chi(secondLastToPlatform), platformHeight − clo(secondLastToPlatform)]`；
- 附件**上/下边缘**避焊缝：`|h − w| − edgeOffset > accessoryToWeldDistance(100)`，`edgeOffset = rungWidth/2 = 85/2 = 42.5`。

```java
final double first = cnum("firstAccessoryToBottom");       // 980
final double step  = cnum("rungSpacing");                  // 280
final int[] candidates = valueSetDesc("accessorySpacingMultiple");  // [7,6,5]
final double bandLo = platformHeight - chi("secondLastToPlatform");
final double bandHi = platformHeight - clo("secondLastToPlatform");

if (!edgeSafe(first, welds, edgeOffset)) return 空布局;    // 无解 ⇒ n=0
ks = [0];
if (!greedyWalk(0, first, step, candidates, bandLo, bandHi, welds, edgeOffset, ks, failed))
    return 空布局;                                        // 无解 ⇒ n=0
heights     = first + k * 280;
increments[0] = first;                                    // H1_L 语义：首元素=首组绝对高度
increments[i] = heights[i] - heights[i-1];                // 其后=距上一组增量
spacing       = 平均增量；
lastToPlatform= platformHeight - lastH；
minWeldDistance = minEdgeWeldDistance(heights, welds, edgeOffset);
```

- **`greedyWalk`（`:645`）**：从下标 `k`（高度 `first+k*step`）出发，落带 `[bandLo,bandHi]` 即成功返回 true；
  否则**优先最大档位**尝试 `k+m`：`h2 > bandHi` 跳过、`!edgeSafe` 跳过；递归失败则回退换小档；
  `failed` 集合记忆化，避免指数级回退。
- **`edgeSafe`（`:675`）**：对全部焊缝，`|h − w| − edgeOffset ≤ 100` 即不通过。
- **无解语义**：返回空布局 ⇒ 该段附件数量 `n=0`（对应本体 `:无附件段`），附件相关约束在 §6 中"不适用但不否决"。

## 4. 电缆线夹与灯布置（S6）

### 4.1 电缆线夹（区域=中国 ⇒ 隔开）

`cableClampIncrements(ladderSupportIncrements)`（`:702`）：

- 首组 = `H1_L`；
- 其后**每 2 个爬梯支撑增量合并为 1 组**：`cs.add(in[i] + in[i+1]); i += 2`；
- 输出 `H{i}_CABLE`（**增量**语义）+ `H{i}_CABLE_Exist`（H1..H20，缺失补 `no`）。
- 末组电缆托架在平台**上方**、距平台 `lastBracketToPlatform = 200`。

### 4.2 照明

`lightHeights(platformHeight, welds, spacing, lightType)`（`:736`）：

- 首灯落 `firstLightHeight ∈ [2600, 3000]`；
- **焊接灯**须两螺柱（灯位 ±`lightStudSpacing/2 = 250`）各自距焊缝 `> lightStudToWeldDistance(100)`
  （`studSafe`，`:795`）；
- 其后按 `spacing`（首选 `10000`，∈`[lightToLightMinSpacing(5000), lightToLightMaxSpacing(10000)]`）向上排，
  且 `≤ platformHeight`；焊接灯每 10mm 步长回退找首个安全位；无解即停止。

## 5. S2~S7 逐步设计（各步只算本环节字段并回写）

**通用**：`runStep(job, client, jobType, stepLabel, SectionStep, SectionMapper)`（`TMSDOntologyJobWorker.java:446`）：
先对每个中段段执行 `SectionStep`（invoke 对应 `TowerDesignEngine.stepN*`，**回写会话中的段设计对象**），
再用 `SectionMapper` 产出本步输出，写流程变量 `step / variantName / sections`。**S2~S7 不做约束判定**。

| 步 | jobType | 本步设计/回写字段 | 输出字段 |
|---|---|---|---|
| S2 | `tmsd-step9-elevator` | `supportHeight / supportToWeldDistance` | `elevatorType / elevatorClass / hasSupport / supportHeight / supportToWeldDistance` |
| S3 | `tmsd-step8-accessory` | `accessoryType / connectionType` | 同左 |
| S4 | `tmsd-step7-diameter` | `bracketLength / bracketRightChord / bracketLeftChord` | 同左 |
| S5 | `tmsd-step6-height` | `ladderLength / trayLength / ladderSupportLength / ladderSupportWidth / rungSpacing / firstRungToBottom` | `ladderLength / trayLength` |
| S7 | `tmsd-step4-platform`（**先于 S6**） | `platformDistance / platformHeight / platformInnerDiameter` | 同左 |
| S6 | `tmsd-step5-tubesection` | `accessoryHeights / accessorySpacing / firstAccessoryToBottom / secondLastToPlatform / accessoryToWeldDistance / cableClampHeights / lastBracketToPlatform / lightHeights / lightType / firstLightHeight / lightStudSpacing / minLightStudToWeldDistance / lightningStudAngles` | 除 `lightningStudAngles` 外的上述字段（含派生的 `accessoryCount`） |

> S6 在 S7 之后：其附件排布 / 灯位以 `platformHeight` 为基准，故必须先有平台设计结果。
> 全部字段在 **S8** 由 `assembleParameters` 汇总进 `parameters()`。

## 6. 约束校验 —— `TmsdDesignPipeline.check`（`:210`）

逐段逐条比对本体 Restriction（数值/文案均取自 `TmsdVocabulary`）：

- `hasValue v` → 实际值必须等于 v；
- `>= a 且 <= b` → 实际值必须落在闭区间；
- `> a` → 实际值必须严格大于 a。

**相邻间距类**（附件中心间距、灯间距）：取全部相邻间距的**最小值与最大值同时判定**。

**判定全迁本体（v16.8 起，v16.9/v16.10 沿用）**：**16 项判定**（2 项净距 + 14 项数值约束）的通过与否**全部回读本体结论**
（`:约束违规` / `:无附件段` / 各 `*合规类`），由 `TmsdOntologyService.assessAll` 承担；`actual` 列仅展示 Java 参考值供报告可读。

- `assessAll` 一次物化：① (附件, 环焊缝) 与 (焊接灯螺柱, 环焊缝) 净距「两两复核」个体
  （`:WeldClearanceCheck`，断言 `:净距`）+ 本段 `:附件数量`；② **14 项 `:数值约束校验` 个体**
  （断言 `:校验属性名` + `:校验值`）；**临时注入 → flush（Openllet 分类）→ 回读结论 → 立即清除**。
- 判定口径：附件安全 ⇔ 无任何「校验附件」复核个体被推为 `:约束违规`；
  螺柱安全 ⇔ 无任何「校验螺柱」复核个体被推为 `:约束违规`；
  无附件 ⇔ 本段中段个体被推为 `:无附件段`；
  第 k 项数值约束通过 ⇔ 其校验个体被归入对应 `*合规类`（名单见《塔架中段设计本体.md》§9.7）。
- 不适用项（无附件段 / 单灯 / 非焊接灯 / 无扶持）与 Java 兜底 `javaVerdicts` 口径一致（显式跳过）。
- 任一步异常返回 `null`，调用方退回 `javaVerdicts`。

**无附件段（n=0）**：附件相关约束（避焊缝、中心间距、首附件、倒数第二到平台、末电缆托架到平台）
标"不适用"但 **不否决**该方案。

## 7. S8 汇总参数 + 判定 + 输出 —— `handleOutputParameters`（`TMSDOntologyJobWorker.java:368`）

**本步职责（“跑完整条流程，最后再验证”）**：

1. 对每段 `assembleParameters` 汇总 `parameters()`（见 §2.2）；
2. `TmsdDesignPipeline.evaluate(req, variant, session.sections, clearanceJudge(key))`（`:170`）逐段校验本体约束、得出满足/否决；
3. `TmsdDesignPipeline.assemble(req, List.of(vr))`（`:189`）组装 `CaseResult`（推荐 = 附件最少且间距最大）；
4. 写出文件 + 本体一致性复核。

**写出**：`TmsdOutputWriter.write(result, Paths.get(outputDir))`（`TmsdOutputWriter.java:212`）：

- 对**全部满足方案**、按老工具目录结构写**两套**：
  `项目法兰尺寸_骨架关系式/` 与 `极限法兰尺寸_骨架关系式/`；
- 各套含 `第1段 … 第N-1段 / 顶段 / 连接法兰` 子目录；
- 每段：`第K段筒体信息关系式.txt`、`第K段附件信息关系式.txt`、法兰关系式（**GBK + CRLF**）；
- 另写 `<用例>-方案对比报告.md`（UTF-8）。
- **极限法兰模式**：中间法兰厚度取本体 `limitFlangeThickness(215)`、
  内径取 `DA − S*2 − limitFlangeInnerReduction(600)`，并按厚度增量扣减该段首/末筒节高度；底/顶法兰不变。
- **注释格式铁律**：写出前 `assertCommentPolicy` 校验——注释一律「行首 `/*` 起始、单行、不补 `*/` 闭合」。
- **行模板/文本块取自本体（v16.10 去硬编码）**：变量名、尾注释、空格标点、整块原样文本不再硬编码于 Java，改为运行时从本体「输出规范」层取值——`TmsdOutputWriter` 用 `fill(key, value, k, i)` 取 `:输出行模板`（注入 `{{value}}`、替换 `{k}`/`{i}`）、用 `outBlock(key)` 取 `:输出块文本`（整体回填）；键未在 `TmsdVocabulary` 定义即抛错，**不回退硬编码**。值仍由 Java 计算。

**本体一致性复核**：对**推荐方案逐段** `ontologyService.validate("TMSD_" + key + "_S" + 段号, session.request, sd)`（`:75`），
临时注入 ABox → `backendService.validateAxioms` → 立即清除。

**输出变量**：`caseName / satisfiedCount / rejectedCount / recommendedVariant / outputFiles / outputDir /
ontologyConsistent / ontologyReports`。

## 8. 一句话数据流

```
两张输入表(xlsx)
  └─ S0 ─► TowerDesignRequest（机型/升降机/区域/连接 + 几何 + 布局）  ── 缓存 session
        └─ S1 ─► 建立各段 SectionDesign + 填几何（step1TubeShape）
              └─ S2..S7 ─► 逐步设计并回写本环节字段
                           （升降机→配件类型→直径→高度→【平台 S7】→【筒节 S6】）
                             └─ S8 ─► assembleParameters 汇总参数
                                       └─► evaluate：逐条本体约束判定（净距走本体等价类回读，其余 Java 直判）
                                             └─► assemble：CaseResult（推荐 = 附件最少且间距最大）
                                                   └─► 两套 GBK 关系式 txt + 方案对比报告 + 本体一致性复核
```
