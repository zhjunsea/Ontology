`Shaoyangbing ⊑ Banbiaobanli`、`⊑ Yang`（tcm-core.owl:181-187）。`Banbiaobanli`/`Yang`/`Yin` 均为 ⊑ Bagang 的原语类，无 `≡`。

## 3. 触发条件与状态机

```
                    ┌─ realize 命中 ──────────→ ① 确定结论（EndEvent_Success）
患者四诊 → 八纲 → 六经 ─┤
                    └─ realize 零命中 ────────→ ② 双路径输出（EndEvent_NoResult）
                                                  ├ 路A：追问（补什么症状）
                                                  └ 路B：或然症候选列表
```

**触发双路径的唯一条件**：`realizedMatches.isEmpty()`（无任何方证被完全推出）。

不再区分「六经能定/不能定」作为**输出形态**的判据——两者都走双路径，区别只体现在**路A 的问题内容**（六经未定时，问题里会包含判据缺口）。

> 这修正了 2026-09-20 的三态划分：原「能定+仅候选」与「不定+信息不足」合并为同一形态，因为对患者而言两者要做的事相同（补症状，或看候选）。

## 4. 或然症接入（两处）

### 4.1 池筛选（扩大召回）

现状：`collectRestrictionFillers` 只从 `equivalentClass` 的 4 个属性取填充符，`possibleSymptom` 不在其中 → 或然症连候选池都进不去。

改为：

```
候选池 = { F | fillers(F.equivalentClass) ∩ S ≠ ∅ }        // 原有：主证命中
       ∪ { F | possibleSymptom(F) ∩ S ≠ ∅ }                // 新增：或然症命中（D2）
```

### 4.2 排序：字典序分层，零加权（2026-09-21 修订）

**为什么放弃加权**：`score = 1.0·main + 0.3·poss` 里的 `0.3` 是自由参数，无医理依据，违反项目既定原则「生产路径无主观拍脑袋规则」（审计报告 §8.2）。更根本的是——**只要把两个度量合成一个分数，就必然需要权重**。所以修法不是换度量，而是**取消合成**。

**现有排序器本来就是字典序**（`rankCandidatesWithScores`，step 0→6，全程无权重）：父子层级 → 广谱惩罚 → jaccard 降序 → hits 降序 → required 降序 → clinicalPriority 升序 → 六经对称差 → 字典序兜底。或然症应以**同样的方式**接入，而不是引入加权求和。

**关键修正（2026-09-21 二次修订）**：原方案 ③ 的条件 `hits_main = 0` 在池内是**空集**——`filterFangzheng` Step 4 硬过滤 `hitCounts >= 1`（`TCMOntologyJobWorker.java:1112-1116`），池内每个方证**按构造**都有 `hits_main ≥ 1`。故或然症几乎无法参与。改为**以「主证缺口」为第一排序键、或然症为第二键**。

**主证缺口 gap（整数，零自由参数）**：

```
gap(叶子 症状 s)   = 0 若 s ∈ S，否则 1
gap(叶子 类 C)     = 0 若 C ∈ 患者推理类型，否则 1
gap(AND(φ1..φn))   = Σ gap(φi)          // 合取项须全部满足
gap(OR(φ1..φn))    = min_i gap(φi)      // 析取项任一满足即可
```

语义：**「还差几个症状才能命中该方证」**——纯计数，无模糊聚合、无自由参数。`gap = 0` ⟺ realize 命中。

**排序键（替换现有 step 2 的 jaccard）**：

| # | 键 | 来源 |
|---|---|---|
| 1 | `gap(F)` 升序 | 新增（主证缺口） |
| 2 | 六经对称差 升序 | 既有（F4 修复） |
| 3 | `possHits(F)` 降序 | 新增（或然症命中数，纯计数） |
| 4 | `\|poss(F)\|` 升序 | 新增（或然症声明少者更特异） |
| 5 | `clinicalPriority` 升序 | 既有 |
| 6 | 字典序兜底 | 既有 |

**门控是隐式的**：`gap = 0` 自然排在最顶（确定结论）；或然症只在 **gap 相同**时起作用。gap 是粗粒度整数、平局频繁 → 或然症作为第二键**经常能生效**，正好解决「很难参与进去」。

**显式门控版本（若需保留「高置信时不问或然症」）**：`gap ≤ 1`（只差一个合取项）视为高置信，或然症不参与。这是**结构量**，非全局常数。

**比例版备选（sat）**：若需区分「gap=1 但定义有 2 项」与「gap=1 但定义有 5 项」，可用比例满足度 `sat`（AND→平均，OR→最大，叶子→0/1）。`sat ≥ 1 − 1/required(F)` 即「只差一个合取项」——对 required=5 恰为 0.8，与「80% 置信度」直觉吻合。但 `sat` 的 AND/OR 聚合规则本身是一个建模选择，不如 `gap` 纯粹。

**度量对比：`gap` / `hits` / `jaccard`（医理依据）**

| 维度 | `gap`（缺口） | `hits`（命中数） | `jaccard`（当前在用） |
|---|---|---|---|
| 医理对应 | 「方证相应还差什么」 | 「命中了几个主证」 | 「集合相似度」 |
| 范式 | 逻辑判定（充要条件） | 计数 | 信息检索相似度 |
| AND/OR 语义 | ✓ 完整（Σ / min） | ✗ 忽略 | ✗ 忽略 |
| 受患者症状总数影响 | 不受 | 不受 | **受（致命）** |
| 定义复杂度偏差 | 无 | 无 | **有（`required` 大者吃亏）** |
| 可解释性 | 高（还差几个） | 中 | 低 |

**`jaccard` 的两处医理硬伤**：

1. **分母含 `patientSize`** → 患者多报一个**无关**症状，所有方证的 jaccard 齐降，排序会**漂移甚至翻转**。例：方证A(`required=2, hits=1`) 与 方证C(`required=9, hits=3`)：`P=1` 时 A 胜（0.500 vs 0.429），`P=2` 时 C 胜（0.333 vs 0.375）——**同一患者，只多说一个症状，结论就变了**。医理上，患者描述的多寡不应改变方证的匹配关系。
2. **`required` 大者吃亏** → 定义越精确（鉴别力越强）的方证，分母越大、jaccard 越低。与医理相反。

**`hits` 的不足**：忽略定义规模与 OR 语义。`required=1` 命中 1 与 `required=5` 命中 1 同为 `hits=1`，但医理上前者「完全满足」、后者「仅满足 1/5」。

**`gap` 为何最合医理**：方证的定义是**充要条件**（合取须全满足、析取任一即可），辨证的本质是**逻辑判定 + 缺口**，不是相似度打分。`gap` 直接回答「还差什么」，且不含任何与患者表述多寡相关的项。

**代码现状**：`ScoredFangzheng.ratio() = hits/required` 已定义但**从未被调用**（死代码）；实际使用的是 `jaccard()`（3 处：`TCMOntologyJobWorker.java:690/698/706`）。

**`gap` 的粗粒度**：`required=2` 缺 1 与 `required=5` 缺 1 同为 `gap=1`。可用 `sat` 作 tie-break（gap 相同再比 sat），或接受粗粒度——平局多反而让或然症更易参与。

**已否决的方案**：

| 方案 | 否决理由 |
|---|---|
| IDF 加权 `log(N/(1+df))` | 度量本身虽由语料统计得出，但**仍需与 mainScore 合成**，权重问题原样存在；且引入新公式，不如字典序简洁 |
| `possibleSymptom` 改对象属性 + 支持类 `FangzhengHuoranzhengSupported ≡ Fangzheng ⊓ ∃you_huoranzheng.{…}` | ① 需把注解改成对象属性；② 引入 `∃prop.{individual}` 名义量模式——正是 `chufang` 把分类从 15s 拖到 385s 的陷阱（铁律 53 已裁定禁用）；③ 患者症状是类不是个体，语义不匹配 |

### 4.3 证据标记

每个候选必须携带 `evidence` 字段，供前端与解释层区分：

| 值 | 含义 | 可否进「确定结论」 |
|---|---|---|
| `MAIN` | 有主证命中 | 可以（若 realize 命中） |
| `POSS_ONLY` | 仅或然症命中（主证零命中） | **永远不可以** |

> 依铁律 16：「仅候选」不得冒充结论。`POSS_ONLY` 是比「仅候选」更弱的一档。

## 6. 追问生成算法

### 6.1 第一层：判据缺口（定八纲/六经）

```
for P in 37 个判据:
    sat(P) = |患者 ∩ leaves(P)|          // 注意 OR 分支：任一满足即算该分支满足
    gap(P) = required(P) - sat(P)
    若 0 < gap(P) ≤ GAP_MAX(=2):
        产出 { ask: "是否有 <缺口叶子>？", unlocks: P 的 ⊑ 目标, basis: P.comment }
```

按 `gap` 升序排列——**缺口越小越先问**（最省力的补充）。

### 6.2 第二层：方证主证缺口（定方证）

```
for F in 候选方证 Top-K(=5):
    gapLeaves = leaves(F.equivalentClass) \ 患者
    对 OR 分支取「最小缺口分支」（而非平铺全部叶子）
    若 gap(F) ≤ GAP_MAX:
        产出 { ask: "是否有 <gapLeaves>？", thenFangzheng: F, basis: F.differentialAxis }
```

### 6.3 合并去重

同一症状可能同时出现在两层（例：`口苦` 既在 `Panju_C1` 里，也在小柴胡汤证的 OR 分支里）。合并为一条，标注「补 X 可定 Y 经，进而命中 Z 方证」。

### 6.4 排序

问题清单按 `(能否同时解锁六经与方证, gap)` 排序——**能一举命中方证的问题排最前**。

## 7. 本例推演（S = {口渴 Kouke, 心烦 Xinfan, 咳嗽 Kesou}）

### 7.1 第一层：判据缺口

| 判据 | required | sat | gap | 补什么 | 能定 |
|---|---|---|---|---|---|
| **`Panju_B7`** | 2 | 1 | **1** | 洪脉 / 大脉 / 黄苔 **任一** | 里 + 阳（阳明） |
| `Panju_D5` | 4 | 1 | 3 | — | 超阈值 |
| `Panju_D6` | 4 | 1 | 3 | — | 超阈值 |
| `Panju_C2` | 5 | 1 | 4 | — | 超阈值 |

→ 最优：**补一个脉象（洪脉/大脉）或舌象（黄苔）即可定「里阳」（阳明）**，依据 26 / 168 / 186 / 180 条。

### 7.2 第二层：方证主证缺口

以或然症候选为准。小柴胡汤证 `≡ Shaoyangbing ⊓ OR(往来寒热, 胸胁苦满, 默默, 不欲食, 心烦∩喜呕, 口苦∩(咽干∪目眩))`：

- 患者有「心烦」，但 `心烦∩喜呕` 分支缺「喜呕」；
- `口苦∩(咽干∪目眩)` 分支缺「口苦 + 咽干（或目眩）」；
- 且合取项 `Shaoyangbing` 需先定少阳病。

**关键发现**：补「口苦 + 咽干 + 目眩」三个症状**同时**满足：
1. `Panju_C1`（口苦⊓咽干⊓目眩）→ 半表半里 + 热 → `Re ⊑ Yang` → **少阳病成立**；
2. 小柴胡汤证的 OR 分支 `口苦∩(咽干∪目眩)` → **满足**。

→ **小柴胡汤证 realize 命中**。依据 263 条少阳提纲。

### 7.3 合并后的输出

**路A（追问，按推荐度排序）**

| # | 问题 | 效果 | 依据 |
|---|---|---|---|
| 1 | 是否有 **口苦、咽干、目眩**？ | 定少阳病 → **小柴胡汤证命中** | 263 条 |
| 2 | 是否有 **洪脉 / 大脉 / 黄苔** 之一？ | 定「里阳」（阳明） | 26/168/186 条 |
| 3 | 是否有 **喜呕**？ | 小柴胡汤证 OR 分支满足（仍需少阳病） | 96 条 |

**路B（或然症候选）**

⚠️ **当前数据下路B 效果受限**：小柴胡汤证的 `possibleSymptom` **只挂了 `#Xianmai`（弦脉）1 条**，96 条的 7 个或然症（含渴、咳）**全未挂**——尽管 7 条加减规则在 `rules.owl:298-333` 全部建了。

→ 患者报「渴、咳」时，小柴胡汤证**不会**因或然症进池。这正是 §9 的数据缺口。

## 9. 前置依赖与数据缺口
