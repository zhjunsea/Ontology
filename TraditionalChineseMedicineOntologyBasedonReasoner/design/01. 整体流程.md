# 经方派诊疗本体推理流程（Openllet 推理机 + 本体）

> 作者：张仲景 & 胡希恕（模拟）  
> 原则：先辨六经，继辨八纲，再辨方证，乃至药证  
> 推理机：Openllet（基于 OWL 2 DL，支持 SWRL 规则）

---

## 一、总体思路

利用 Openllet 推理机，将《伤寒论》的“病脉证并治”体系与胡希恕“六经—八纲—方证”辨证层次，构建为可计算的本体。  
通过 Openllet 的 **一致性检查、实例分类、SWRL 规则推理** 等功能，实现从四诊信息到方剂药物的自动推导，模拟经方诊疗过程。

核心流程：

```
四诊录入 → 本体一致性检查 → 八纲分类 → 六经分类 → 方证分类 → 方剂药物推荐 → 结果解释
```

## 二、本体顶层设计

### 1. 顶层类（Class）

| 顶层类 | 子类/实例示例 | 说明 |
|--------|-------------|------|
| 四诊信息 | 症状（发热、恶风、汗出、口渴、便秘……）<br>脉象（浮、沉、缓、紧、洪大……）<br>舌象（苔黄燥、苔白滑……）<br>体质（壮实、虚弱、阳虚……）<br>腹证（腹满硬痛、心下按之满痛……） | 客观依据 |
| 六经病 | 太阳病、阳明病、少阳病、太阴病、少阴病、厥阴病 | 病位病性纲领 |
| 八纲 | 表、里、阴、阳、寒、热、虚、实 | 六经之纲目 |
| 方证 | 桂枝汤证、麻黄汤证、白虎汤证、大承气汤证…… | 辨证尖端 |
| 方剂 | 桂枝汤、麻黄汤、白虎汤、大承气汤…… | 治疗实体 |
| 药物 | 桂枝、芍药、甘草、生姜、大枣…… | 组成方剂 |
| 药证 | 桂枝证、芍药证、麻黄证、石膏证…… | 药物使用指征 |

### 2. 核心对象属性（Object Property）

| 属性 | 定义域 | 值域 | 说明 |
|------|--------|------|------|
| `has_symptom` | 患者 | 症状 | 患者表现出某症状 |
| `has_pulse` | 患者 | 脉象 | 患者脉象 |
| `has_tongue` | 患者 | 舌象 | 患者舌象 |
| `has_abdominal_sign` | 患者 | 腹证 | 患者腹证 |
| `has_prescription` | 方证 | 方剂 | 方证对应方剂 |
| `has_ingredient` | 方剂 | 药物 | 方剂组成药物 |
| `has_indication` | 药物 | 药证 | 药物的适应证（药证） |

### 3. 数据属性（Data Property）

可补充年龄、性别、病程等，用于加减规则。

## 三、八纲与六经公理化定义（OWL 公理）

Openllet 支持 OWL 2 表达，以下使用 Manchester Syntax 书写公理。

### 1. 八纲定义

```manchester
Class: 表证
  EquivalentTo: 
    (has_symptom some 恶寒 or has_symptom some 恶风) 
    and (has_pulse some 浮)

Class: 里证
  EquivalentTo: 
    has_symptom some (腹满 or 便秘 or 下利 or 呕吐 or 口渴)
    and (not 表证)

Class: 热证
  EquivalentTo: 
    has_symptom some 发热
    and (has_symptom some 口渴 or has_symptom some 烦躁 or has_pulse some 数)

Class: 寒证
  EquivalentTo: 
    has_symptom some 恶寒
    and (has_pulse some 迟 or has_symptom some 下利清谷 or has_symptom some 手足厥冷)

Class: 表虚证
  EquivalentTo: 表证 and has_symptom some 汗出

Class: 表实证
  EquivalentTo: 表证 and has_symptom some 无汗

Class: 里虚证
  EquivalentTo: 里证 and has_symptom some 下利 and has_symptom some 食不下

Class: 里实证
  EquivalentTo: 里证 and (has_symptom some 便秘 or has_symptom some 腹满硬痛)

Class: 阳证
  EquivalentTo: 表证 or 热证 or 实证

Class: 阴证
  EquivalentTo: 里证 or 寒证 or 虚证
```

### 2. 六经病定义

```manchester
Class: 太阳病
  EquivalentTo: 
    表证 and 阳证 
    and (has_symptom some 发热) 
    and (has_symptom some 恶寒 or has_symptom some 恶风) 
    and (has_pulse some 浮)

Class: 阳明病
  EquivalentTo: 
    里证 and 阳证 and 热证 
    and (has_symptom some 但热不寒) 
    and (has_symptom some 口渴) 
    and (has_pulse some 大 or has_pulse some 实 or has_pulse some 洪)

Class: 少阳病
  EquivalentTo: 
    半表半里证 and 阳证 
    and (has_symptom some 往来寒热) 
    and (has_symptom some 胸胁苦满)

Class: 太阴病
  EquivalentTo: 
    里证 and 阴证 and 寒证 and 虚证 
    and (has_symptom some 腹满) 
    and (has_symptom some 呕吐) 
    and (has_symptom some 食不下) 
    and (has_symptom some 下利)

Class: 少阴病
  EquivalentTo: 
    表证 and 阴证 and 寒证 and 虚证 
    and (has_pulse some 微细) 
    and (has_symptom some 但欲寐)

Class: 厥阴病
  EquivalentTo: 
    半表半里证 and 阴证 
    and (has_symptom some 消渴) 
    and (has_symptom some 气上撞心) 
    and (has_symptom some 心中疼热) 
    and (has_symptom some 饥而不欲食)
```

## 四、典型方证定义（以太阳病和阳明病为例）

### 1. 太阳病方证

#### 桂枝汤证（太阳中风，表虚）

```manchester
Class: 桂枝汤证
  EquivalentTo: 
    太阳病 
    and 表虚证 
    and (has_symptom some 汗出) 
    and (has_symptom some 恶风) 
    and (has_pulse some 浮缓)
```

#### 麻黄汤证（太阳伤寒，表实）

```manchester
Class: 麻黄汤证
  EquivalentTo: 
    太阳病 
    and 表实证 
    and (has_symptom some 无汗) 
    and (has_symptom some 恶寒) 
    and (has_symptom some 身痛) 
    and (has_pulse some 浮紧)
```

### 2. 阳明病方证

#### 白虎汤证（阳明经证，里热炽盛）

```manchester
Class: 白虎汤证
  EquivalentTo: 
    阳明病 
    and (has_symptom some 大热) 
    and (has_symptom some 大渴) 
    and (has_symptom some 大汗) 
    and (has_pulse some 洪大) 
    and not (has_symptom some 便秘)
```

#### 大承气汤证（阳明腑证，里实燥结）

```manchester
Class: 大承气汤证
  EquivalentTo: 
    阳明病 
    and 里实证 
    and (has_symptom some 潮热) 
    and (has_symptom some 便秘) 
    and (has_symptom some 腹满硬痛) 
    and (has_symptom some 谵语) 
    and (has_pulse some 沉实) 
    and (has_tongue some 黄燥起刺)
```

## 七、SWRL 规则扩展（用于复杂加减与合病）

Openllet 支持 SWRL 规则，可表达“若……则……”的临床加减逻辑。

例如：

```swrl
患者(?p) ^ has_symptom(?p, 项背强几几) ^ 类型(?p, 桂枝汤证) 
  -> 类型(?p, 桂枝加葛根汤证)
```

或表达合病：

```swrl
患者(?p) ^ 类型(?p, 太阳病) ^ 类型(?p, 阳明病) 
  -> 类型(?p, 太阳阳明合病)
```

SWRL 规则弥补了 OWL 表达能力的不足，使推理更贴近临床动态变化。

## 八、诊疗流程详细步骤

### 第 1 步：患者四诊信息录入

将患者的主诉、症状、脉象、舌象、腹证等，以 OWL 个体断言形式录入本体。

示例（患者张三）：

```manchester
Individual: 张三
  Types: 
    has_symptom 发热,
    has_symptom 恶风,
    has_symptom 汗出,
    has_pulse 浮缓
```

如果采用 Protégé 等工具，可通过表单录入；也可通过自然语言处理自动提取。

### 第 2 步：本体一致性检查（Openllet Consistency Checking）

运行 Openllet 推理机，检查患者个体是否与本体公理冲突。

例如患者同时被断言“汗出”和“无汗”，而本体中定义“汗出”与“无汗”为互斥（Disjoint），推理机会报告本体不一致，提示四诊信息矛盾，需临床核实。

**这一步骤体现了“观其脉证”的严谨性，防止错误辨证。**

### 第 3 步：八纲自动分类（Instance Classification）

Openllet 根据公理自动将患者个体归入八纲类。

对张三：

- 表证：因有恶风、脉浮 → 成立
- 热证：因有发热 → 成立
- 表虚证：因表证 + 汗出 → 成立
- 阳证：因表证/热证 → 成立

推理机可输出：

```
张三 rdf:type 表证
张三 rdf:type 热证
张三 rdf:type 表虚证
张三 rdf:type 阳证
```

### 第 4 步：六经病分类

基于八纲结果和六经公理，Openllet 进一步归类：

```
张三 rdf:type 太阳病
```

因为张三满足太阳病定义（表证、阳证、发热、恶风、脉浮）。

### 第 5 步：方证辨别（尖端）

Openllet 继续将患者归入具体方证类：

```
张三 rdf:type 桂枝汤证
```

同时排除麻黄汤证（因无“无汗”，且表虚与表实互斥）。

### 第 6 步：方剂与药物推荐

通过方证到方剂的映射关系：

```manchester
Class: 桂枝汤证
  SubClassOf: has_prescription value 桂枝汤
```

Openllet 推理出：

```
张三 has_prescription 桂枝汤
```

再结合方剂组成，推荐药物：

```
桂枝汤 has_ingredient 桂枝, 芍药, 甘草, 生姜, 大枣
```

### 第 7 步：SWRL 规则触发（若有加减）

如果患者同时有“项背强几几”，SWRL 规则激活，将其归为桂枝加葛根汤证，推荐加葛根。

### 第 8 步：结果输出与解释

最终输出结构化结果：

```
病：太阳病
证：桂枝汤证（太阳中风表虚）
方：桂枝汤
药：桂枝、芍药、甘草、生姜、大枣
条文依据：《伤寒论》第12条
```

Openllet 还可通过推理追踪功能，解释每一步分类的依据，便于教学与临床审查。

## 九、复诊与动态调整

复诊时更新患者的四诊信息断言，重新运行 Openllet 推理。

例如患者服药后出现“大汗出、大烦渴、脉洪大”，则推理机自动重新分类：

```
八纲：里、热、实
六经：阳明病
方证：白虎汤证
方剂：白虎汤
```

实现“知犯何逆，随证治之”的动态辨证。

## 十、Openllet 相较于 HermiT 的优势与注意事项

| 特性 | Openllet | 说明 |
|------|----------|------|
| 推理速度 | 较快，适合大规模本体 | 适合临床实时推理 |
| SWRL 规则支持 | 支持 | 可表达复杂加减规则 |
| OWL 2 DL 支持 | 完整 | 表达力强 |
| 一致性检查 | 支持 | 防止四诊矛盾 |
| 解释功能 | 有 | 提供推理依据 |

**注意事项：**

1. 中医症状的模糊性：需配合模糊逻辑或概率扩展，否则边界过于刚硬。
2. 脉象主观性：需建立标准脉象本体，标注可靠性。
3. 动态传变：静态本体难以表达时间序列，可引入时态本体或多次推理。
4. SWRL 规则可能引入非单调性，需谨慎设计，避免冲突。

## 十一、总结

利用 Openllet 推理机结合经方本体，可以实现：

- **客观化**：四诊信息到方证的推导逻辑透明。
- **可解释**：推理步骤可回溯，符合“辨证论治”要求。
- **动态化**：复诊更新信息，推理机自动调整诊断。
- **教学化**：帮助学习者理解六经八纲方证的逻辑关系。

**此系统不取代医生，而是辅助辨证，使“观其脉证，知犯何逆，随证治之”在数字世界中得以严谨呈现。**
